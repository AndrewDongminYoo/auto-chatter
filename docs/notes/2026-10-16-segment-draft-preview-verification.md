# 필터 초안 대상 미리보기 검증

## 범위

[#26](https://github.com/AndrewDongminYoo/auto-chatter/issues/26)의 [저장 전 초안 미리보기](../specs/2026-10-16-segment-draft-preview.md)를 로컬에서 확인했습니다.
실제 `public/app/` HTML·CSS·스크립트를 `127.0.0.1`에서 제공하고, 분리된 `agent-browser` 세션에서 합성 연락처와 API 응답을 사용했습니다.
적용된 목록에는 한 명, 다른 초안에는 두 명, 큰 표본에는 55명을 넣어 서로 다른 상태와 페이지 경계를 만들었습니다.
새 서버 API·DB 계약·의존성은 없습니다.

## 실패를 먼저 확인한 항목

- 구현 전 `Expected current-draft preview button before saving a filter`로 버튼 부재를 확인했습니다.
- 합성 데이터 객체를 제거하면 `Missing preview fixture; no UI evidence is valid`로 검사 자체가 실패했습니다.
- 요청 중 native disabled 버튼이 키보드 포커스를 잃는 것을 확인했습니다.
  `aria-disabled`와 중복 클릭 검사를 적용한 뒤 포커스 유지와 중복 요청 차단을 확인했습니다.
- 512자 식별자가 390px 화면을 넘겨 문서 폭이 2,991px이 되는 것을 확인했습니다.
  기존 문단 줄바꿈 스타일을 재사용한 뒤 문서 폭이 390px으로 유지됐습니다.
- 연락처 기록 삭제 후 늦은 응답이 식별자를 다시 표시하는 실패를 확인했습니다.
  기존 삭제 후 화면 정리 경로에서 미리보기를 무효화한 뒤 결과가 다시 나타나지 않았습니다.

## 브라우저 결과

다음 14개 검사 그룹이 통과했습니다.

1. 마지막 적용 목록과 다른 초안을 조회하며 카드 DOM·편집값·목록 조건·커서·변경 표시를 보존합니다.
2. 조건 변경 시 이전 결과를 지우며 0명 응답을 표시합니다.
3. 첫 페이지 50명·예시 5명과 추가 결과를 구분하고 전체 수로 표시하지 않습니다.
4. 선택한 저장 필터에서도 현재 계정·숫자 0·OR 초안을 사용하며 `segment_id`·`after`를 보내지 않습니다.
5. 불리언 `false`를 보존합니다.
6. 잘못된 숫자 초안은 요청 없이 오류를 표시합니다.
7. 실패 시 이전 결과를 제거하고 다시 시도할 수 있습니다.
8. 요청 중 중복 클릭을 차단하며 이전 성공 응답이 새 결과를 덮지 않습니다.
9. 이전 실패와 종료 처리가 진행 중인 새 요청을 덮지 않습니다.
10. 참여자·계정에 HTML 형태의 문자열이 있어도 텍스트로 표시합니다.
11. 연결 목록과 필드 정의 갱신 시 미리보기를 지웁니다.
12. 미리보기에서 기록한 요청 13개는 모두 기존 `GET /api/contacts`였습니다.
13. 연락처 기록 삭제 후 늦은 응답을 표시하지 않습니다.
14. 세션 초기화 후 늦은 응답을 표시하지 않습니다.

별도로 기존 필터 저장이 현재 초안을 보내고, 기존 필터 적용이 목록을 갱신하는 것을 확인했습니다.
키보드 실행과 포커스 유지, 데스크톱 1,280px·모바일 390px 표시도 확인했습니다.

## 자동 검사와 증거의 한계

최소 검증 명령은 `node --check public/app/app.js`, `corepack pnpm check-types`, `corepack pnpm test`와 변경 파일의 `trunk check --no-fix`입니다.
구문·타입·단위 검사는 코드 및 기존 정적 보안 규칙을 검사하며 실제 화면 동작은 위 브라우저 결과로 구분합니다.
합성 API의 필터 응답은 화면 상태와 요청 직렬화를 검사할 뿐 서버 질의의 정확성·운영 작업 공간 격리·실계정 동작을 증명하지 않습니다.
서버 구현은 변경하지 않았으며 DB·workerd·격리 배포 검사는 PR의 hosted CI 결과로 별도 확인합니다.
정확한 전체 수·제외 사유·동의/활동 조건·캠페인 대상 고정과 #26 전체 완료는 남아 있습니다.
운영 배포와 사용자 화면의 최종 시각 승인은 이 기록으로 대체하지 않습니다.
