# 작업 공간 시간대 설정 화면 검증

## 대상과 경계

GitHub #32 세 번째 구현의 [작업 공간 설정](../specs/2026-09-30-workspace-roles.md#작업-공간-설정) 화면을 확인했습니다.
실제 `public/app` 파일과 실제 `appApi`를 로컬 PostgreSQL 17의 일회용 DB(`automations_ui`, 확인 뒤 삭제)에 연결한 임시 로컬 서버를 사용했습니다.
Supabase는 세션 쿠키 값으로 `/user` 응답을 돌려주는 대역으로 바꿨고, 로그인은 이 대역 서버가 쿠키를 직접 설정하는 방식으로 대신했습니다. 운영 DB·Supabase·Meta는 호출하지 않았습니다.
화면 동작은 Chrome에서 확인했습니다.

## 브라우저 검사

- 소유자로 들어가면 Instagram 계정 영역 아래에 작업 공간 설정 영역이 보였고, 시간대 입력란에 기본값 `Asia/Seoul`이 표시됐습니다. 입력란의 추천 목록에는 브라우저가 아는 시간대 418개가 들어 있었습니다.
- 입력란에 `america/new_york`을 입력하고 Enter로 저장하자 "시간대 이름을 확인해 주세요" 오류 안내가 표시됐고, 값은 저장되지 않았습니다.
- `America/New_York`을 입력하고 "시간대 저장"을 누르자 저장 알림이 표시됐고, DB의 `workspaces.time_zone`도 `America/New_York`이었습니다.
- 상담원으로 들어가면 같은 영역에 `America/New_York`이 읽기 전용으로 보였고, 저장 버튼은 숨겨지고 "관리자와 소유자만 바꿀 수 있습니다" 안내가 보였습니다. 같은 화면에서 보낸 `PUT /api/workspace/settings`는 `403 role_forbidden`이었습니다.
- 390px 너비의 같은 출처 iframe에서 문서 너비는 371px로 넘치지 않았고, 시간대 입력란의 높이는 47px였습니다. 라이트 모드만 확인했고, 다크 모드는 이번에 확인하지 않았습니다.
- 확인 뒤 내보내기 안내 문구에 "작업 공간 설정"을 더했으며, 이 문구 변경은 화면에서 다시 확인하지 않았습니다.

## 남은 검증

migration 027은 2026-10-01 운영 DB에 적용하고 Worker를 배포했지만([운영 적용 기록](2026-09-26-cloudflare-runbook.md)), 시간대 설정 화면은 운영에서 조작하지 않았고 시각 대기도 운영 데이터로 실행하지 않았습니다.
