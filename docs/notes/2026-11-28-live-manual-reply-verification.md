## 진행

- `497d554`의 자동 배포가 끝난 뒤 Deploy 워크플로를 껐습니다(대기·진행 중인 실행 없음).
- 대시보드 인박스에서 테스트 계정과의 대화를 열고 "상담 시작"을 눌렀습니다. 화면이 "상담 중 · 이 사용자의 자동 답장은 중지됩니다"로 바뀌었습니다.
- 작성란에 "auto-chatter 인박스 수동 답장 실계정 확인 메시지입니다."를 입력했습니다. 전체 발송이 꺼져 있어 "지금 보내기"가 비활성이고, 차단 사유("전체 발송이 중지되어 있습니다")가 표시되었습니다.
- 08:44:49Z에 활성 커밋을 `--var SEND_ENABLED:true`로 배포했습니다(버전 `bcb6f941`). 대화를 새로고침하자 "답장 가능 · 2026. 11. 29. 오후 5:05:46까지 (서버 확인 기준)"가 표시되고 "지금 보내기"가 활성화되었습니다. 작성 중인 초안은 그대로 남아 있었습니다.
- "지금 보내기"를 누르자 버튼이 "보내기 요청 중…"으로 바뀌었고, 접수 뒤 이력에 "발송 대기"로 나타나며 작성란이 비워지고 "보내기를 요청했습니다. Meta 접수 여부는 이력에서 확인해 주세요."가 표시되었습니다.
- 수동 답장 행은 08:45:16Z에 생기고 08:45:25Z에 `sent`가 되었으며, Meta 메시지 ID가 기록되었습니다. 새로고침한 이력은 "Meta 접수"였고, 처리 기록은 예약 접수(17:45:16 KST), 발송 시작(17:45:20 KST), Meta 접수(17:45:25 KST)였습니다.
- 08:45:54Z에 기본값으로 다시 배포해 발송을 껐습니다(버전 `883f4f32`). 발송이 켜져 있던 동안 나간 것은 이 답장 1건뿐이었습니다(비공개 답장, DM 플로, 캠페인, 팔로우 응답 0건).
- "자동화 재개"를 눌러 상담 전환을 끝냈습니다. 상담 전환 행은 `active=false`, `version=2`(시작과 해제)였습니다.
- 테스트 계정의 DM함에서 이 답장을 받은 것을 확인했습니다.

- 활성 버전(`883f4f32`, 태그 `497d554`, `SEND_ENABLED=false`)을 확인한 뒤 Deploy 워크플로를 다시 켰습니다. 그사이 `main`이 움직이지 않아 추가 배포는 없었습니다.
- 다섯 단계의 화면(발송 꺼짐의 차단 사유, 답장 가능 시각, 요청 중, 발송 대기, Meta 접수와 처리 기록)을 확인했고, 화면을 승인받았습니다.

## 확인하지 않은 것

- 모바일 화면, 키보드 입력, 오래된 응답, 대화 전환, 중복 클릭은 실계정에서 데스크톱 한 번의 흐름으로만 봤습니다. 이 항목들은 [로컬 화면 검증](2026-09-28-inbox-manual-reply-ui-verification.md)이 다룹니다.
- 거부와 unknown 결과의 표시, 검토와 해결 기록, 예약 발송은 실계정에서 만들지 않았습니다. DB·workerd 테스트와 로컬 화면 검증이 다룹니다.
