# 자동화 작업 화면 디자인

## 진단과 계약

사용자 피드백: 기존 화면이 템플릿으로 찍어낸 화면처럼 보인다.
기존 화면의 큰 홍보 제목, 넓은 여백, 반복되는 둥근 카드가 계정 연결과 규칙 편집보다 강조되고 있었다.
이번 작업은 제품 UI 재구성이며 마케팅 페이지 제작이 아니다.
`design-taste-frontend`의 진단·반복 패턴 제거 원칙과 `frontend-design`의 제품 UI 계약을 적용한다.

- 목적: Instagram 계정 운영자가 댓글 조건과 답장을 함께 보며 규칙을 편집한다.
- 구조: 데스크톱의 왼쪽 탐색, 간결한 계정 행, 규칙 목록·편집·대화 미리보기의 작업 영역.
- 반응형: 중간 폭에서는 미리보기가 편집 아래로 이동하고 모바일에서는 한 열과 가로 탐색을 사용한다.
- 밀도: 기존보다 여백을 줄이고 카드 대신 영역 간 구분선을 사용한다.
  `DESIGN_VARIANCE=5`, `MOTION_INTENSITY=2`, `VISUAL_DENSITY=6`을 제품 작업에 맞는 기준으로 삼는다.
- 글꼴: 설치된 한국어 UI 글꼴과 sans-serif 대체 글꼴을 사용한다.
  새 웹폰트 요청이나 의존성을 추가하지 않는다.
  본문·레이블·보조 설명의 크기와 굵기로 위계를 만든다.
- 색상: 기존 남색 아이콘과 브랜드 색을 유지하고, 아이콘의 녹색 계열은 대화 흐름에 제한적으로 사용한다.
  배경·표면·텍스트는 의미별 CSS 변수로 정의하고 시스템의 밝은·어두운 모드를 따른다.
- 자산: 기존 앱 아이콘을 유지한다.
  새 사진이나 장식 아이콘은 추가하지 않는다.
- 미리보기: 입력값을 `textContent`로 표시하고 예시임을 명시한다.
  팔로우 여부는 실제 조회 결과로 오해하지 않도록 조건별 경로로 구분한다.
- 상호작용: 기존 입력명·API·저장·오류·이탈 경고를 유지한다.
  과도한 모션 없이 포커스와 선택 상태를 표현한다.
- 경계: 인증·발송·개인정보 정책, 경로, 외부 배포는 변경하지 않는다.

## 성공 기준

1. 데스크톱·모바일의 작업 구조 개선 → 실제 브라우저 스크린샷 비교, 가로 넘침 검사.
2. 대화 미리보기 → 문구·키워드·팔로우 입력 변경과 규칙 선택·초기화 반영 확인.
3. 기존 조작 유지 → 저장 요청, 입력 검증, 저장 실패 시 입력 유지 확인.
4. 접근성·테마 → 두 색상 모드의 자동 접근성 검사, 키보드 포커스, 축소 모션 확인.
5. 배포 가능한 정적 자산 → JavaScript 구문 검사와 Trunk 검사, Cloudflare 번들 dry-run.

## 검증 기록

이번 기록은 `c4ce4a1`의 UI를 재구성한 변경에 대한 검증이다.

### 실제 확인 결과

- 기존 16px 둥근 카드와 반복 번호·소개 제목을 제거하고, 영역 구분선과 규칙 선택 상태로 작업 구조를 표현했다.
- 대화 미리보기는 실제 폼 값에 연결했다.
  키워드·첫 DM·확인 단어·팔로우 조건별 문구가 입력, 규칙 선택, 새 규칙 초기화, 로그아웃에 맞춰 갱신됐다.
- 미리보기 검사는 기대 문구가 없는 상태에서 먼저 실패시킨 뒤 입력 이벤트 후 통과시켰다.
  `<img>` 형태의 입력도 요소를 만들지 않고 텍스트로 남았다.
- 합성 API에 저장 503 오류를 주어도 입력과 미리보기가 유지됐고 재시도는 저장됐다.
- 모든 댓글 모드와 팔로우 해제 시 미리보기의 조건과 노출 영역이 갱신됐다.
- 1440px 데스크톱의 밝은·어두운 모드와 390px 모바일의 실제 스크린샷을 열어 확인했다.
  320px·390px 설정 화면과 390px 로그인 화면은 가로 넘침 검사를 통과했다.
- 로그인·설정 화면의 밝은·어두운 모드 axe 검사에서 위반은 0건이었다.
  각 화면의 색상 대비 검사 1건은 장식용 화살표 때문에 자동 판정을 완료하지 못했다.
  해당 화살표는 접근성 트리에서 숨겨지며 실제 렌더링과 의미 색상을 수동 확인했다.
- 별도 읽기 전용 접근성 리뷰에서 검사한 텍스트 색상 조합은 모두 4.5:1 이상이었다.
  가장 낮은 값은 밝은 모드의 보조 텍스트와 보조 표면 조합인 4.82:1이었다.
- 본문 바로가기를 키보드로 실행했을 때 실제 `main` 포커스를 확인했다.
  축소 모션을 설정한 상태에서 규칙 편집과 스크롤을 확인했다.
- 상호작용 리뷰와 접근성 리뷰 모두 수정이 필요한 회귀를 찾지 못했다.
- `node --check public/app/app.js`, `git diff --check`, `corepack pnpm build:cloudflare`가 통과했다.
  번들 검사는 배포하지 않는 dry-run이며 발송 설정은 계속 `false`다.
- 변경한 네 파일의 Trunk 검사도 통과했다.

최소 검증 명령은 다음과 같다.

```bash
node --check public/app/app.js
trunk check public/app/index.html public/app/styles.css public/app/app.js docs/notes/2026-09-26-dashboard-design-direction.md
corepack pnpm build:cloudflare
```

API·DB를 바꾸지 않아 이번에는 서버 단위·DB 테스트를 반복 실행하지 않았다.
실제 Meta 연결·발송, 운영 배포, 실기기 및 Safari·Firefox, 화면 읽기 프로그램의 음성 출력과 운영 성능은 검증하지 않았다.
브라우저 테스트는 로컬의 실제 정적 파일과 합성 API 응답을 사용했다.
마케팅 스킬의 사진·히어로·시차 효과·프레임워크 도입 규칙은 이 제품 화면의 적용 범위에서 제외했다.
