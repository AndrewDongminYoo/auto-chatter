# Instagram 수신 인박스 로컬 검증

## 구현 및 보관 경계

5회차는 선택 활성화한 계정의 새 텍스트 DM과 확인 버튼 응답을 보관·조회하는 기반입니다.
기존 승인된 수동 삭제 정책을 권장 기본값으로 유지했으며 운영 배포는 수행하지 않았습니다.
기본 꺼짐·활성화 시각·수신 활성 상태로 저장을 제한합니다.
DM 작성자 ID를 댓글 연락처와 같다고 추정하지 않습니다.
수동 답장·발신 이력·팀·첨부·삭제 및 수정 이벤트는 아직 구현하지 않았습니다.

## 실패 관찰과 수리

- 첫 DB 테스트는 연결 목록에 `inbox_enabled`가 없어서 실패했습니다.
- 페이지 테스트는 숫자 ID를 문자열 별칭으로 정렬하는 오류를 잡았습니다.
  실제 identity 컬럼으로 정렬하도록 바꾼 뒤 최신 50개와 이전 5개를 빠짐없이 조회했습니다.
- 브라우저 fixture에 대화가 없으면 `Expected fixture-populated inbox conversation`으로 검사가 실패합니다.
  인박스 응답을 제공한 fixture에서 실제 대화가 표시되는 것을 확인했습니다.
- 독립 화면 리뷰가 삭제 완료 안내에 DM 본문이 빠진 점을 확인했고 요청·완료 범위를 함께 수정했습니다.
- 독립 데이터 리뷰는 최종 소스에서 차단 사항을 찾지 못했습니다.
  새 identity 시퀀스를 기존 서버 grant와 API·PUBLIC revoke 목록에 포함했습니다.
  수정 전에도 제한 서버 역할의 실제 identity INSERT는 workerd에서 성공했으므로 시퀀스 목록 누락으로 INSERT가 실패한다고 주장하지 않습니다.
- 호스팅 코드 리뷰는 수신 재개·OAuth 재연결에서 보관 시작 시각을 갱신하지 않는 문제를 확인했습니다.
  두 전환의 회귀 테스트가 수정 전 실패했고, 선택 보관한 계정이 비활성에서 활성으로 전환할 때 시작 시각을 갱신한 후 통과했습니다.
  중지 기간의 지연 메시지는 저장하지 않고 기존 이력·재개 후 새 메시지는 유지하며, 이미 활성인 계정의 발송 설정 변경은 시작 시각을 바꾸지 않습니다.

## 검사 범위와 결과

- strict 타입 검사와 단위 테스트 101개가 통과했습니다.
- PostgreSQL 17의 로컬 `automations_test`에서 DB 테스트 115개가 통과했습니다.
  보관 스위치·소유권·중복·역순·마이그레이션 재실행·대화 및 메시지 페이지와 기존 확인 흐름을 읽습니다.
- 실제 workerd·Hyperdrive 검증 25개가 통과했습니다.
  새 사례는 서명된 텍스트 DM을 두 번 전달하고 제한 서버 역할로 한 행만 저장되는 것을 검사합니다.
- 실제 브라우저에서 본문을 HTML 대신 텍스트로 표시하며 확인 버튼 응답 종류가 표시되는 것을 확인했습니다.
- 합성 API로 보관 켜기 취소·실패 상태 유지·대화 더 보기·이전 메시지 추가와 로그아웃 뒤 늦은 응답 차단을 확인했습니다.
- 1440px 데스크톱과 390px 모바일에서 메시지를 표시했고 가로 넘침은 없었습니다.

이 증거는 실제 Meta 계정의 DM 보관이나 운영 DB 마이그레이션을 증명하지 않습니다.
개인 계정 auto-chatter의 DM retention/inbox Oracle 조회는 `[no precedent found]`이며 Wiki freshness는 미확인입니다.
