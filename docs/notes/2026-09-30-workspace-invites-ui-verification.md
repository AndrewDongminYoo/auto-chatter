# 작업 공간 초대·멤버 화면 검증

## 대상과 경계

GitHub #21의 [역할·초대 계약](../specs/2026-09-30-workspace-roles.md) 가운데 초대, 멤버 제거, 역할 변경 화면을 확인했습니다.
실제 `public/app` 파일과 실제 `appApi`를 로컬 PostgreSQL 17의 일회용 DB에 연결한 로컬 서버를 사용했습니다.
Supabase는 세션 쿠키 값으로 `/user` 응답을 돌려주는 대역으로 바꿨으며, 운영 DB·Supabase·Meta는 호출하지 않았습니다.
화면 동작은 Chrome에서 확인했습니다.

## 자동 검사

`corepack pnpm check-types`, `corepack pnpm test`(146건), `corepack pnpm test:db`(242건), `corepack pnpm test:cloudflare`(43건)가 통과했습니다.
초대의 이메일 일치 검사를 끄거나 멤버십 조회에서 제거된 멤버를 걸러 내지 않으면 해당 DB 테스트가 실패하는 것을 확인했습니다.

## 브라우저 검사

- 소유자로 들어가면 멤버 영역에 소유자와 "나" 표시가 보였고, 대문자가 섞인 이메일로 만든 초대는 소문자로 정규화된 이메일, 상담원 역할, 만료일과 함께 대기 목록에 표시됐습니다.
- 새 초대 링크는 `/app/#invite=` 형식으로 한 번만 표시됐습니다.
- 초대받은 계정으로 링크를 열자 수락 알림이 표시되고 주소에서 토큰이 지워졌으며, 상담원에게는 멤버 영역이 보이지 않았습니다.
- 같은 링크를 다시 열면 "이미 사용한 초대 링크입니다" 안내가 표시됐습니다.
- 다른 계정으로 초대 링크를 열면 이메일 불일치 안내가 표시되고 탭에 보관한 토큰이 지워졌습니다.
- 소유자가 역할을 관리자로 바꾸자 변경 알림이 표시됐고, 멤버를 제거하자 멤버 수가 줄고 제거 알림이 표시됐습니다. 제거된 계정은 새 초대 링크로 다시 합류했습니다.
- 첫 확인에서 두 가지를 고쳤습니다. 역할 선택 상자가 전체 너비로 늘어나 멤버 행 안으로 줄였고, 멤버 영역 아래에 계정 영역과 같은 구분선을 넣었습니다.
- 제거 버튼의 이름이 "데이터 내보내기"와 겹치는 "내보내기"여서 "멤버 제거"로 바꿨고, 역할 이름 뒤 조사가 어색한 알림("상담원로")을 고쳤습니다.
- 로그아웃 상태로 초대 링크를 연 뒤 다른 이메일의 계정으로 로그인 양식을 제출했습니다. 수정 전에는 이메일 불일치 안내가 "로그인했습니다."로 덮였고, 수정 후에는 불일치 안내가 오류로 남고 보관한 토큰이 지워졌습니다. 로컬 서버가 여러 `Set-Cookie`를 한 헤더로 합치던 문제와 인증 요청 제한 바인딩이 없던 문제를 먼저 고친 뒤 확인했습니다.
- 390px 너비의 같은 출처 iframe에서 문서 너비는 375px로 넘치지 않았고, 멤버 영역의 버튼·선택 상자는 높이 44px 이상이었습니다. 다크 모드 화면을 시각 검토했으며, 라이트 모드는 이번에 확인하지 않았습니다.

## 남은 검증

운영 DB에 migration 024를 적용하고 실제 가입·인증 메일을 거쳐 초대를 수락하는 흐름은 별도 승인 대상입니다.
상담원에게 관리 버튼을 숨기는 화면 정리는 이번 범위가 아닙니다.
