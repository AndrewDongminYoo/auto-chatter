운영자가 아래 문구의 실제 발송 테스트를 승인했고 다른 게시물을 등록했다고 알렸습니다.
등록한 계정의 Meta media 조회에는 이전 게시물과 새 게시물 `17909444478471816`이 있었으며, 새 게시물을 대상으로 선택했습니다.
Meta 프로필·게시물 소유자 ID를 대조해 `ai.you.wanted` 소유임을 확인했습니다.
첫 DM, 미팔로우 안내 DM과 팔로우 후 완료 DM의 실제 수신을 운영자 화면과 DB 상태로 대조했습니다.
테스트를 마치고 규칙·계정·전역 발송을 다시 중지했습니다.

## 활성화 전 확인

이전 테스트 계정은 저장된 토큰을 사용하는 실제 `InstagramFollowTransport.followStatus()` GET 조회에서 `false`로 확인됐습니다.
이는 조회 시점의 미팔로우 상태이며 이후 각 확인 답장에서는 워커가 다시 조회합니다.
조회는 실제 발송 POST를 수행하지 않았습니다.

운영 DB의 연결 1개·발송 활성 계정 0개·활성 규칙 0개·미완료 outbox 0개·미완료 팔로우 대화 0개를 확인했습니다.
이미 완료된 첫 DM 행과 비활성화한 이전 규칙은 보존했습니다.
명시적인 사용자·계정 소유권과 유효한 토큰을 확인한 트랜잭션에서 새 규칙을 만들고 계정 발송을 활성화했습니다.
기존 댓글이나 완료된 발송을 다시 대기 상태로 바꾸지 않았습니다.

## 테스트 활성화 배포

Worker 버전은 `18141dc0-a1c6-49be-a50c-5b4bfe18fde6`, 배포 태그는 `6d71ef7`입니다.
실행 코드 변경 없이 앞선 검증을 통과한 코드로 배포했고 기존 secrets를 유지했습니다.
Worker 버전 조회에서 `SEND_ENABLED`의 실제 값 `true`를 확인했습니다.
저장소의 기본값은 `false`입니다.
아래 명령은 당시 실행 기록이며 재활성화 절차가 아닙니다.
`--tag`는 Worker 버전 라벨이며 Git 커밋을 선택하지 않습니다.
Wrangler는 현재 checkout의 소스를 배포하므로 재활성화 전에는 별도 발송 승인, `git status --porcelain`의 빈 결과, `git rev-parse HEAD`와 검증한 커밋의 일치 및 해당 소스의 검증 결과를 확인해야 합니다.

```log
corepack pnpm exec wrangler deploy --env-file /dev/null --var SEND_ENABLED:true --tag 6d71ef7 --message 'Approved follow-gate DM test on media 17909444478471816'
```

## 실계정 검증 순서

1. 이전 테스트 계정으로 새 게시물에 정확한 댓글 키워드를 남깁니다.
2. 첫 DM의 실제 수신과 outbox `sent`·공급자 메시지 ID, 팔로우 대화 `waiting`을 대조합니다.
3. 미팔로우 상태에서 `확인`으로 답장합니다.
4. 미팔로우 안내 DM 수신, `follow_status=not_following`, 대화의 `waiting` 복귀와 확인 receipt를 대조합니다.
5. 운영자가 계정을 팔로우하고 다시 `확인`으로 답장합니다.
6. 팔로워 DM의 실제 수신, `follow_status=following`, 대화 `sent`와 공급자 메시지 ID를 대조합니다.
7. 규칙·계정·전역 발송을 다시 중지하고 실제 스위치와 미완료 상태를 확인합니다.

미팔로우 안내 확인 전에는 테스트 계정의 미팔로우 상태를 유지합니다.
팔로우 상태 확인 불가는 미팔로우와 구분하며 불명확한 발송 `unknown`을 자동 재시도하지 않습니다.
규칙은 특정 댓글 작성자 허용 목록을 제공하지 않으므로 해당 게시물의 정확한 테스트 키워드에 일치하는 댓글이 대상입니다.
중복 이벤트·재응답의 DB 상태는 확인하되 추가 실발송 승인을 추정해 같은 안내를 반복 전송하지 않습니다.

## 미팔로우 분기 검증 결과

운영자 화면에서 테스트 댓글 `auto-chatter 팔로우 테스트`, 첫 DM, `확인` 답장과 승인한 미팔로우 안내 DM을 확인했습니다.
DB의 댓글 ID는 `18176820826435361`, 게시물 ID는 `17909444478471816`, outbox ID는 `2`입니다.
첫 DM은 `sent`이며 공급자 메시지 ID가 기록됐고 오류 코드는 없습니다.
팔로우 대화는 `waiting / not_following`으로 돌아왔으며 안내 DM의 공급자 메시지 ID가 기록됐고 오류 코드는 없습니다.
확인 답장의 수신·확정 시각은 `2026-09-26T10:51:57.457Z`이며 확인 receipt는 1건입니다.
검증 시점의 발송 활성 계정과 활성 규칙은 각각 1개입니다.

## 팔로워 분기와 중지 결과

운영자 화면에서 계정의 팔로잉 상태, 두 번째 `확인` 답장과 승인한 팔로워 완료 DM을 확인했습니다.
DB의 같은 outbox `2`에 연결된 팔로우 대화는 `sent / following`이며 공급자 메시지 ID가 기록됐고 오류 코드는 없습니다.
두 번째 확인 답장의 수신·확정 시각은 `2026-09-26T10:57:24.063Z`이며 확인 receipt는 총 2건입니다.
완료된 첫 DM·팔로우 대화와 receipt는 보존했습니다.

소유권을 다시 확인한 관리자 트랜잭션에서 테스트 규칙의 `enabled=false`, 계정의 `send_enabled=false`를 적용하고 수신 `active=true`는 유지했습니다.
재조회에서 발송 활성 계정·활성 규칙·미완료 outbox·미완료 팔로우 대화는 모두 0개였습니다.
미완료 outbox는 `pending / sending / unknown`, 미완료 팔로우 대화는 `waiting / pending / sending / unknown` 상태를 조회했습니다.
전역 발송 중지 배포 버전은 `dfa763f7-742d-497a-8e58-6eeb737837bd`, 코드 태그는 `6d71ef7`입니다.
별도 CLI override 없이 저장소 기본 설정으로 배포했으며 실제 버전 조회에서 `SEND_ENABLED=false`를 확인했습니다.

이번 검증은 한 운영 계정과 한 테스트 사용자에서 미팔로우 → 팔로우 전환을 확인한 결과입니다.
여러 실제 사용자 간 격리, 팔로우 조회 불가 분기, 실제 중복 웹훅·재응답 및 Advanced Access 승인을 검증한 결과는 아닙니다.

## 중지 절차

완료 또는 오류 시 규칙 `6465962b-8e47-4993-887d-351250f48b36`의 `enabled`와 연결 `a5df4215-fb1e-46d4-93f4-13c0176fb031`의 `send_enabled`를 한 트랜잭션에서 `false`로 변경합니다.
수신 연결의 `active=true`는 유지합니다.
아래 기본 배포 명령으로 전역 `false`를 복원하고 배포 버전·스위치·DB 상태를 다시 확인합니다.
중지 전에 승인된 외부 POST가 이미 시작됐다면 설정 변경으로 취소할 수는 없습니다.

```bash
corepack pnpm exec wrangler deploy --env-file /dev/null --message 'Stop approved follow-gate DM test'
```
