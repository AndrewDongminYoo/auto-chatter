# DM 시작 트리거와 캠페인 실발송 실계정 검증

## 범위와 승인

[#293](https://github.com/AndrewDongminYoo/auto-chatter/issues/293)의 DM 시작 트리거 실계정 확인과 [#36](https://github.com/AndrewDongminYoo/auto-chatter/issues/36)의 캠페인 실발송(수신자 1명)을 한 발송 창에서 확인했습니다.
캠페인 후보가 되려면 수신자가 댓글 작성자이면서 확인된 DM 수신자여야 하므로(`src/app/inbox-identity.ts`의 `verifiedDmRecipientsSql`), 비공개 답장을 실제로 보내야 했습니다. 그래서 두 검증을 묶었습니다.
2026-11-18에 운영 DB 조회, 테스트 규칙·플로·동의·캠페인 승인 쓰기, Deploy 워크플로 끄기와 `SEND_ENABLED=true` 배포 및 실제 발송, 종료 후 `false` 배포와 워크플로 다시 켜기를 승인했습니다. 기존 규칙은 끄지 않았습니다.
계획과 사전 점검은 [#293의 2026-11-18 댓글](https://github.com/AndrewDongminYoo/auto-chatter/issues/293#issuecomment-6965102694)에 있습니다.

메시지 본문, 테스트 계정의 ID와 Meta 메시지 ID는 이 노트에 적지 않습니다.

## 사전 점검

2026-11-18 00:24Z에 운영 DB를 읽기 전용 트랜잭션으로 조회했습니다.

- migration 070~072의 테이블이 모두 있었습니다.
- 세 작업 공간의 요금제가 모두 `advanced`여서 월 캠페인 발송 한도가 테스트를 막지 않았습니다.
- 연결 하나가 `active`, `send_enabled`, 받은 메시지함 저장이 모두 켜져 있었고, 토큰 만료는 2027-01-09, 구독 확인은 2026-11-17 22:28Z에 성공했습니다.
- 대기 중인 발송 행(비공개 답장, DM 플로, 캠페인, 수동 답장, 외부 전송), 재개할 플로 실행, 캠페인 승인, 켜진 플로, 명시적 마케팅 동의 기록이 모두 0건이었습니다.
- 켜진 댓글 규칙은 팔로우 조건 규칙 하나였습니다. 이 규칙은 켜 둔 채로 진행했고, 그 게시물은 2026-11-19 테스트 중에 이미 삭제된 상태였습니다. 발송 창 동안 나간 비공개 답장은 아래 두 테스트 규칙의 2건뿐이었습니다.

같은 조회를 2026-11-18 03:44Z에 다시 실행해 변화가 없음을 확인했습니다.

## 발견 사항

- 연락처 필터의 동의 조건은 댓글 작성자 기준("동의 목적")과 DM 수신자 기준("DM 동의 목적") 두 쌍입니다. 캠페인 동의는 DM 수신자에 기록되므로 DM 쪽 조건을 써야 대상에 잡힙니다. 처음에 댓글 작성자 쪽 조건을 골라 0명이 나왔습니다.
- 캠페인 초안 화면에서 "대상 고정"을 찾기 어려웠습니다. 버튼이 연락처 메뉴의 관리 도구 안에만 있습니다: [#372](https://github.com/AndrewDongminYoo/auto-chatter/issues/372).
- 댓글 규칙은 지우거나 보관할 수 없어, 게시물을 삭제한 규칙이 목록에 남습니다: [#371](https://github.com/AndrewDongminYoo/auto-chatter/issues/371).
- 명시적 마케팅 동의를 기록하는 화면이 없어, 로그인한 `/app/` 탭의 개발자 도구에서 `POST /api/connections/:id/channel-consent-events`를 호출했습니다.

## 검증하지 않은 것

- 스토리 응답과 멘션 트리거(#294)는 구현되지 않아 확인하지 않았습니다.
- 캠페인은 수신자 1명만 보냈습니다. 여러 수신자의 분할 발송, 속도·예산 한도, 취소, 부분 실패와 복구는 실계정에서 확인하지 않았습니다.
- 동의가 없는 수신자, 수신 거부, 24시간 창이 닫힌 수신자의 차단은 실계정에서 확인하지 않았습니다.
- 팔로우한 상태의 확인 응답은 이번에 확인하지 않았습니다. 2026-09-26 [팔로우 분기 실발송 테스트](2026-09-26-live-follow-test.md)에서 확인했습니다.
