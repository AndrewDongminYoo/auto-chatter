# 캠페인 초안 API 구현 검증

## 범위와 기준

[승인된 계약](../specs/2026-10-21-campaign-drafts.md)의 관리자 전용 생성·조회·수정·보관 API를 구현했습니다.
기준 HEAD는 `325abd3d8748cd14b5e935fdc5f7059029040aa8`이며 아래 로컬 검사는 커밋 전 작업 변경을 대상으로 수행합니다.
화면·발송·예약·비용·실행 승인은 포함하지 않습니다.
기존 고정 대상과 일반 텍스트를 저장하며 새 의존성은 없습니다.
운영 DB·실계정·공급자 호출은 사용하지 않았습니다.

## 실패 재현과 수정

새 API 테스트는 구현 전에 경로가 없어 404로 실패했습니다.
구현 후 생성 재시도·다른 작업 공간·상담원 거절·동시 버전 충돌·입력 검사가 통과했습니다.
이름과 UUID를 정규화한 최초 요청 해시를 따로 보존하므로 수정 후 생성 재시도는 현재 상태를 반환하며 과거 본문으로 되돌리지 않습니다.

초안만 남은 작업 공간 fixture는 외래 키 검사를 잠시 끈 테스트 세션에서 만들어 두 이동 경로를 직접 검사합니다.
관리자 배정 스크립트가 이동을 허용하는 실패를 먼저 관찰한 뒤 새 테이블을 검사하도록 수정했습니다.
초안 쓰기는 작업 공간 잠금을 얻은 뒤 관리자 멤버십을 다시 확인합니다.
초대 수락이 먼저 완료된 경합에서 이전 작업 공간으로 늦은 초안이 생성되지 않는지도 기존 동시성 테스트에 추가했습니다.

첫 전체 DB 검사에서는 748개 중 747개가 통과했고 세그먼트 마이그레이션 fixture 하나가 새 외래 키 때문에 과거 테이블을 제거하지 못했습니다.
그 fixture의 롤백되는 트랜잭션 안에서 초안 테이블도 명시적으로 제거하도록 수정했습니다.
기존 마이그레이션을 재실행하는 다른 fixture에는 최신 삭제 함수 복원을 위한 063을 포함했습니다.
운영 테이블을 강제로 제거하거나 실제 제약을 완화하지 않았습니다.

## 검사와 읽는 대상

- 단위 검사: 입력 계약, UTF-16 본문 길이와 코드 포인트 이름 길이, 정규화, 정확한 필드·버전을 검사합니다.
- DB 검사: 실제 API와 PostgreSQL에서 원래 요청 재시도, 동시 생성·수정·한도, 보관, 개인정보 삭제 후 명단 수를 검사합니다.
- 원장 불변성: 비어 있지 않은 outbox·동의·명단·태그·중지 fixture를 읽고 초안 생성·수정·보관 전후 행을 대조합니다.
- 내보내기·작업 공간 삭제: 공통 fixture에 실제 초안 행을 넣어 테이블 누락과 내부 해시 노출을 검사합니다.
- Worker 검사: 실제 번들·제한된 DB 역할로 초안 생성·재시도·수정·보관과 다른 작업 공간·상담원 거절을 검사합니다. 외부 인증만 합성 응답입니다.
- 마이그레이션: 기존 기준 스키마에 전체 runner를 적용한 결과와 새 설치의 제약·권한·삭제 함수를 대조합니다.

## 실행 명령

```bash
corepack pnpm install --frozen-lockfile
corepack pnpm check-types
corepack pnpm test
TEST_DATABASE_URL=postgres://postgres@127.0.0.1:<port>/automations_test corepack pnpm test:db
TEST_DATABASE_URL=postgres://postgres@127.0.0.1:<port>/automations_test corepack pnpm test:cloudflare
```

DB와 Worker 검사는 전용 임시 PostgreSQL에서 순차 실행합니다.
검사 로그와 리뷰 증거는 인접 작업 공간의 `../pr-loop-reviews/auto-chatter/2026-10-21-campaign-drafts/`에 보관합니다.
최종 단위 검사 369개, 전체 DB 검사 748개, 실제 Worker 검사 80개가 통과했습니다.
타입 검사와 frozen lockfile 설치도 통과했습니다.
전체 DB 검사 후 Worker 권한 검사에서 명단의 `FOR SHARE`가 UPDATE 권한을 요구해 생성이 503으로 실패하는 것을 확인했습니다.
작업 공간 삭제와 같은 작업 공간 잠금을 이미 보유하므로 불필요한 명단 행 잠금을 제거했고 제한된 역할의 Worker 검사를 다시 통과했습니다.

기준 스키마에 전체 runner를 적용한 결과는 새 설치의 초안 제약·RLS·ACL과 세 삭제 함수가 일치했습니다.
비교 대상의 기본 키를 제거한 음성 대조군은 의도한 불일치로 실패했습니다.
API·동시성 및 저장소·삭제 경계를 나눈 독립 읽기 전용 리뷰는 모두 지적 사항 없이 끝났으며, 루트 검토에서는 위 Worker 권한 실패를 수정했습니다.

기존 Instagram·Worker 초기화 fixture는 부모 테이블을 `DROP CASCADE`할 때 일부 후속 테이블을 남깁니다.
이번 변경의 초안 테이블은 초기화 목록에 포함했습니다.
기존 identity 테이블도 목록에 없어 같은 DB에서 전체 검사를 반복하면 외래 키가 사라진 행이 남을 수 있습니다.
이는 이번 변경 밖의 기존 문제로 남기며, 전체 DB 통과 결과는 새 임시 DB에서 측정했습니다.
