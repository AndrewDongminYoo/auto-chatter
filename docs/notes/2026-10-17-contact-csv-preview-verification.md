# CSV 태그 사전 검사 검증

## 범위

[#25](https://github.com/AndrewDongminYoo/auto-chatter/issues/25)의 [읽기 전용 CSV 태그 사전 검사](../specs/2026-10-17-contact-csv-preview.md)를 검증했습니다.
기존 v1 CSV의 식별 표현을 유지하며 현재 태그와 교체 예상 태그를 비교합니다.
실제 적용·신규 연락처·식별자 병합·운영 배포는 포함하지 않습니다.

## 자동 검사

새 API가 없는 상태에서 요청 테스트가 404로 실패하는 것을 먼저 확인했습니다.
명시적 UTF-8 임시 PostgreSQL의 `automations_test`에서 검사했으며 운영 DB는 사용하지 않았습니다.

| 검사                                                      | 읽은 대상과 결과                                                           |
| --------------------------------------------------------- | -------------------------------------------------------------------------- |
| `corepack pnpm check-types`                               | 실제 TypeScript 소스의 타입 검사 통과                                      |
| `corepack pnpm test`                                      | CSV 레코드·인용·유니코드·128KiB·500행 경계를 포함한 단위 테스트 304개 통과 |
| `TEST_DATABASE_URL=<local> corepack pnpm test:db`         | 실제 SQL·API·테이블 전후 비교를 포함한 DB 테스트 652개 통과                |
| `TEST_DATABASE_URL=<local> corepack pnpm test:cloudflare` | 제한된 서버 역할의 v1 왕복·상담원 거절을 포함한 workerd 테스트 78개 통과   |

변경된 17개 파일에 `corepack pnpm exec trunk check --ci`를 실행했고 문제가 없었습니다.

DB 검사는 실제 내보낸 파일의 왕복, 앞자리 0과 큰 sender ID, 같은 sender의 서로 다른 연결, 외부 연결과 없는 연락처, 중복·잘못된 태그·빈 배열을 확인합니다.
유효성 오류를 먼저 분류한 뒤 유효한 동일 식별자 행을 모두 중복으로 분류합니다.
관리자 권한 조회 후 역할 강등과 최종 읽기 전 연락처 삭제도 재현했습니다.
미리보기 전후 모든 public 테이블의 행 내용을 비교했고 발송 알림은 없었습니다.
이 검사는 운영 데이터나 실제 발송을 검증하지 않습니다.

## 실제 브라우저

프로젝트의 실제 정적 화면과 API를 임시 DB에 연결하고 인증만 합성 사용자로 대체했습니다.
파일은 로컬에서 만든 v1 표본이며 Meta·운영 네트워크 요청은 없습니다.
브라우저 검증기의 결과 행을 하나 제거했을 때 예상한 실패 메시지가 나오는 것을 확인한 뒤 원상 복구하여 검사했습니다.

- 7개 CSV 레코드를 변경 2·변경 없음 1·오류 1·중복 2·조회 불가 1로 표시했습니다.
- 여러 줄 필드 값은 행 수를 늘리지 않았고 무시 대상 값은 결과에 노출하지 않았습니다.
- HTML 모양의 태그는 텍스트로 표시했고 실행 가능한 요소를 만들지 않았습니다.
- 잘못된 UTF-8과 파일 크기 초과는 API 전송 전에 거절했습니다.
- 파일 교체와 실패는 이전 결과를 지웠으며 지연된 파일 읽기·API 응답은 무시했습니다.
- 세션 초기화·연결 삭제 무효화는 파일과 결과를 지웠고 상담원 설정은 컨트롤을 숨기고 비활성화했습니다.
- 기존 연락처의 편집 초안은 검사 전후 유지됐습니다.
- 25행 결과를 처음 20행, 추가 표시 후 25행으로 확인했습니다.
- 잘못된 응답 형태는 거절하고 이전 결과를 남기지 않았습니다.
- 390px 모바일에서 문서 폭은 390px이며 가로 넘침이 없었습니다.

데스크톱·모바일 화면 자료는 저장소 밖의 보존용 리뷰 디렉터리에 보관합니다.
운영자의 화면 승인과 PR 병합은 별도 단계입니다.

## 독립 검토와 남은 범위

API·권한·파서와 화면·지연 응답을 두 개의 읽기 전용 리뷰로 나누어 검사했습니다.
중복 판정 순서에 대한 초기 지적은 명시한 오류 우선 계약과 DB 회귀 테스트를 재대조하여 철회됐으며 최종 차단 사항은 없습니다.
루트 검토는 기존 태그 저장 검증과의 동일성, 단일 SELECT의 권한·연결·댓글 조건, 실제 브라우저 결과를 확인했습니다.
별도 스키마나 마이그레이션을 추가하지 않았습니다.
가져오기 적용·식별자 병합/분리와 #25의 운영 검증은 남아 있습니다.
