# 채널 계약 로컬 검증 기록

2026-10-04, 기준 `7b3ea96`, `feat/37-channel-contract`에서 [#37 계약](../specs/2026-10-04-channel-contract.md)을 검증했습니다. 이 기록은 운영 배포·실계정·실제 두 번째 채널 검증이 아닙니다. 테스트는 로컬 합성 계정·응답과 폐기용 `127.0.0.1:5433/automations_test`만 사용했습니다.

## 먼저 재현한 실패

- 기존 코드에서 새 API 검사 3개가 실패했습니다. 상태의 `channel`이 없고, 지원하지 않는 타입과 명시적 텍스트가 모두 400이었습니다. 기대값은 각각 Instagram 설명, 422 거절, 202 호환 접수입니다.
- 공통 계약·Instagram 어댑터 단위 파일은 모듈이 없는 상태에서 먼저 실행했습니다. 이 실패는 동작 판정 실패가 아니라 모듈 부재입니다.
- 실제 Chromium에서 파일 붙여넣기가 취소되지 않는 실패를 먼저 확인했습니다. 화면 검토에서 도움말이 라벨 폼에 있던 문제도 발견해, 작성기 내부에서 보이는지 검사하는 실패를 추가한 뒤 고쳤습니다.

## 자동 검사

- 타입 검사 통과, 단위 224/224 통과. 테스트용 어댑터는 실제 공급자·네트워크·런타임 등록 없이 서로 다른 불투명 식별자, 수신 키, capability, 동의 범위, 합성 시간 창과 결과를 검사합니다.
- DB 493/493 통과. 지원하지 않는 요청은 outbox·감사 기록·queue 알림을 만들지 않고, 추가 필드는 여전히 400입니다. 생략/명시적 텍스트는 같은 한 건을 반환하며 내용 변경은 409입니다. 기존 역할·연결·시간 창·토큰·동의·claim·재시도 검사도 통과했습니다.
- 전송 뒤 감사 기록 저장 실패는 `sending` claim을 유지하고 stale 복구 때만 `unknown`이 됩니다. 이를 공급자 오류로 다시 분류하거나 자동 재발송하지 않는 기존 DB 검사를 유지했습니다.
- 실제 번들 기반 workerd 57/57 통과. reply-status 설명, 422/400 거절과 무기록, 기존/명시적 텍스트 멱등성을 검사했습니다. 전체 Trunk는 278개 파일에서 문제 없이 통과했습니다.

기존 서명·중복 수신·계정별 알림, 댓글/팔로우 거절·제한·불확실 결과 검사를 함께 실행했습니다. 공급자 호출은 테스트 fixture로 대체했으며 실제 발송은 하지 않았습니다.

## Chromium 화면과 동작

실제 `/usr/bin/chromium`을 Playwright로 실행하고 저장소 정적 자산과 CSP를 로컬 HTTP fixture에 연결했습니다. 합성 API는 모든 외부 요청을 차단했습니다. 데스크톱 1280px과 모바일 390px에서 32개 검사를 통과했습니다.

- 파일 및 혼합 파일/텍스트 붙여넣기·드롭은 취소되고 초안과 발송 요청 수가 유지됩니다. 일반 텍스트 붙여넣기는 가로채지 않습니다. 도움말은 작성기 내부에서 보이며 textarea에 연결되어 있습니다.
- Enter 줄바꿈, Ctrl+Enter 한 건 예약, 명시적 텍스트 본문을 확인했습니다. 누락·잘못된·미지원 capability는 초안을 유지하고 새 예약을 막으며, DOM 버튼을 강제로 켜도 제출할 수 없습니다.
- 이전 대화의 늦은 응답은 다른 대화의 버튼을 열지 않습니다. 접수 불확실 상태의 원래 요청은 capability 안내가 달라도 같은 키·본문으로 확인할 수 있습니다. `unknown`은 새 예약을 막고 재전송 버튼을 제공하지 않습니다.
- 두 화면 폭의 허용/차단 작성기를 직접 검토했습니다. 390px 가로 넘침, 브라우저 오류, CSP 위반, 외부 요청은 없었습니다. 모바일에서 안내가 줄바꿈되고 비활성 버튼과 초안이 보입니다.

세션 증거는 `/tmp/auto-chatter-37/`에 있습니다. `red-api.log`, `red-contract.log`, `red-browser.log`, `red-visible-help.log`가 최초 실패이고, `types.log`, `unit.log`, `db.log`, `cloudflare.log`, `browser.log`, `trunk.log`가 검사 출력입니다. 재현용 합성 브라우저 harness는 `browser.mjs`, 화면은 `desktop-allowed.png`, `mobile-allowed.png`, `desktop.png`, `mobile.png`입니다. 이 파일들은 개발 세션 산출물이며 저장소나 운영 자산이 아닙니다.

## 완료 경계

독립 검토자는 생산 코드의 서명 이후 파싱, 네임스페이스, 동의·시간 창, 기존 send catch, API 멱등성, 작성기 접수 확인과 네 화면을 검토했고 수정 요청이 없었습니다. 새 DB 스키마·마이그레이션·배포 설정·의존성·공급자 권한은 없습니다.

[#17](https://github.com/AndrewDongminYoo/auto-chatter/issues/17), [#27](https://github.com/AndrewDongminYoo/auto-chatter/issues/27)의 실계정 검증과 #37의 전체 운영 수용은 열린 상태입니다. 이 PR은 병합된 Instagram 토대 위의 공통 코드 경계만 추가하며, 실제 다중 채널 지원을 완료했다고 표시하지 않습니다.
