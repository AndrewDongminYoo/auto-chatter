# 숫자·날짜 연락처 비교 조건 검증

## 범위와 선행 결과

최신 main `791267e807fd54825b2abc720167c712f08bf7be`에서 [로드맵 #11](https://github.com/AndrewDongminYoo/auto-chatter/issues/11)과 실제 구현·열린 이슈·PR을 대조했습니다.
팀·인박스·플로·삭제·토큰 갱신은 이미 구현된 부분이 많아 체크박스를 기준으로 재구현하지 않았습니다.
[#25](https://github.com/AndrewDongminYoo/auto-chatter/issues/25)의 연락처 상세(#139)·관리자 CSV 내보내기(#141)와 기존 단일 필드 필터를 선행 기반으로 사용합니다.
CSV 가져오기와 동의 있는 식별자 병합은 아직 지원하지 않으며, 이번 조회는 기존 댓글 참여자를 계정별로 구분합니다.

[#26](https://github.com/AndrewDongminYoo/auto-chatter/issues/26)의 숫자·날짜 타입별 비교만 확장합니다.
`gt`, `gte`, `lt`, `lte`를 직접 조회·저장 필터·화면에서 지원하며 기존 계정·태그 조건과 AND로 결합합니다.
숫자는 JSON 숫자의 순서로, 날짜는 유효한 `YYYY-MM-DD`의 일자 순서로 비교합니다.
텍스트·boolean 순서 비교, 숫자 문자열, 잘못된 날짜, 누락·null 비교값은 거부합니다.
조회 때 현재 값을 다시 평가하며 미입력은 순서 비교에 포함하지 않습니다.
필터는 발송 동의나 발송 가능 판정이 아니며 새 발송 경로를 만들지 않습니다.

## 실패 관찰과 자동 검사

구현 전 `node --test --test-name-pattern='ordered' src/app/settings.db.test.ts`의 새 검사 3개가 실패했습니다.
숫자·날짜 조회는 기대한 200 대신 400, 저장 조건 생성은 201 대신 400을 반환했습니다.
구현 후 숫자·날짜 각 연산자의 경계, 음수·0·2와 10의 숫자 순서, 미입력, 저장값 보존, 계정·태그 결합, 최신 값 재평가, 외부 작업 공간 거부와 필드 보관 보호를 확인했습니다.
추가한 55명 페이지 검사에서는 기존 커서의 두 페이지를 합친 결과가 순서대로 55명이었고 중복이 없었습니다.
제한된 서버 역할의 workerd는 gte 0 저장·조회·값 변경 뒤 재평가·외부 작업 공간 거부를 확인했습니다.

최종 검사 명령은 다음과 같습니다.

- `corepack pnpm check-types`
- `corepack pnpm test`
- `TEST_DATABASE_URL=postgres://…@127.0.0.1:55433/automations_test corepack pnpm test:db`
- `TEST_DATABASE_URL=postgres://…@127.0.0.1:55433/automations_test corepack pnpm test:cloudflare` (Worker dry-run build 포함)
- `trunk fmt`·`trunk check` (변경 경로)
- `git diff --check`

보안 선행 수정 적용 후 타입 검사, 단위 239개, DB 522개, workerd 58개와 전체 Trunk 296개 파일이 모두 통과했습니다.
최종 전체 Trunk에서 기존 main의 `sharp 0.35.4`에 새 OSV 경고가 발견되어, 기존 override의 하한만 올리는 [별도 Draft PR #157](https://github.com/AndrewDongminYoo/auto-chatter/pull/157)을 선행으로 적용했습니다.
해당 수정의 설치 결과는 sharp 0.35.5이며 연락처 기능은 그 위에 쌓은 PR로 검토합니다.

DB는 `/tmp`의 전용 PostgreSQL 17 클러스터를 사용했습니다.
main의 기존 스키마에 0·false·빈 텍스트·윤일 값 일치 조건을 만든 뒤 `deploy/migrate-multi-user.sql` 전체를 두 번 실행해 기존 조건 보존과 gte 0 저장을 확인했습니다.
세그먼트 RLS는 켜져 있고 서버 역할의 DELETE 권한은 거부된 상태를 유지했습니다.

## 실제 로컬 브라우저

합성 인증 사용자와 실제 로컬 API·DB를 연결하고 외부 요청을 차단한 Chromium으로 확인했습니다.
전역 발송과 공개 Instagram 연결은 모두 꺼진 상태입니다.

- 숫자 gte 0은 0·10 참여자만 표시했습니다.
- 합성 저장 HTTP 503 뒤 이름·gte·0 초안이 보존되고, 재시도는 201을 반환했습니다.
- 저장된 숫자·날짜 필터를 다시 선택하면 비교 연산자와 0·날짜 값이 복원됐습니다.
- `2024-02-29` gt는 `2024-03-01`만, lte는 `2024-02-28`과 당일을 표시했습니다.
- 날짜 값은 도구의 `fill`이 비워 버려 DOM의 date 값으로 입력한 뒤 키보드 Enter와 버튼으로 제출했습니다. 네이티브 날짜 선택기 조작은 검증하지 않았습니다.
- 텍스트 필드로 전환하면 순서 비교 선택지는 숨김·비활성화되고 eq로 돌아갔습니다.
- main의 이전 app.js만 임시 복원하면 순서 비교의 값 입력 표시 검사가 실패했고, 현재 코드로 복원하면 통과했습니다. 현재 파일은 finally 구문으로 보존했습니다.
- 390×844와 1280×900 스크린샷을 직접 검토했습니다. 390px에서 문서 폭도 390px이었으며 비교 문구·값 입력·제출 버튼이 잘리지 않았습니다.

화면의 긴 선택 문구는 숫자의 이상·초과·이하·미만과 날짜의 당일 포함/제외 이전/이후로 구분해 줄였습니다.
Safari·Firefox·실기기 터치·화면 읽기 음성·운영자 화면 승인은 확인하지 않았습니다.

## 적용 경계와 남은 의존성

운영 적용에는 마이그레이션 036을 전체 실행기로 적용한 뒤 Worker 배포가 필요합니다.
이 작업은 운영 DB 변경·배포·메시지 발송·공급자 설정 변경을 수행하지 않습니다.
`SEND_ENABLED=false`, `INSTAGRAM_PUBLIC_CONNECT_ENABLED=false`를 유지합니다.

#26의 AND/OR, 동의·활동 조건, 저장 전 대상 미리보기·제외 사유와 캠페인 대상 고정은 후속입니다.
#25의 가져오기·동의 있는 식별자 연결이 남아 있고, 청구 연락처 원장 #51과 리포트 #50은 해당 식별자 계약을 확인한 뒤 진행해야 합니다.
공개 Instagram 승인·추가 사용자 검증 #14, 운영 수용 #13·#64와 SMS·판매 플랜 결정 #45·#53은 외부 승인 또는 운영자 판단이 필요합니다.
#11·#26과 운영 수용 이슈를 이 변경만으로 닫지 않습니다.
