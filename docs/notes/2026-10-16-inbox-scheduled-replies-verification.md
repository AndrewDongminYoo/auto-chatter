# 인박스 일회성 예약 답장 검증

## 범위와 환경

[#24](https://github.com/AndrewDongminYoo/auto-chatter/issues/24)의 일회성 예약 답장 단계입니다.
[계약](../specs/2026-10-16-inbox-scheduled-replies.md)과 [구현 계획](../plans/2026-10-16-inbox-scheduled-replies.md)을 기준으로 검사했습니다.
격리된 UTF8 PostgreSQL의 `automations_test`, 모의 Graph, 실제 workerd와 로컬 합성 API를 사용했습니다.
운영 DB 적용·배포·실제 Meta 권한·DM 도착은 검증하지 않았으며 이 결과로 #24를 종료하지 않습니다.

## 실행한 검사

- `corepack pnpm check-types`: TypeScript 타입 검사 통과.
- `corepack pnpm test`: 단위 테스트 297개 통과.
- `corepack pnpm test:db`: PostgreSQL 통합 테스트 627개 통과. 운영 상태 계산과 수정 후 생성 요청 재확인 회귀를 포함한 최종 전체 실행 결과입니다.
- `corepack pnpm test:cloudflare`: 78개 통과. workerd의 실제 API로 예약 생성·same-origin 거부·수정·오래된 버전 거부·취소를 검사하고, 모의 Graph와 Queue/cron으로 예정 시각·즉시 답장 순서·발송 전 생성자 제거를 확인합니다.
- 구현 전 예약 생성은 기대한 202 대신 400으로 실패했습니다. 운영 상태 회귀는 미래 예약을 대기 시간으로 잘못 센 `1500 !== null` 실패를 확인한 뒤 수정했습니다.
- 최초 생성 뒤 예약을 수정하면 원래 요청의 접수 확인이 `409 !== 202`로 실패하는 회귀를 재현했습니다. 최초 접수 fingerprint를 감사 행에 보존하도록 수정한 뒤 예약 DB 테스트 12개와 타입 검사가 통과했습니다.

호스팅 리뷰에서 먼저 생성한 예약이 뒤에 접수된 즉시 답장의 unknown을 건너뛰는 문제를 확인했습니다.
실제 모의 전송 오류로 unknown을 만든 뒤 예약을 발송 시각이 지난 상태로 바꿔 워커·cron/Queue·운영 지표 회귀 3개가 실패하는 것을 확인했습니다.
sending·미해결 unknown 차단을 생성 순서와 분리한 뒤 3개가 통과했으며, 운영자 해결 뒤 예약이 다시 처리되는 것도 확인했습니다.
위 전체 실행 수는 이 수정 이후 결과입니다.

DB 검사는 시간대 변경과 동일 키 재확인, 입력 범위, 다른 작업 공간·생성자 권한, 수정·취소의 버전 경합, 워커 선점 후 변경 거부, 발송 직전 수신 거부·창 만료·멤버 제거, migration 049 재실행과 취소 행 내보내기·작업 공간 삭제를 포함합니다.
작업 공간·멤버·연결 잠금과 예약 행의 버전은 동시에 들어온 변경 하나만 성공시키며, 성공한 취소는 외부 POST를 만들지 않습니다.

## 화면 검사

실제 `public/app/` HTML·CSS·JavaScript를 격리 브라우저 `ac-scheduled`에서 로컬 합성 API와 함께 실행했습니다.
브라우저의 날짜 필드 일괄 입력은 값을 비워 두어, 날짜 값은 DOM 입력 이벤트로 제공하고 실제 Enter·클릭·선택 동작으로 제출 경계를 확인했습니다.

- 예약 생성 후 발신 이력에 `예약 대기`, 확정 시각과 시간대가 표시됩니다.
- 예약 문구 수정 후 저장된 새 문구·버전을 읽었습니다.
- 충돌 응답 후 입력은 남고 오래된 버전으로 수정·취소하는 버튼은 잠깁니다. 최신 예약으로 다시 편집하면 해제됩니다.
- 취소와 생성 응답을 503으로 유실시킨 뒤 같은 요청 키·본문으로 재확인했습니다. 기록된 요청을 비교해 동일성을 확인했고 예약 행은 중복 생성되지 않았습니다.
- 접수 여부를 모를 때 문구·보낼 시각을 바꿀 수 없습니다.
- 날짜 필드에서 Enter를 눌러도 예약 요청이 생기지 않습니다.
- 대화를 바꾸면 다른 대화에 초안이 노출되지 않고 돌아왔을 때 기존 문구가 유지됩니다. 로그아웃 확인 뒤 문구·시각·예약 수정 폼이 모두 지워졌습니다.
- 실제 설정 화면에서 시간대를 UTC로 바꾸면 미접수 시각만 비워지고 문구가 유지됩니다. 기존 예약의 확정 시각은 바뀌지 않습니다.
- 수신 거부 상태에서는 예약 수정이 막히지만 취소는 가능합니다.
- 1440px 데스크톱과 390px 모바일에서 확인했으며 모바일 문서 너비가 화면을 넘지 않았습니다.
- 검증용 예약 행이 없을 때 `scheduled fixture missing`으로 화면 확인식을 먼저 실패시킨 뒤 실제 생성 후 통과시켰습니다.

화면 캡처는 저장소 옆 `pr-loop-reviews/auto-chatter/inbox-scheduled-replies-20261016/`에 보관합니다.
운영자의 최종 화면 승인은 별도입니다.
