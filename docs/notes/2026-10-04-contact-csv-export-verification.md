# 관리자 연락처 CSV 내보내기 검증

## 범위

[#25](https://github.com/AndrewDongminYoo/auto-chatter/issues/25)의 [CSV 내보내기 계약](../specs/2026-10-04-contact-csv-export.md)만 확인했습니다.
최초 구현 기준은 `7b3ea96`입니다. 이후 웹훅 작업 공간 보호 #138·연락처 상세 #139·채널 계약 #140이 병합된 `7c74963` 위로 재기반했습니다.
테스트 목록과 API import 충돌은 양쪽 추가 항목을 모두 유지했고, 세 기능의 구현을 바꾸지 않았습니다.
로컬 일회용 PostgreSQL `automations_test`와 합성 데이터만 사용했습니다. 운영 DB·실제 공급자·실제 계정은 호출하지 않았습니다.
스키마·마이그레이션·가져오기·식별자 병합·동의·보존 정책은 바꾸지 않았습니다. #17·#27의 외부 검증과 #25 전체 완료 조건은 남습니다.

## 회귀 및 서버 검사

구현 전 DB 테스트 8개가 실패했고, 공개 경로는 예상한 성공/검증 오류 대신 `404`를 반환했습니다.
인코더 테스트는 모듈 미구현으로 실행에 실패했고, 브라우저 검사는 내보내기 버튼이 없어 실패했습니다.
추가 회귀에서는 연결 획득이 예산을 넘긴 직후 거절될 때 일반 오류가 나오던 것을 확인한 뒤 `503 contact_export_timeout`으로 고쳤습니다.
접는 도움말도 요소가 없는 상태에서 브라우저 실패를 확인한 뒤 추가했습니다.

- 단위 8개: 고정 헤더·큰따옴표/CRLF, 한국어·개행·구분 문자, 큰 ID/앞자리 0, 원래 작은따옴표, 숨은 공백/제어 문자 뒤 수식 접두사와 전각 형태, NULL/빈 계정 이름, JSON 자료형, 정확한 UTF-8 바이트 한도와 한 바이트 초과, 행 한도, 늦은 연결 파기와 획득 시간 초과를 확인했습니다.
- DB 10개: 소유자/관리자 허용, 상담원/없는 멤버/제거된 멤버 거부, 모든 query 거부, 다른 작업 공간 제외, 연결별 중복 댓글 합치기·연결 해제 계정 포함, 마이크로초와 SQL 숫자 JSON 정밀도, 활성 필드의 `0`/`false`/빈 문자열/날짜, 보관·미설정 필드 제외, 두 중지 사유의 네 조합을 확인했습니다.
- 실제 `REPEATABLE READ READ ONLY`와 모든 배치의 일관성을 확인했습니다. 첫 배치 뒤 다른 세션에서 태그·값·보관 상태·댓글 삭제/추가를 커밋해도 기존 내보내기는 옛 스냅샷을, 다음 내보내기는 새 상태를 읽었습니다.
- 전체 테이블 전후 비교와 알림 카운터로 읽기에 따른 저장 변경·큐 알림이 없음을 확인했습니다. 원문 댓글/DM·자격 증명·다른 멤버 리마인더용 표식은 파일에 없었습니다. 동의 근거·상담 메모 테이블을 조회하지 않는 것도 코드로 확인했습니다. 활성 필드에 저장한 답장은 내보내기 대상이라는 개인정보 경계는 유지합니다.
- 실제 5,001명 요청은 JSON 오류만 반환하고 첨부 헤더가 없었습니다. 내부의 작은 행/바이트 예산으로 롤백을, `pg_sleep`과 작은 총 시간 예산으로 남은 시간 제한·연결 파기를 확인했습니다. 실패한 쿼리는 롤백하고 아직 진행 중일 수 있는 시간 초과 쿼리는 풀로 재사용하지 않았습니다.
- workerd 검사는 제한된 서버 역할로 CSV 조회·BOM·원문/자격 증명 제외, query 거부와 상담원 직접 호출 거부를 확인합니다.

## 실제 브라우저

실제 `public/app` 파일을 로컬 HTTP 서버와 CSP로 제공하고 API만 합성 응답으로 바꿨습니다.
Playwright 1.63와 로컬 Chromium으로 23개 항목을 통과했습니다. 외부 요청·페이지/서버 오류·CSP 위반은 모두 0건입니다.

- 키보드로 접힌 “CSV 값 읽는 방법”을 펼치고 닫았으며, 소유자/관리자만 버튼과 설명을 보고 상담원은 보지 못했습니다.
- 키보드로 다운로드를 시작하고 중복 클릭 차단과 진행 상태를 확인했습니다. 현재 화면 한 행보다 많은 합성 연락처 52개가 포함된 실제 파일을 읽어 BOM이 정확히 한 번 있고 큰 ID·앞자리 0·SQL 숫자 JSON이 보존되는지 확인했습니다.
- 진행 중 필터를 바꿔도 전체 범위였고, 필터와 저장 전 태그/필드 수정은 그대로 남았습니다. 요청에는 목록 query가 없었습니다.
- 빈 결과는 헤더 파일을 만들고, 초과·시간 초과·일반 오류는 다운로드를 만들지 않았습니다. 로그아웃과 화면의 연결 데이터 삭제 후 도착한 응답도 다운로드하지 않았습니다. 생성한 객체 URL은 모두 해제됐습니다.
- 390px에서 수평 넘침이 없고 버튼 높이가 44px 이상이었습니다. 데스크톱·모바일 PNG를 직접 열어 줄바꿈·접힌 안내·보존된 초안을 확인했고 독립 리뷰도 같은 화면과 구현을 확인했습니다.

## 최초 실행 및 증거

`check-types`가 통과했고, 전체 단위 테스트 225개·DB 테스트 500개·Cloudflare 테스트 57개가 실패/건너뛰기 없이 통과했습니다.
`trunk check --all --no-fix`는 277개 파일에서 문제를 찾지 않았으며 `git diff --check`도 통과했습니다.
고정된 구현과 브라우저 증거에 대한 독립 리뷰에서도 수정할 사항이 없었습니다.

회귀 로그는 `/tmp/auto-chatter-25-csv-red-unit.log`, `-red-db.log`, `-browser-red.log`, `-acquisition-red.log`, `-disclosure-red.log`이며 모두 같은 접두사를 씁니다.
최종 로그도 `/tmp/auto-chatter-25-csv-` 아래 `types.log`, `unit.log`, `db.log`, `cloudflare.log`, `trunk.log`, `browser.log`로 보관했습니다.
브라우저 도구는 `/tmp/auto-chatter-25-csv-browser/verify.mjs`, 실제 파일은 `/tmp/auto-chatter-25-csv-downloaded.csv`, 화면은 `/tmp/auto-chatter-25-csv-desktop.png`와 `/tmp/auto-chatter-25-csv-mobile.png`입니다. 임시 증거 파일은 저장소에 넣지 않습니다.

## 병합된 main과의 통합 검증

`7c74963` 위에서 타입 검사, 단위 232개·DB 512개·workerd 57개가 실패/건너뛰기 없이 통과했습니다.
`package.json`은 main의 전체 테스트 목록에 CSV 단위·DB 파일만 추가하며, 웹훅만 있는 작업 공간의 이동 거부와 생성 경쟁, 연락처 상세의 권한·신원 근거, 채널별 답장 제한 회귀도 함께 실행했습니다.
CSV·연락처 상세·채널 제한 브라우저 검사는 각각 23개·19개·32개가 통과했습니다. 외부 요청과 페이지/서버 오류는 0건이며, 갱신된 모바일 화면도 직접 확인했습니다.
`trunk check --all --no-fix`는 289개 파일에서 문제를 찾지 않았고 `git diff --check`도 통과했습니다.

원래 CSV 커밋과의 `range-diff`, API/UI/workerd 자동 병합, main의 보호 코드 보존을 독립 리뷰했습니다. 코드 문제는 없었으며 연락처 상세 PR 상태가 오래된 명세 문장 하나를 정정했습니다.
통합 실행 로그는 `/tmp/auto-chatter-141-integration-` 접두사의 `types.log`, `unit.log`, `db.log`, `cloudflare.log`, `trunk.log`, `browser-csv.log`, `browser-details.log`, `browser-channel.log`입니다.
브라우저 도구는 위 CSV 도구와 `/tmp/auto-chatter-25-browser/verify.mjs`, `/tmp/auto-chatter-37/browser.mjs`를 사용했습니다. 호스팅 CI의 최종 커밋과 실행 링크는 PR #141 본문에 기록합니다.

## 확인하지 않은 것

Excel·LibreOffice 등 스프레드시트 앱에서 직접 열거나 편집·다시 저장한 결과, 실제 스크린 리더 낭독과 실제 모바일 기기는 확인하지 않았습니다.
다운로드 원본의 바이트/값 보존 검증을 모든 앱의 수식 해석·재저장 안전성 보장으로 확대하지 않습니다.
운영 마이그레이션·배포·실제 사용자 데이터 내보내기·실제 발송은 하지 않았습니다.
