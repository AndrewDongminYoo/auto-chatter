# 세그먼트 그룹 편집 화면 검증

## 결과와 범위

[#26](https://github.com/AndrewDongminYoo/auto-chatter/issues/26)의 [그룹 화면](../specs/2026-09-27-contact-segments.md#그룹-화면)(그룹 편집 화면과 트리 세그먼트 수정, PR B)을 로컬에서 검증했습니다.
기준 커밋은 `d44dc12`이며, 검증한 것은 이 작업 트리의 미커밋 변경입니다.
서버, 스키마, 마이그레이션은 바꾸지 않았습니다.
이 기록은 운영 배포나 #26 전체 완료를 뜻하지 않으며, 발송 대상 지정은 별도로 승인받을 후속 범위입니다.

기존 테스트는 바꾸지 않았습니다.
새 검사는 `src/app/condition-tree-model.test.ts`의 검사 18개이며, 이 파일을 `test` 스크립트에 추가했습니다.
이 검사는 `public/app/condition-tree-model.js`를 `node:vm`으로 읽어 다음을 확인합니다.

- 모듈의 한도가 `src/app/contacts.ts`의 `CONDITION_TREE_*` 값과 같습니다.
- 빈 초안은 조건이 없는 `all` 그룹 하나이며 요청 형태로 만들 수 없습니다.
- 그룹 추가는 5개까지 받고 6번째를 거절하며, 조건이 10개이면 그룹 추가도 거절합니다.
  조건 추가는 그룹마다 5개까지, 모두 10개까지 받고 6번째와 11번째를 거절합니다.
  거절은 같은 이유를 비활성화 이유 함수와 함께 돌려주고 초안을 바꾸지 않습니다.
- 마지막 그룹은 삭제할 수 없습니다.
  조건 삭제로 그룹이 비면 그 초안은 "그룹 2에 조건을 하나 이상 추가해 주세요."로 거절됩니다.
- 그룹과 조건은 한 칸씩 움직이고, 맨 위·맨 아래에서는 거절하며, 조건은 다른 그룹으로 넘어가지 않습니다.
- 모드는 루트와 그룹에 `all`·`any`만 받습니다.
  조건 값은 정해진 키의 문자열과 알려진 종류만 받습니다.
- 완성된 초안은 순서를 유지한 `condition_tree`가 되고, 숫자·불리언·날짜·빈 텍스트 값과 `negate: true`, 값 없는 `is_set`·`is_unset`을 서버 형태로 만듭니다.
  태그는 입력한 그대로 보냅니다.
- 빈 태그, 고르지 않은 필드, 쓸 수 없는 필드, 타입에 맞지 않는 비교 방식, 빈·무한·문자 숫자 값, 빈 날짜, 알 수 없는 불리언 값은 위치("그룹 2의 조건 1")를 넣은 이유로 거절합니다.
  한도 밖의 초안과 모르는 모드도 거절합니다.
- 저장된 트리를 초안으로 읽고 다시 만들면 같은 트리입니다.
- 비교는 순서를 구분합니다.
  그룹·조건 이동, 모드, 종류, 태그 대소문자 변경은 변경이고, 이동을 되돌리면 같습니다.
  조건 종류가 보내지 않는 입력(태그 조건의 필드, 값이 필요 없는 비교의 값)은 비교하지 않습니다.
- 필드 보관은 그 필드의 조건을 대소문자 구분 없이 모두 지우고 개수를 세며, 비게 된 그룹은 남깁니다.
- 요약은 PR A의 문장(괄호, " 그리고 "·" 또는 ", "태그 X 있음/없음")과 같습니다.
- 저장하지 않은 트리 판정은 조건이 없는 트리를 제외하고, 저장된 트리 중 하나와 순서까지 같으면 저장된 것으로 봅니다.

검사는 모듈보다 먼저 작성했고, 모듈이 없을 때 파일을 읽지 못해 실패하는 것을 확인한 뒤 모듈을 작성했습니다.
첫 실행의 실패 원인은 다른 realm 배열의 `deepEqual` 비교였고, 검사 쪽에서 JSON 왕복으로 고쳤습니다.
음성 대조로 모듈을 한 번에 하나씩 바꾸고 이 검사를 실행했습니다.
실패한 검사 수는 `node --test`의 `fail` 값입니다.
그룹 한도 6개(3개), 그룹 추가와 조건 추가 양쪽의 10개 확인 제거(2개), 순서를 무시하는 비교(1개), 위쪽 끝 이동 허용(1개), 빈 그룹 확인 제거(3개), `negate` 누락(2개)의 6개 변경은 모두 검사가 실패했습니다.
필드 ID의 소문자 비교 제거는 처음에는 실패하지 않았습니다.
검사의 필드 ID에 영문자가 없었기 때문이며, 영문자가 든 ID의 대소문자 검사를 추가한 뒤 두 가지 변경(보관 ID와 조건 ID 각각)이 각각 1개 실패했습니다.
이 대소문자 검사는 코드보다 나중에 작성했으므로 위 음성 대조가 그 근거입니다.
변경은 매번 원본 사본으로 되돌렸습니다.
리뷰에서 편집 모드 밖의 트리가 저장하지 않은 변경으로 잡히지 않는다는 지적을 받아 `segmentTreeUnsaved`를 추가했습니다.
이 검사도 함수보다 먼저 작성했고, 함수가 없어 `segmentTreeUnsaved is not a function`으로 실패하는 것을 확인했습니다.
조건 수 확인 제거, 순서 비교 대신 조건 수 비교, 첫 번째 저장된 트리만 비교하는 3개 변경은 각각 이 검사 1개를 실패시켰습니다.

## 화면 연결

`public/app/app.js`의 DOM 연결을 실행하는 검사 도구는 저장소에 없습니다.
`node --check public/app/app.js`와 `node --check public/app/condition-tree-model.js`로 구문만 확인했습니다.
`[UNVERIFIED: real browser]` Playwright 라이브러리가 이 작업 트리의 `node_modules`에 없고, 설치는 새 의존성이므로 실제 브라우저 확인은 하지 않았습니다.
대시보드는 Supabase 로그인 세션이 있어야 열리므로 오프라인 정적 파일만으로는 연락처 화면에 들어갈 수 없습니다.

운영자가 실제 화면에서 확인할 항목은 다음과 같습니다.

1. 연락처 필터에서 "그룹 조건 사용"을 누르면 태그·추가 정보 입력과 결합 선택이 비활성화되고, 그룹 1과 "그룹 1에 조건을 하나 이상 추가해 주세요."가 보입니다.
2. 그룹 1에 태그 있음 `vip`와 추가 정보 조건(숫자 필드 이상 100000)을, 그룹 2에 태그 있음 `event`를 넣고 루트를 "하나 이상의 그룹 만족"으로 바꿉니다.
   미리보기가 "그룹 조건 불일치" 사유와 맞는 합계를 보여 주고, 필터 적용이 목록을 불러옵니다.
3. 조건 하나의 태그를 비우면 이유가 보이고, 필터 적용·미리보기·필터 저장이 요청을 보내지 않습니다(브라우저 개발자 도구의 네트워크 탭).
4. 새 필터로 저장한 뒤 저장된 필터에서 고르면 편집 화면이 저장된 트리로 채워집니다.
5. "필터 수정"을 누르고 그룹을 아래로 옮겼다가 다시 위로 옮긴 뒤 페이지를 닫으면 저장하지 않은 변경 경고가 나오지 않고, 한 번만 옮긴 상태에서는 경고가 나옵니다.
   한 번 옮긴 뒤 변경 저장을 누르면 저장된 필터가 바뀐 순서로 다시 채워집니다.
6. 두 탭에서 같은 필터를 수정해 한쪽을 먼저 저장하면, 다른 쪽 저장은 저장된 트리의 요약과 함께 충돌을 보여 주고 입력한 초안이 그대로 남습니다.
   "저장된 값 불러오기"는 저장된 트리로 편집 화면을 채웁니다.
7. 초안 트리에서만 쓰는 필드를 보관하면, 확인 창에 검색 조건 해제 안내가 나오고, 보관 뒤 지운 조건 개수와 완성 안내가 표시됩니다.
8. 그룹 5개에서 "그룹 추가"가, 그룹 하나에 조건 5개 또는 모두 10개에서 "조건 추가"가 이유와 함께 비활성화되고, 마지막 그룹의 "그룹 삭제"도 이유와 함께 비활성화됩니다.
9. 저장 중에는 편집 화면의 모든 입력이 잠깁니다.
   필터 수정 중 조건 하나의 종류를 바꿨다가 되돌린 뒤 페이지를 닫으면 저장하지 않은 변경 경고가 나오지 않습니다.
10. 직접 만든 트리에 조건이 있을 때 "그룹 조건 지우기"를 누르거나 다른 저장된 필터를 고르면 확인 창이 나오고, 취소하면 트리가 그대로 남습니다.
    같은 트리로 페이지를 닫거나 새로고침하면 저장하지 않은 변경 경고가 나오고, 로그아웃과 Instagram 계정 연결은 버리기 확인을 받습니다.
    저장된 트리 세그먼트를 고른 직후에 지우면 확인 창 없이 지워지고, 같은 필터를 다시 고르면 트리가 돌아옵니다.
    태그를 `VIP`처럼 입력한 트리를 새 필터로 저장하면 편집 화면의 태그가 `vip`로 바뀌고, 그 뒤에는 같은 동작에서 확인 창이 나오지 않습니다.
11. 폭 375px에서 가로 스크롤 없이 모든 조건과 버튼을 쓸 수 있고, 탭 순서가 그룹 결합, 그룹, 조건, 조건 버튼, 그룹 버튼, 그룹 추가 순서입니다.
