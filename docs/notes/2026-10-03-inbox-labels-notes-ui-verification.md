# 인박스 라벨·내부 메모 화면 검증

## 대상과 경계

GitHub [#23](https://github.com/AndrewDongminYoo/auto-chatter/issues/23)의 두 번째 부분인 [라벨과 내부 메모](../specs/2026-10-03-inbox-labels-notes.md)(#23-B)를 확인했습니다.
리마인더(#23-C)와 키워드 자동 라벨은 이 변경에 없습니다.
[검색·읽음 화면 검증](2026-10-03-inbox-search-read-ui-verification.md)과 같은 방식으로, 실제 `public/app` 파일과 실제 `appApi`를 로컬 PostgreSQL 17(포트 5434)의 일회용 DB(`automations_ui`, 실행마다 새로 만들고 확인 뒤 삭제)에 연결한 임시 로컬 서버를 세션 임시 디렉터리에 새로 만들어 사용했습니다.
임시 서버는 `/app/` 응답에 `public/_headers`의 Content-Security-Policy를 그대로 붙였습니다.
Supabase는 세션 쿠키 값으로 `/user` 응답을 돌려주는 대역으로 바꿨고, 대역은 다른 모든 외부 요청을 거절하고 기록하도록 했습니다. 기록된 외부 요청 시도는 0건이었고, 운영 DB·Supabase·Meta·Cloudflare는 호출하지 않았습니다.
합성 데이터는 소유자·관리자·상담원 두 명, 연결 둘(`ui_shop`, `ui_studio`, 둘 다 연결 해제 상태), 대화 여섯 개, 라벨 넷(그중 "이벤트 응모"는 보관), 라벨이 붙은 대화 셋, 한 대화의 메모 둘입니다.
화면 동작은 Playwright 1.63.0으로 headless Chromium(chrome-headless-shell 1243)을 조작해 확인했습니다.

## 자동 검사

`src/app/inbox-labels-notes.db.test.ts`의 22개 테스트가 라벨 관리와 역할, 50개 한도와 동시 추가, 이름 중복, 보관한 라벨의 거부, 버전 충돌, 버전마다 감사 한 행, 메모의 형식과 페이지, 메모가 메시지 목록과 DM 검색에 나오지 않음, 라벨 필터와 커서, 세 삭제 함수와의 동시 실행, 사람 삭제의 범위, migration 033 재실행을 확인합니다.
서버 역할이 메모와 라벨 감사 기록을 고치거나 지우지 못하고, 라벨 행의 CHECK가 서버 역할로도 동작하는 것은 `src/cloudflare/access.db.test.ts`가 확인합니다.
잠금 하나씩 빼고 같은 파일을 실행해 테스트가 그 잠금을 잡는지 확인했습니다. 실패는 모두 잠금 대기 시간 초과가 아니라 값 확인에서 나왔고, 잠금을 되돌리자 모두 통과했습니다.

- 새로 붙이는 라벨 행의 `FOR SHARE`를 빼자, 확인 뒤 커밋 전에 들어온 보관이 기다리지 않았고, 먼저 열린 보관 뒤의 라벨 변경이 보관된 라벨을 붙였습니다(두 테스트 실패).
- 라벨 변경과 메모 추가에서 연결 행 `FOR SHARE`를 각각 빼자, 연결·사람 삭제 뒤에 행이 남거나 사람 삭제가 쓰기를 기다리지 않았습니다(각각 세 테스트 실패).
- 라벨 추가의 작업 공간 행 잠금을 빼자 49개일 때 동시에 들어온 두 추가가 모두 성공했습니다.
- 라벨 변경에서 작업 공간 행 `FOR SHARE`를 빼자 작업 공간 삭제와의 동시 실행 테스트가 `deadlock detected`로 실패했습니다.

## 브라우저 검사

점검 스크립트의 50개 항목이 모두 통과했습니다.

- 상담원 목록에서 라벨이 붙은 대화에만 라벨 칩이 보였고, 보관한 라벨은 "이벤트 응모 (보관됨)"으로 다른 모양의 칩이었습니다. 상담원에게는 "인박스 라벨" 설정 칸이 보이지 않았습니다.
- "라벨" 필터에는 "전체"와 보관한 라벨을 포함한 라벨 넷이 있었고, VIP를 고르자 VIP 대화 둘만 남았습니다. 상태 "완료"를 더하면 "검색어나 보기 조건에 맞는 대화가 없습니다."가 보였고, 상태를 되돌려도 라벨 필터는 유지됐습니다.
- 키보드: 대화 버튼에 초점을 두고 Enter로 열었습니다. 라벨 체크박스에서 Space로 "배송 지연"을 고르자 "저장하지 않은 변경 · 3 / 10"이 보였고, Tab이 나머지 체크박스를 거쳐 "라벨 저장"에 닿았으며 Enter로 저장했습니다. DB에는 버전 2의 라벨 셋과 감사 행 두 개(시드 1, 이번 1)가 있었고, 목록을 다시 불러오지 않고 그 행에 새 칩이 붙었습니다.
- 보관한 라벨이 붙은 대화에서는 그 라벨이 체크된 채 보였고, 떼고 저장하자 선택지에서 사라졌습니다. 보관한 라벨이 붙지 않은 대화에는 그 라벨이 선택지로 나오지 않았습니다.
- 다른 상담원이 API로 먼저 라벨을 바꾼 뒤 저장하자 "다른 멤버가 먼저 라벨을 바꿔 최신 라벨을 다시 불러왔습니다."가 보였고, 체크박스가 다른 상담원이 저장한 라벨로 바뀌었습니다.
- 저장하지 않은 변경이 있는 채로 다른 상담원이 API로 라벨을 다시 바꾸고 "대화 새로고침"을 누르자, 화면은 새 버전을 읽었지만 저장하지 않은 변경은 남았습니다. 그 변경을 저장하자 덮어쓰지 않고 같은 충돌 안내가 보였고, DB에는 다른 상담원이 저장한 버전 3의 라벨 셋이 그대로 있었습니다. 화면은 변경을 시작할 때의 버전을 `expected_version`으로 보냅니다.
- 내부 메모는 메시지 칸 아래에 다른 배경과 "팀 전용" 표시로 나뉘어 최신순으로 보였고, 줄바꿈이 유지됐습니다. 메시지 칸에는 메모 글이 없었습니다. 메모 칸에 키보드로 17자를 입력하자 글자 수 표시가 "17 / 2,000"이 됐고, ⌘ + Enter로 남기자 "나"가 쓴 메모가 맨 위에 붙고 입력란이 비었으며 DB에 저장됐습니다. 메모에만 있는 글(`반품 송장`)로 DM을 검색하면 맞는 대화가 없었습니다.
- 관리자에게는 "인박스 라벨" 칸이 "3 / 50"으로 보였습니다. 키보드로 "교환 요청"을 입력하고 Enter로 추가하자 "4 / 50"이 됐고, 대소문자만 다른 `vip`는 "같은 이름의 라벨이 있습니다"로 거부됐습니다. VIP를 "VIP 고객"으로 바꾸자 목록 칩에 새 이름이 보였고, "교환 요청"을 확인 창을 거쳐 보관하자 동작 버튼 없이 "보관됨"으로 남았습니다.
- 390px에서 라벨 필터를 고른 목록, 연 대화(라벨 칸과 메모 칸), 관리자의 라벨 설정 모두 문서의 `scrollWidth`가 390을 넘지 않았고, 라벨 필터, 라벨 체크박스 줄, "라벨 저장"과 "메모 남기기", 라벨 설정의 버튼 높이는 44px 이상이었습니다.
- 페이지 오류와 CSP 위반은 없었습니다. 콘솔 오류 기록은 합성 연결에 토큰이 없어 생기는 기존 규칙 편집기의 게시물 목록 요청(`/api/connections/:id/media`) 넷과, 점검이 일부러 만든 `409` 셋(라벨 충돌 둘, 이름 중복)뿐이었습니다.
- 점검 스크립트가 결함을 잡는지 보려고 목록 행에 칩을 붙이는 줄을 잠시 빼고 실행하자 두 번째 항목에서 실패했습니다. 코드를 되돌리고, `trunk fmt`가 화면 코드를 정리한 뒤 새 DB에서 다시 실행하자 47개 항목이 모두 통과했습니다. 새로고침 뒤 저장 항목은 저장 요청이 현재 버전을 보내던 이전 줄로 잠시 되돌리자 충돌 안내를 기다리다 실패했고, 되돌린 줄을 고치자 50개 항목이 모두 통과했습니다.
- 운영자 시각 승인용 스크린샷 8장(라벨 칩과 필터를 고른 목록, 라벨 편집, 내부 메모, 관리자의 라벨 설정을 각각 데스크톱과 390px로)은 세션 임시 디렉터리에 PNG로 저장했고 저장소에는 넣지 않았습니다.

## 확인하지 않은 것

- 실제 키보드로 선택 상자를 여닫는 동작, 스크린 리더 낭독, 다크 모드는 확인하지 않았습니다. 필터 선택 상자의 값은 [검색·읽음 화면 검증](2026-10-03-inbox-search-read-ui-verification.md)과 같은 이유로 `selectOption`으로 골랐습니다.
- 메모 추가의 응답을 받지 못한 경우(네트워크 오류나 5xx)의 안내와 "이전 메모 보기"(51개 이상)는 브라우저에서 실행하지 않았고, 메모 페이지는 DB 테스트로만 확인했습니다.
- 대화 라벨 10개 한도에서 나머지 체크박스가 막히는 동작은 브라우저에서 만들지 않았고, 서버의 10개 한도는 DB 테스트로만 확인했습니다.
- migration 033은 운영 DB에 적용하지 않았고 배포하지 않았으므로, 운영 데이터와 실제 Instagram 계정으로 이 화면을 확인하지 않았습니다.
