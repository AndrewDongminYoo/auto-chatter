# 월 캠페인 발송 한도 화면 검증

## 대상과 경계

[#52](https://github.com/AndrewDongminYoo/auto-chatter/issues/52)의 [월 캠페인 발송 한도](../specs/2026-10-12-plan-entitlements.md#월-캠페인-발송-한도)가 화면에 보이는 다섯 곳을 확인했습니다: 설정의 요금제 줄, 캠페인 미리보기의 한도 표시, 승인 거절 문구, 한도로 시작하지 않은 실행의 현황, 그 실행의 승인 영역.
방식은 [DM 트리거 편집기 화면 검증](2026-11-08-dm-trigger-editor-ui-verification.md)과 같습니다.
실제 `public/` 파일과 실제 `appApi`를 로컬 PostgreSQL(포트 5437)의 일회용 DB(`automations_ui52`, `db/schema.sql` 적용, 확인 뒤 삭제)에 연결한 임시 로컬 서버를 사용했습니다.
임시 서버는 `/app/` 응답에 `public/_headers`의 Content-Security-Policy를 붙였고, 요청마다 새 연결 풀을 `appApi`에 넘겼습니다. DB에는 `postgres` 역할로 연결했으므로 서버 역할의 권한 제한은 이 확인에 들어가지 않았습니다.
Supabase는 세션 쿠키 값으로 `/auth/v1/user` 응답을 돌려주는 대역으로 바꿨고, 다른 모든 외부 요청은 막고 기록했습니다. 기록된 외부 요청 시도는 0건이었고, 운영 DB·Supabase·Meta·Cloudflare는 호출하지 않았습니다.
서버, 데이터 준비 스크립트, 점검 스크립트는 세션 임시 디렉터리에 두었고 저장소에는 넣지 않았습니다.
화면 동작은 Playwright 1.62가 headless Chromium(chrome-headless-shell 1248)을 조작해 확인했습니다. 화면 너비는 1280px이고, 확인 창은 모두 승인했습니다.

## 합성 데이터

- 작업 공간 하나: 요금제 `essential`(월 1,000건), 시간대 `Asia/Seoul`, 소유자·관리자 멤버 각 1명.
- 켜진 연결 하나(`ui_shop`, 합성 암호문)와, 모든 수신자 조건을 통과하는 댓글 작성자 둘(공급자가 받은 비공개 답장, 1시간 전 텍스트 DM, 명시적 마케팅 동의).
- 그 둘을 고정한 대상 하나와 그 대상을 쓰는 초안 둘(‘봄 할인 안내’, ‘가을 신상품 안내’).
- 이번 달에 시작한 이전 실행의 발송 행 999건(테스트 고정 도구 `seedCampaignSends`).
- ‘가을 신상품 안내’의 유효한 즉시 승인 하나. 데이터 준비 스크립트가 실제 `startDueCampaignRuns`를 한 번 불렀고, 후보 2명이 남은 1건을 넘어 그 실행은 발송 행 없이 `completed`로 기록됐습니다(`plan_limit_exceeded: "2"`, `plan_limit: "1000"`, `plan_limit_used: "999"`, `plan_limit_reserved: "0"`).

## 확인한 것

- 설정: 요금제 줄이 ‘요금제: 에센셜 · 멤버 2/2명(대기 중인 초대 포함) · Instagram 계정 1/2개 · 이번 달 캠페인 발송 999/1,000건’이었습니다.
- 미리보기: ‘봄 할인 안내’의 발송 조건 미리보기에서 ‘요금제 월 캠페인 발송 한도’가 ‘2026년 11월 1,000건 · 사용 999건 · 다른 승인 0건 · 남음 1건’이었고, 조건 통과는 2명이었습니다. 경고 맨 위에 ‘조건 통과 인원이 이번 달 남은 캠페인 발송 한도보다 많아 즉시 또는 이번 달 실행으로는 승인할 수 없습니다. 다음 달 실행으로 예약하거나 다른 승인을 취소해 주세요.’가 보였습니다.
- 승인 거절: 같은 초안을 즉시 실행으로 승인하자 `409`가 돌아왔고, 승인 상태 줄에 ‘2026년 11월 캠페인 발송 한도 1,000건 중 남은 1건으로는 조건 통과 2명을 승인할 수 없습니다(이번 달 사용 999건, 같은 달 다른 승인 0건). 실행 시점을 다른 달로 옮기거나 다른 승인을 취소해 주세요.’가 보였습니다. DB에 그 초안의 승인 행은 생기지 않았고, 실행 승인 버튼은 그대로 남았습니다.
- 실행 현황: ‘가을 신상품 안내’를 열자 실행 현황의 상태가 ‘시작하지 않음 · 이번 달 캠페인 발송 한도 초과’였고, ‘시작하지 않은 이유’에 ‘실행 시작 시점에 이번 달 캠페인 발송 한도 1,000건 중 999건을 이미 사용했고 같은 달 다른 승인에 0건이 예정되어 있어, 조건 통과 2명 모두에게 보내지 않았습니다.’가 보였습니다. 조건별 인원 표는 ‘조건 통과’ 0명 아래에 ‘월 발송 한도 초과’ 2명 행이 있었습니다. 발송 행 일곱 상태는 모두 0건이었고 실행 취소 버튼은 없었습니다.
- 승인 영역: 같은 초안의 승인 제목이 ‘최근 승인 · 실행을 시작하지 않음’, 상태가 ‘실행을 시작하지 않음 · 이번 달 캠페인 발송 한도 초과’였고, 승인 영역 어디에도 ‘실행 시작됨’은 없었습니다.

## 콘솔과 점검 스크립트

- 페이지 오류는 없었습니다. 4xx·5xx 응답은 의도한 승인 `409` 하나와, 임시 서버에 Meta 설정이 없어 생긴 자동화 화면의 게시물 조회(`/api/connections/:id/media`의 `503`과 그 아래 경로의 `404` 두 건)뿐이었습니다.
- 점검 스크립트의 확인 16개가 모두 통과했습니다. 문구를 고친 뒤 DB를 새로 만들어 한 번 더 실행한 결과입니다.
- 점검 스크립트가 결함을 잡는지 보려고 실행 현황이 한도 표시를 읽는 줄(`renderRun`의 `broadcast_limit_exceeded` 읽기)을 잠시 `null`로 바꾸자, 실행 현황 확인이 ‘시작하지 않음’ 문구를 기다리다 시간 초과로 실패했습니다. 파일을 복원하고 바이트 단위로 같은지 확인했습니다. 이 결함 주입은 첫 실행에서 한 번만 했고, 그 뒤 더한 표의 ‘월 발송 한도 초과’ 행, 승인 영역 상태, 바뀐 문구는 브라우저에서 결함 주입으로 확인하지 않았습니다. 이 셋은 `src/app/campaign-drafts.test.ts`가 변경 전 구현에서 실패하는 것으로 확인했습니다.
- 시각 확인용 캡처 5장(설정 페이지와 요금제 줄, 미리보기, 승인 거절, 실행 현황)은 세션 임시 디렉터리에 저장했고 저장소에는 넣지 않았습니다.

## 확인하지 않은 것

- 기한 달이 바뀌는 예약 변경의 거절 문구, 같은 버전 재승인 거절 문구, 한도 0(`free`) 요금제의 미리보기·승인·실행 문구, 요금제를 낮춘 달의 ‘캠페인 발송 불가(이번 달 N건 발송)’ 표시는 브라우저에서 보지 않았습니다. 이 문구들은 `src/app/campaign-drafts.test.ts`와 `src/app/plan-labels.test.ts`로만 확인했습니다.
- 390px 너비, 실제 키보드 조작, 스크린 리더 낭독, 다크 모드는 확인하지 않았습니다.
- 배포하지 않았으므로 운영 데이터와 실제 Instagram 계정으로 이 화면을 확인하지 않았습니다.
