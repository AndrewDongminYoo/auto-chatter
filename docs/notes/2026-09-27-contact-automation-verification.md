# 연락처 자동화 제어 검증

## 범위와 실패 증거

API 경로가 없어 404가 반환되는 실패와 기존 워커가 중지된 연락처를 선점하는 실패를 실제 로컬 DB에서 확인했습니다.
Cloudflare cron이 중지된 연락처를 큐 대상으로 선택하는 실패와 실제 화면에 제어가 없는 실패도 확인했습니다.
테스트용 Postgres는 CI와 같은 17-alpine이며 별도 `automations_test` DB만 사용합니다.
실제 Meta·운영 DB에는 접근하지 않습니다.

## 전달 계약

연락처는 작업 공간·연결·댓글 작성자 조합으로 구분합니다.
중지는 대기 상태를 보존하며 선점과 큐 알림 대상에서 제외합니다.
검증 중 중지와 마지막 Node·Cloudflare guard는 발송 전 거부로 pending을 유지하고 속도 제한 재시도를 소비하지 않습니다.
재개 후 기간 만료와 계정·규칙·토큰·쿨다운을 다시 검사하며 unknown을 재발송하지 않습니다.
최종 DB 검사와 외부 POST 사이에는 원자적 취소가 없습니다.

확인 메시지 수신 중 pause가 커밋되는 경쟁을 독립 리뷰가 발견했습니다.
루트가 실제 receipt 테이블 잠금으로 pending 전환 실패를 재현하고 UPDATE에서 현재 상태를 다시 검사한 뒤 같은 테스트의 통과를 확인했습니다.
이미 pending인 flow가 중지 중 받은 확인을 기록하지 않아 재개 이후 중복 이벤트가 다시 활성화하는 경로도 재현했습니다.
중지된 non-waiting flow에서도 본문 없이 receipt ID를 기록하되 자동화 전환을 막아 중복 이벤트를 무시합니다.

## 화면

합성 연락처와 실제 로컬 화면에서 중지·재개, 재개 취소, 실패 시 상태와 초안 보존, busy 상태의 요청 차단과 로그아웃 뒤 늦은 응답을 검사했습니다.
허용 상태는 전체 발송 스위치가 켜졌다는 의미가 아니므로 실행 중 대신 허용으로 표시합니다.
스크린샷은 중지·허용 상태가 실제 fixture에 설정된 데스크톱과 390px 화면을 사용합니다.
새 화면은 PR 병합 전에 운영자의 명시적 승인이 필요합니다.

## 검증 기록

최종 명령 결과는 아래 기준으로 기록합니다.
DB 검사는 실제 저장·격리·선점·기간·경쟁을 읽습니다.
workerd 검사는 제한된 서버 역할을 통한 API와 실제 번들·Hyperdrive·큐 전달을 읽으며 네트워크 공급자는 합성 응답입니다.
RLS·API 역할 SELECT 거부·서버 DELETE 권한 부재와 마이그레이션 재실행을 확인합니다.
독립 리뷰가 같은 로컬 DB를 사용한 결과는 최종 증거로 사용하지 않고, 루트가 전체 초기화·직렬 테스트로 재확인합니다.

- `corepack pnpm check-types`와 JavaScript 문법 검사 통과.
- `corepack pnpm test`: 101개 통과.
- 루트의 `corepack pnpm test:db`: 110개 통과.
- 루트의 `corepack pnpm test:cloudflare`: 25개 통과.
- 실제 workerd 번들에서 중지된 연락처 큐 전달은 Graph 호출 없이 pending을 유지하고, 재개 뒤 합성 공급자에게 한 번 전달합니다.
- 변경 경로에 한정한 Trunk 검사 통과.
- 독립 데이터 경계 리뷰 CLEAR, 전달 리뷰의 receipt 경쟁 수정 뒤 읽기 전용 재검토 CLEAR.
- 화면 리뷰는 기능 차단 사항 없이 취소·busy 상태 추가 검사만 권고했고, 루트가 두 경로를 실행해 통과했습니다.
