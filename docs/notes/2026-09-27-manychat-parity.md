# ManyChat 대체제 반복 구현 기준

## 반복 계약

운영자는 완료 문구 `ManyChat 대체제 구현 및 검증 완료`와 최대 10회를 지정했습니다.
한 회는 작은 기능 단위의 구현·검증·PR이며 병합은 운영자가 수행합니다.
10회 도달은 제품 완성의 증거가 아니며, 미완료 기능과 외부 승인·실계정 검증을 남기면 완료 신호를 출력하지 않습니다.
배포·과금·외부 발송은 구체적인 대상과 범위가 승인된 별도 작업입니다.

## 기준과 격차

2026-09-27 [ManyChat 가격 비교](https://manychat.com/pricing), [연락처 문서](https://help.manychat.com/hc/en-us/articles/14281110746012-Contacts-tab-Overview), [사용자 정의 필드](https://help.manychat.com/hc/en-us/articles/14281167138588-Custom-User-Fields-and-Bot-Fields), [인박스](https://help.manychat.com/hc/en-us/articles/14281070478748-Manychat-Inbox)를 확인했습니다.
기존 전체 명세의 공식 API·다중 채널·사용량 구독 목표를 유지합니다.
가격과 개별 플랜 포함량의 복제는 목표가 아닙니다.
남은 구현·외부 승인·운영 검증은 [GitHub 전체 로드맵 #11](https://github.com/AndrewDongminYoo/auto-chatter/issues/11)에서 추적합니다.
등록 기준과 문서 드리프트 수정 근거는 [백로그 기록](2026-09-27-manychat-backlog.md)에 있습니다.

각 기능은 코드 존재·자동 테스트·브라우저·실계정·운영 배포를 구분해 기록합니다.
미승인 채널이나 모의 테스트만 통과한 기능을 실제 지원으로 표시하지 않습니다.
현재 수신 인박스는 계정별 선택 보관과 승인된 수동 삭제 정책을 적용하며, 중지·재연결 후에는 보관 시작 시각을 갱신합니다.
첨부·다른 채널·자동 보관기한을 추가하기 전에는 현재 보관 정책과 개인정보처리방침을 함께 검토합니다.
완전한 대체 여부는 이 표의 남은 일과 전체 제품 명세 수용 기준으로 판단하며 PR 개수로 판단하지 않습니다.
WhatsApp·TikTok 연동 이슈 #40–#43은 `unplanned`로 보관하며 현재 제품 완료 조건에서 제외합니다.

## 6회차 선행 계약

[기능별 수용 매트릭스](2026-09-27-manychat-acceptance-matrix.md)는 등록한 작업의 현재 코드·로컬·공급자·운영 완료 상태를 구분합니다.
[DM 식별자·상담 전환 계약](../specs/2026-09-27-inbox-handoff-contract.md)의 문맥 조회는 저장된 성공 발송 근거와 현재 중지 상태를 읽습니다.
[상담 전환 쓰기 API](../specs/2026-09-27-inbox-human-handoff.md)는 버전·감사·독립 중지 사유를 저장하며 로컬 검증 범위는 [상담 전환 기록](2026-09-27-inbox-human-handoff-verification.md)에 있습니다.
수동 답장 서버 API·outbox·발신 이력·미전송 실패의 감사 재시도를 구현했습니다.
[수동 답장 계약](../specs/2026-09-27-inbox-manual-replies.md)에 제한과 운영자 결정 경로를 정리했습니다.
[수동 답장·상담 전환 화면](../specs/2026-09-28-inbox-manual-reply-ui.md)은 대화별 초안·접수 확인·안전한 재예약·재전송 없는 해결 기록을 제공합니다.
합성 브라우저와 격리 DB·workerd의 로컬 근거는 [화면 검증 기록](2026-09-28-inbox-manual-reply-ui-verification.md)에 있습니다.
운영 배포와 승인된 실발송 검증은 남아 있습니다.
