# 최근 댓글 저장 활동 조건 검증

## 결과와 범위

[#26](https://github.com/AndrewDongminYoo/auto-chatter/issues/26)의 [최근 N일 조건](../specs/2026-10-16-segment-relative-activity.md)을 로컬에서 검증했습니다.
최근 일수는 1~366이며 조회마다 한 번 정한 DB 시각 직전 N×24시간을 사용합니다.
시작을 포함하고 조회 시각을 제외하며, 실제 UTC 경계를 응답과 화면에 표시합니다.
이 기록은 운영 적용이나 #26 전체 완료를 뜻하지 않습니다.

## 자동 검사

최초 상대 기간 DB 테스트 3개가 미지원 query와 저장 필드의 400 응답으로 실패한 뒤 구현을 적용했습니다.
전체 검사 중 기존 동의 필터의 SQL 인자 위치 검증이 새 인자 추가로 실패하여 해당 위치만 수정했습니다.

| 검사                            | 읽는 대상과 확인 결과                                                                      |
| ------------------------------- | ------------------------------------------------------------------------------------------ |
| `corepack pnpm check-types`     | TypeScript 타입과 모듈 계약, 통과                                                          |
| `corepack pnpm test`            | 모의 요청·정책·API 입력 계약, 302개 통과                                                   |
| `corepack pnpm test:db`         | UTF-8 PostgreSQL의 실제 쿼리·제약·권한 계약, 647개 통과                                    |
| `corepack pnpm test:cloudflare` | 실제 workerd와 제한된 `auto_chatter_server` 역할, 78개 통과                                |
| 전체 migration 실행기           | 격리 DB에서 일수 컬럼 제거 후 `deploy/migrate-multi-user.sql` 실행, COMMIT 및 새 제약 확인 |

DB 검사는 cutoff 직전·동일 시각·종료 직전·동일 시각·미래, 최신 댓글 기준, 빈 결과, 작업 공간 격리, AND/OR와 동의 제외 순서, 50명 페이지와 전체 댓글 이력, 저장·보관·레거시 응답을 확인합니다.
정확한 마이크로초 경계 테스트는 실제 집계 SQL에서 시각 함수만 고정하며 집계 결과를 대체하지 않습니다.
별도 실제 시계 요청은 응답 시각이 요청 중에 있고 다음 요청에서 갱신되며 7×24시간 길이를 유지하는지 확인합니다.
DB 세션을 `America/New_York`로 바꾼 DST 경계 검사에서도 24시간 길이를 유지합니다.
마이그레이션 반복 적용과 366일 값 보존, DB 직접 입력 제약도 확인합니다.
Worker 검사는 상대 필터 생성·조회·다른 작업 공간 거절·댓글 경과 후 제외·보관 후 거절을 실제 제한 역할로 실행합니다.

최소 재검증 명령은 다음과 같습니다.

```bash
TEST_DATABASE_URL=postgres://postgres@127.0.0.1:65256/automations_test node --test --test-concurrency=1 --test-name-pattern='relative comment activity' src/app/settings.db.test.ts
```

위 주소는 이번 검증에서 사용한 폐기 가능한 로컬 DB 예시입니다.
다시 실행할 때는 별도로 준비한 로컬 `automations_test` 주소를 사용해야 합니다.

## 실제 브라우저

프로젝트의 실제 정적 파일과 `appApi`, 격리 PostgreSQL을 연결하고 인증만 합성한 로컬 화면을 사용했습니다.
최근 1시간·8일 전·미래 댓글 연락처를 각각 준비하여 최근 7일 미리보기에서 전체 3명, 대상 1명, 활동 기간 제외 2명을 확인했습니다.
대상 수를 잘못된 문구로 바꾸면 검증기가 예상 오류로 실패하는 음성 대조를 먼저 확인했습니다.

- 고정·상대 모드의 입력 표시와 활성 상태, 숫자 일수만 포함한 실제 저장 요청, 저장 필터 재선택을 확인했습니다.
- 0·367·소수·빈 일수는 API 요청 전에 거절되며 이전 예시가 지워집니다.
- 일수 변경·저장 필터 선택·세션 초기화는 완료된 미리보기와 지연 응답을 무효화합니다.
- 응답에 `activity_window`가 없으면 대상 예시를 표시하지 않습니다.
- 미리보기는 편집 중인 태그를 보존하고, 필터 전환 취소도 해당 초안을 보존합니다.
- 보관 후 직접 조건과 재조회에서 최근 일수를 유지합니다.
- 1440×1050 데스크톱과 폭 390 모바일 화면을 확인했고 모바일 문서 너비는 390으로 가로 넘침이 없었습니다.

브라우저 도구의 select 동작은 합성 change 이벤트만 발생시켜, 모드 전환 검사에서는 브라우저 input 이벤트도 명시적으로 발생시켰습니다.
실제 화면과 API·DB를 검사했지만 실제 사용자 인증, 운영 데이터, Meta 요청은 검사하지 않았습니다.
화면 승인 자료는 저장소 밖의 보존 디렉터리 `../pr-loop-reviews/auto-chatter/segment-relative-activity-20261016/`에 둡니다.
운영자의 시각적 승인은 별도로 필요합니다.

## 검토와 적용 조건

독립 API·DB 검토와 UI·문서 검토, 루트의 호출 경로·화면 대조를 수행했습니다.
초기 검토의 무효화 누락 주장은 `fieldFilterControls()`를 통한 기존 호출을 확인해 해소했고, 제한 역할 검사 누락 주장도 실제 runtime 테스트를 확인해 해소했습니다.
확인된 코드 결함은 없습니다.
README·CLAUDE·기존 세그먼트/연락처/고정 활동 명세와 수용표의 관련 계약을 함께 갱신했습니다.
AGENTS는 CLAUDE를 단일 명령·검증 기준으로 지정하는 기존 안내가 그대로 유효합니다.

기존 DB는 코드 배포 전에 migration 053을 전체 실행기로 적용해야 합니다.
운영 DB·배포·실제 발송·운영 규모 성능은 검증하지 않았습니다.
Oracle의 해당 프로젝트 상대 기간 검색은 `[no precedent found]`였으며, 선례 부재를 일반 규칙의 부재로 해석하지 않았습니다.
