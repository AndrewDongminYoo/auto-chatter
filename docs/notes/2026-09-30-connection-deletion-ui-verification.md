# 연결 데이터 삭제 화면 검증

## 대상과 경계

GitHub #81의 [화면 계약](../specs/2026-09-30-connection-deletion-ui.md)을 기존 [연결 단위 삭제 계약](../specs/2026-09-29-connection-data-deletion.md) 위에서 확인했습니다.
실제 `public/app` 파일을 제공하고 `/api/*`를 합성 응답으로 대신하는 로컬 서버를 사용했습니다.
운영 DB·Meta API·실제 삭제는 호출하지 않았으며, 서버 API와 DB 함수는 이번 변경에 포함되지 않습니다.

## 자동 검사

`corepack pnpm check-types`와 `corepack pnpm test`(138건)가 통과했습니다.
공개 페이지 테스트는 `/privacy`, `/data-deletion`, `/service`의 앱 내 삭제 경로 문장을 확인합니다.
문구 변경을 되돌린 상태에서는 이 검사 3건이 실패하는 것을 확인했습니다.
서버 파일을 바꾸지 않았고 로컬 부하가 높아 `test:db`와 `test:cloudflare`는 실행하지 않았습니다.

## 브라우저 검사

agent-browser의 이름을 지정한 세션에서 합성 연결 4개를 사용했습니다.

- 토큰이 없고 수신·발송이 꺼진 연결에만 "데이터 삭제"가 표시됐습니다. 만료된 토큰이 남은 연결, 유효한 토큰으로 수신만 중지한 연결, 활성 연결에는 "삭제 기록"만 표시됐습니다.
- 키보드만으로 "데이터 삭제"를 Enter로 열고, Tab으로 입력에 이동해 Enter로 제출했습니다. 입력에서 Tab을 누르면 "기록 삭제" 버튼, 그다음 "삭제 기록"으로 이동했습니다.
- 다른 계정 ID는 `confirmation_mismatch`, 공백만 입력한 값은 `invalid_data_deletion`, 서버 상태를 바꾼 두 경우는 `connection_active`와 `sending_in_progress` 안내를 양식 안에 표시했습니다. 오류 뒤 입력에 `aria-invalid="true"`와 초점이 있었습니다.
- 뒤에 공백을 붙인 계정 ID는 공백을 제거한 값으로 전송됐습니다.
- 성공하면 입력을 비우고 양식을 닫은 뒤 삭제 건수를 알렸고, 삭제 기록에 새 기록이 "내 요청"으로 먼저 표시됐습니다. 이용자 단위 기록은 요청자 없이 "이용자 단위 삭제(운영자 처리)"로, 다른 사용자의 기록은 "다른 관리자 요청"으로, 0건 기록은 "삭제할 기록이 없었습니다."로 표시됐습니다.
- 키보드로 성공 흐름을 실행하자 처음에는 닫힌 양식 때문에 초점이 `body`로 떨어졌습니다. 초점을 "삭제 기록" 요약으로 옮기도록 수정한 뒤 같은 흐름에서 초점이 그 요약에 있는 것을 확인했습니다.
- PR #88의 Codex 리뷰(P2)에 따라, 삭제한 연결의 연락처·인박스 대화·처리 내역을 불러오고 태그 변경과 인박스 초안을 남긴 상태에서 삭제했습니다. 수정 전에는 연락처 카드 1개, 처리 내역, 인박스 대화와 초안이 그대로 남았고, 수정 후에는 모두 사라지고 저장하지 않은 변경과 초안이 0이 됐으며 초점은 "삭제 기록"에 있었습니다.
- 같은 PR의 두 번째 Codex 리뷰(P2)에 따라, 삭제 전에 시작한 처리 내역 요청을 헤더만 먼저 보내고 본문을 7초 늦게 보내도록 만든 상태에서 삭제했습니다. 요청 순서 검사가 없으면 삭제 후 비워진 처리 내역을 늦은 응답이 삭제 전 항목으로 덮었고, 검사를 추가한 뒤에는 늦은 응답을 무시했습니다. 헤더까지 늦추면 Chrome이 같은 URL의 두 번째 요청을 첫 응답의 헤더가 올 때까지 보내지 않아 경합이 재현되지 않았습니다.
- 세 번째 Codex 리뷰(P2)에 따라, 다른 연결의 연락처 카드에 저장하지 않은 태그 변경이 있는 상태에서 삭제 전에 시작한 "더 보기" 요청의 본문을 7초 늦게 보냈습니다. 수정 전에는 늦은 페이지가 삭제한 연결의 연락처를 목록에 다시 추가했고, 수정 후에는 그 연락처를 제외했으며 다른 연결의 변경은 유지됐습니다.
- 390px 화면에서 문서 너비는 390px였고, 요약과 버튼의 높이는 44px, 입력 너비는 350px였습니다. 라이트·다크 모드의 오류 화면을 시각 검토했습니다.
- 첫 캡처에서 삭제 버튼이 남색 배경에 빨간 글자로 표시되어 대비가 낮았습니다. 기존 "연결 해제"와 같은 `secondary danger`로 바꾼 뒤 다시 캡처했습니다.
- 기록을 여는 요청이 끝나기 전에 세션을 재설정하면 늦은 응답이 기록을 쓰지 않았고, 재설정하지 않은 대조 실행에서는 기록 3건이 표시됐습니다.

## 남은 검증

운영 배포 후 해제한 실제 연결에서 삭제와 기록 표시를 확인하는 작업은 별도 승인 대상입니다.
합성 API 결과로 운영 DB 함수의 권한과 동작을 주장하지 않습니다.
