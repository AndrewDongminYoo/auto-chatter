# 연락처 검증 기록

## 자동 검사

연락처 API 경로 부재로 HTTP 404 대신 200을 요구한 회귀가 실패했습니다.
DB 테스트에서도 댓글 참여자 목록이 비어 있고 태그 수정이 404로 거부되는 실패를 관찰한 뒤 구현했습니다.
추가 회귀는 계정·작업 공간 격리, 빈 태그·초과 길이 거부, 태그 제거, 필터, 51명 페이지와 마이그레이션 재실행을 검사합니다.
타입 검사, 단위 96개, DB 89개와 workerd 22개가 통과했습니다.
workerd 검사는 제한된 서버 역할로 연락처를 읽고 태그를 수정하며 다른 작업 공간의 수정이 404인 것을 실제 로컬 DB에서 확인합니다.
새 테이블의 RLS 활성화와 서버 역할의 DELETE 권한 부재도 확인합니다.

## 브라우저

운영 CSP를 적용한 로컬 정적 자산과 합성 계정·연락처 응답으로 실제 UI를 실행했습니다.
연락처 fixture가 없는 상태에서 두 연락처를 요구하는 검사가 실패한 뒤 fixture를 적용해 통과했습니다.
태그 저장 성공, HTTP 503 뒤 입력 보존, 태그 필터, 빈 목록, 390px 화면의 동일 document 폭과 로그아웃 뒤 늦은 목록 응답 무시를 확인했습니다.
화면은 실제 Instagram 이름·프로필 조회를 입증하지 않으며 현재 저장된 참여자 ID를 표시합니다.

## 운영 경계

이 PR은 migration 008 적용·배포·실계정 태그 변경·발송을 수행하지 않습니다.
연락처와 태그 보관은 기존 승인된 수동 삭제 정책을 따릅니다.
프로젝트 전용 Oracle 선례는 `[no precedent found]`였고 현재 Wiki freshness는 확인되지 않았습니다.

## 적대적 리뷰 보완

화면 리뷰가 발견한 태그 전용 beforeunload 경고 누락은 실제 입력으로 dirty 상태를 만든 cancelable 이벤트 검사에서 실패한 뒤 수정했습니다.
수정 후 태그만 변경하면 unload가 취소되고 원래 값으로 돌리면 취소되지 않습니다.
서버 리뷰가 발견한 문자열 sender ID 수정·페이지 불일치는 기존 수집기가 허용한 식별자를 숫자로 제한한 문제였습니다.
문자열 페이지 경계와 URL에 인코딩된 슬래시·퍼센트·공백을 회귀로 검증해 실패 후 수정했습니다.
workerd의 실제 서버 역할 API 검사에도 문자열 식별자를 사용합니다.

## 호스팅 리뷰 보완

PR #6의 연락처 조회 인덱스 누락 지적을 확인했습니다.
스키마와 migration 008에 workspace·connection·sender 순서의 인덱스를 추가하고 created_at을 포함합니다.
마이그레이션으로 인덱스가 생성되는 검사와 PostgreSQL 실행 계획에서 해당 인덱스를 사용할 수 있는 검사가 실패한 뒤 통과했습니다.
업그레이드 검사는 인덱스를 제거한 뒤 마이그레이션을 두 번 적용합니다.
실행 계획 검사는 enable_seqscan을 끈 조건에서 검색 인덱스의 사용 가능성을 확인하며 운영 지연 시간이나 대량 집계 성능을 보장하지 않습니다.
목록은 여전히 댓글 집계를 수행하며 대량 데이터의 운영 측정은 남아 있습니다.
