# 필터 초안의 전체 대상 수 검증

## 범위와 결과

[#26](https://github.com/AndrewDongminYoo/auto-chatter/issues/26)의 [초안 미리보기](../specs/2026-10-16-segment-draft-preview.md)에 조회 시점의 정확한 대상 수를 추가했습니다.
`GET /api/contacts?preview=true`는 기존 조건·권한 검증을 거쳐 연락처 그룹의 수를 `total` 10진수 문자열로 반환합니다.
같은 SQL 문장에서 최대 50명 샘플을 읽고 화면에는 최대 5명을 표시합니다.
일반 목록에는 집계나 `total`을 추가하지 않으며 미리보기의 모든 `after` 값은 거절합니다.
저장된 데이터의 조회 결과이므로 편집 중인 값·발송 가능 여부·고정 대상은 뜻하지 않습니다.

## 자동 검사

- `corepack pnpm check-types`: TypeScript 타입 검사 통과.
- `corepack pnpm test`: HTTP 계약·검증 등 단위 테스트 293개 통과.
- `TEST_DATABASE_URL=<격리된 로컬 UTF-8 automations_test> corepack pnpm test:db`: 실제 PostgreSQL 상태·질의 결과를 읽는 테스트 598개 통과.
- 같은 DB의 `corepack pnpm test:cloudflare`: 번들 생성과 권한이 제한된 서버 역할을 포함한 Worker 런타임 검사 75개 통과.

새 API·DB 회귀 검사는 구현 전 유효한 `preview=true`가 400을 반환해 실패했습니다.
구현 후 0·1·50·51·55명, 반복 댓글의 중복 제거, 같은 sender의 계정별 구분, 태그·숫자 필드 AND/OR, 다른 작업 공간·계정·필드·세그먼트 차단을 확인했습니다.
저장된 조건은 다시 조회한 데이터 변경을 반영하며 보관된 세그먼트는 404입니다.
단위 검사는 큰 값 `9007199254740993`의 문자열 보존, 내부 집계 필드 제거, 일반 응답 형태, 잘못된 플래그·커서·인증 실패도 확인합니다.
Worker 검사에서는 실제 응답의 `total: "1"`, 다른 작업 공간의 `"0"`, 일반 목록의 기존 형태와 빈 커서 거절을 확인했습니다.

첫 전체 DB 실행은 임시 클러스터의 `SQL_ASCII` 설정 때문에 한글 길이 경계 검사 4개가 실패했습니다.
소유한 임시 DB만 `template0`의 UTF-8 DB로 다시 만든 뒤 전체 598개를 통과했으며 제품 코드를 수정해 우회하지 않았습니다.

## 브라우저 검사

실제 `public/app/`를 로컬 HTTP 서버와 격리된 Chromium 세션에서 실행하고, 합성 API 응답으로 15개 시나리오 묶음을 확인했습니다.
이는 화면 동작의 증거이며 실계정이나 운영 API 연결 검증은 아닙니다.
기존 화면은 55명 전체 수 검사에서 실패했고, 구현 후 통과했습니다.
검사 fixture를 지우면 `Missing preview fixture; no UI evidence is valid`로 실패함도 확인했습니다.

- 55명 전체 수·최대 5명 예시, 0명, 큰 정수 문자열을 정확히 표시합니다.
- `total` 누락·숫자형·음수·소수·빈 문자열·선행 0은 이전 결과를 지우고 재시도를 안내합니다.
- 적용된 목록·카드 객체·편집 중인 태그·페이지 커서·dirty 상태를 유지합니다.
- 현재 초안의 계정·숫자 0·boolean false·OR 조건을 사용하며 `segment_id`와 `after`를 보내지 않습니다.
- 오류 뒤 재시도, 중복 클릭, 조건 변경 뒤 늦은 성공·실패·종료 처리를 확인했습니다.
- 계정·필드 갱신, 기록 삭제와 로그아웃은 결과를 무효화합니다.
- 참여자와 계정의 HTML 문자열은 텍스트로 표시하며 미리보기 요청은 `preview=true`의 GET뿐입니다.

1280×1000과 390×844 화면에서 전체 수·예시·오류 안내를 직접 확인했고 가로 넘침이 없었습니다.
Enter로 실행한 뒤 미리보기 버튼의 포커스가 유지됐습니다.
병합 전 운영자의 화면 승인은 별도로 필요합니다.

## 로컬 질의 비용

PostgreSQL 17.11의 격리된 UTF-8 DB에 연결 계정 1개, 연락처 10,000명, 각 3개씩 댓글 30,000개와 `lead` 태그를 가진 연락처 1,000명을 만들었습니다.
댓글·태그 테이블에 `ANALYZE`를 실행한 뒤 실제 `listContacts`가 전달한 SQL과 바인딩 값을 캡처해 `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`으로 각 조합을 한 번 측정했습니다.
모두 메모리 캐시 적중이었으며 디스크 읽기는 0이었습니다.

| 조건        | 모드     | 반환 샘플 | 전체 수       | 실행 시간 | shared hit blocks |
| ----------- | -------- | --------- | ------------- | --------- | ----------------- |
| 없음        | 일반     | 50        | 반환하지 않음 | 0.185 ms  | 115               |
| 없음        | 미리보기 | 50        | 10,000        | 14.714 ms | 518               |
| 태그 `lead` | 일반     | 50        | 반환하지 않음 | 0.148 ms  | 115               |
| 태그 `lead` | 미리보기 | 50        | 1,000         | 4.051 ms  | 518               |

일반 목록은 그룹 51개에서 멈췄고 미리보기는 각각 10,000·1,000개 그룹을 처리했습니다.
따라서 정확한 수 계산 비용은 페이지 크기로 제한되지 않습니다.
이 합성 표본은 운영 규모·경합·최악의 필터·네트워크 지연을 재현하지 않으며 운영 성능 보증으로 사용하지 않습니다.
집계는 사용자가 명시적으로 요청한 미리보기에서만 실행합니다.

## 문서와 남은 범위

연락처·세그먼트·초안 미리보기 명세와 수용 매트릭스의 전체 수 관련 주장을 갱신했습니다.
`CLAUDE.md`에 조회 불변 조건을 추가했으며 `README.md`의 일반 연락처 설명과 `AGENTS.md`의 지침 위임은 여전히 맞아 그대로 유지했습니다.
이전 미리보기·병합 검증 기록은 당시 커밋의 이력으로 보존합니다.
Oracle의 프로젝트 관련 선례는 `[no precedent found]`입니다.
제외 사유·동의/활동 조건·캠페인 대상 고정, #26 전체 완료, 운영 DB·배포·실계정 검증은 포함하지 않습니다.
