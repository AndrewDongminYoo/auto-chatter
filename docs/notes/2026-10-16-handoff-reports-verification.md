# 상담 전환 이력 검증 기록

## 범위

[#50](https://github.com/AndrewDongminYoo/auto-chatter/issues/50)의 상담 전환 이벤트 리포트 단계입니다.
[명세](../specs/2026-10-16-handoff-reports.md)에 따라 보존된 시작·해제 기록과 계정별 고유 대화를 집계합니다.
현재 상담 상태·성공 전환·플로 인과성을 추정하지 않으며 #50 전체 완료는 아닙니다.

## 로컬 검증

- `corepack pnpm check-types`: TypeScript 타입 검사 통과.
- `corepack pnpm test`: 단위 테스트 302개 통과.
- UTF-8 격리 PostgreSQL의 `corepack pnpm test:db`: 실제 SQL·제약·권한·경계 통합 테스트 643개 통과.
- 같은 DB의 `corepack pnpm test:cloudflare`: 번들과 로컬 workerd·Hyperdrive·Queue 테스트 78개 통과.
- 새 API 테스트 5개는 라우트 구현 전 404로 실패했고 구현 후 반복 전환·멱등 재요청·계정별 대화 구분·현재 상태와의 독립성·삭제·권한·필터·DST·빈 결과·마이크로초 경계를 통과했습니다.
- 기간 인덱스가 없을 때 실제 집계 SQL의 실행 계획 검사가 실패했습니다.
  추가 후 기간 밖 12,000건과 기간 안 1건에서 계정 필터 유무 모두 workspace와 날짜 조건으로 인덱스 범위를 제한하고 대상 1건을 읽었습니다.
  같은 기간의 많은 계정 중 선택한 계정만 읽는 성능은 증명하지 않습니다.
- 새 인덱스를 제거한 뒤 전체 `deploy/migrate-multi-user.sql` 실행기의 COMMIT과 `(workspace_id,created_at,connection_id)` 인덱스 재생성을 확인했습니다.
- `corepack pnpm install --frozen-lockfile`로 기존 lockfile 일치를 확인했고 의존성 변경은 없습니다.
- 처음 만든 임시 DB가 SQL_ASCII여서 기존 한글·이모지 테스트 5개가 실패했습니다.
  서버 로그의 인코딩 오류를 확인하고 UTF-8 DB로 다시 만든 뒤 전체 테스트를 통과했습니다.

## 실제 브라우저

격리 Chromium에서 제품 정적 파일·실제 `appApi`·로컬 PostgreSQL을 사용했습니다.
Supabase 인증 응답만 합성 사용자로 대체했고 실제 Meta 호출은 없었습니다.

- 두 계정의 이벤트 4건에서 변경 4, 시작 2, 해제 2, 고유 대화 2를 렌더링했습니다.
- 화면 숫자 하나를 임시로 99로 바꾸자 대조 검사가 실패했고 원래 값에서 통과했습니다.
- CSV의 집계 네 행을 화면과 대조하고 UTF-8 BOM·CRLF 및 계정 이름·고객 데이터 제외를 확인했습니다.
- 계정 변경은 결과를 지웠고 첫 계정 조회에서 3·2·1·1을 표시했습니다.
- 응답을 지연한 뒤 날짜 변경 또는 실제 앱 세션 초기화를 실행하면 늦은 응답이 결과·CSV를 복원하지 않았습니다.
- 저장된 시간대를 바꾸면 충돌 응답으로 결과를 지우고 새로고침 안내를 표시했습니다.
- 상담원으로 다시 불러오면 리포트를 숨겼고 직접 API 호출은 403이었습니다.
- 데스크톱 1440px과 모바일 390px에서 실제 화면을 확인했고 모바일 가로 넘침이 없었습니다.

날짜는 DOM 입력 요소에 지정한 뒤 실제 input 이벤트와 폼 제출을 실행했습니다.
캡처는 저장소 밖의 보존용 검토 디렉터리에 있습니다.

## 검토와 한계

독립 API·UI 검토에서 정확성·권한·집계·화면 동작의 차단 사항은 없었습니다.
API 검토의 낮은 우선순위 지적에 따라 기간 인덱스는 계정별 선택성까지 보장하지 않는다는 한계를 기록했습니다.
현재 계약은 기간 범위 제한이며 운영 측정 없이 추가 인덱스를 만들지 않았습니다.

이 결과는 운영 DB 적용·실제 Supabase 인증·배포된 Worker·Meta 발송이나 운영 규모 성능을 증명하지 않습니다.
배포 전에 migration 052를 전체 실행기로 적용해야 하며 운영 조회·백업·적용과 배포는 별도 승인 범위입니다.
화면 캡처의 운영자 시각 승인은 아직 받지 않았습니다.
