# 운영 상태 화면 검증

## 대상과 경계

GitHub #59의 [운영 상태](../specs/2026-10-01-operations-health.md#화면) 영역을 확인했습니다.
실제 `public/app` 파일과 실제 `appApi`를 로컬 PostgreSQL의 일회용 DB(`automations_ui`, 확인 뒤 삭제)에 연결한 임시 로컬 서버를 사용했습니다.
Supabase는 세션 쿠키 값으로 `/user` 응답을 돌려주는 대역으로 바꿨고, 로그인은 이 대역 서버가 쿠키를 직접 설정하는 방식으로 대신했습니다. 운영 DB·Supabase·Meta·Cloudflare는 호출하지 않았습니다.
합성 데이터는 연결 하나(`ui_shop`, 토큰 만료 5일 뒤, 발송 제한 일시 중지 40분), `unknown`·`failed`·12분 전에 claim한 `sending` 답장 각 1건, 7분 전의 마지막 `cron` 성공입니다.
화면 동작은 Chrome에서 확인했습니다.

## 브라우저 검사

- 소유자로 들어가면 작업 공간 설정 아래에 "운영 상태" 영역이 보였습니다. 요약에 확인 시각과 마지막 정기 작업 성공 시각이 표시됐고, 서비스 경보 배지 "정기 작업이 5분 넘게 성공하지 않음"이 따로 한 줄에 보였습니다.
- 연결 `ui_shop`에는 "발송 처리 10분 초과", "결과 미확인 발송 있음", "토큰 만료 7일 이내" 배지와 "가장 오래 기다린 발송: 없음 · 가장 오래 처리 중인 발송: 12분", "최근 24시간: 결과 미확인 1건 · 실패 1건 · 차단 0건", "토큰 만료까지 4일 · 발송 제한으로 …까지 일시 중지"가 표시됐습니다. 남은 기간은 내림이므로 5일 미만은 4일로 보입니다.
- 일시 중지 중인 연결의 대기 답장은 큐 지연으로 세지 않으므로 "가장 오래 기다린 발송"은 "없음"이었습니다.
- "다시 확인"을 누르면 버튼이 "확인 중…"으로 바뀐 뒤 돌아왔고, 요약의 확인 시각이 새 값으로 바뀌었습니다.
- 화면 텍스트에 댓글·답장 본문, 토큰 암호문, 이메일, 댓글 작성자 ID는 나오지 않았습니다.
- 상담원으로 들어가면 작업 공간 화면은 보였고 운영 상태 영역은 숨겨졌으며, 페이지는 `/api/workspace/health`를 요청하지 않았습니다. 같은 화면에서 직접 보낸 요청은 `403 role_forbidden`이었습니다.
- 390px 너비의 같은 출처 iframe에서 문서 너비는 386px로 넘치지 않았고, 운영 상태 영역 안에 화면 밖으로 나간 요소가 없었습니다. 라이트 모드만 확인했고 다크 모드는 확인하지 않았습니다.
- 첫 확인에서 서비스 경보 배지가 요약 문장 바로 뒤에 붙어 보여, 배지를 별도 줄로 옮긴 뒤 다시 확인했습니다.

## 남은 검증

migration 030을 운영 DB에 적용하지 않았고 배포하지 않았으므로, 운영 데이터로 이 화면을 확인하지 않았습니다.
