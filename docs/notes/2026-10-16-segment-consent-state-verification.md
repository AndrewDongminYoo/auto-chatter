# 목적별 동의 기록 필터 검증

## 범위와 결과

[#26](https://github.com/AndrewDongminYoo/auto-chatter/issues/26)의 [목적별 동의 기록 계약](../specs/2026-10-16-segment-consent-state.md)을 일반 목록·저장된 필터·초안 미리보기에 적용했습니다.
현재 작업 공간·연결·Instagram·댓글 식별자·목적에 해당하는 `channel_consent_state`의 허용·철회·행 없음만 비교합니다.
DM 식별자, 동의 근거의 유효성과 발송 가능 여부를 판단하지 않습니다.
미리보기는 기간, 동의 기록, 태그·필드 순서로 중복 없이 제외합니다.
기존 DB는 전체 실행기로 migration 047을 적용한 뒤 새 코드를 사용해야 합니다.
운영 적용·배포·실계정·실발송과 #26 전체 완료는 확인하지 않았습니다.

구현 전 API·DB 검사는 유효한 동의 조건이 400을 반환하는 실패를 확인했습니다.
브라우저는 동의 입력 부재로 실패하는 것을 확인했고, 검증 fixture를 제거하면 `Missing consent fixture`로 실패하는 것도 확인했습니다.
브라우저의 합성 HTTP 응답은 실제 서버 연결 증거가 아니며 DB와 workerd 검사가 서버 계약을 별도로 검사합니다.

DB 검사는 두 목적·세 상태, marketing import 근거의 grant, 다른 작업 공간·연결의 동일 sender, 숫자가 같은 DM 식별자를 구분합니다.
기간·동의·태그/필드 AND·OR의 제외 합계, 0명, 55명의 50+5 페이지와 반복 댓글의 전체 수를 확인했습니다.
저장 필터를 재조회할 때 `all` 철회와 재동의를 반영하고, 과거 `occurred_at`을 가진 새 원장 기록도 현재 투영 결과대로 읽는지 검사했습니다.
조회 전후 원장 행 수가 같고 기존 세그먼트 응답은 새 키를 생략합니다.
마이그레이션은 기존 행의 null 유지·반복 적용·저장 조건 보존·부분/빈/잘못된 enum의 CHECK 거부를 검사했습니다.
workerd는 제한된 역할로 목적·상태를 저장·조회·보관하고 grant/revoke 전환 및 다른 작업 공간 거부를 확인했습니다.

브라우저는 목적만 선택한 불완전 입력의 요청 차단, 목적 삭제 시 상태 초기화, 허용·철회·기록 없음, 활동 기간과 태그 결합을 검사했습니다.
누락·잘못된 정수·합계 불일치·서버 오류는 결과를 지우고 재시도할 수 있습니다.
편집 중인 연락처, 저장 실패 후 조건, 저장·복원·보관 후 수동 조회 조건과 로그아웃 초기화를 확인했습니다.
리뷰의 저장 필터 선택 관련 지적은 지연 응답으로 재현되지 않았습니다.
기존 `fieldFilterControls()`가 미리보기를 무효화하는 것을 확인했고, 별도 검사로 선택 후 늦은 응답 폐기·새 필터 미리보기·직접 조건 전환 후 결과 초기화를 확인했습니다.
중복 코드는 추가하지 않았습니다.
데스크톱 1280×1000과 모바일 390×844에서 입력·정상·0명·오류 화면을 확인했으며 모바일 문서 너비는 390px였습니다.
키보드 Enter로 미리보기를 실행하고 포커스 표시를 확인했습니다.
화면 자료와 운영자 승인 기록은 체크아웃 밖의 `../pr-loop-reviews/auto-chatter/segment-consent-state-20261016/`에 보존합니다.

## 실제 쿼리의 로컬 비용

로컬 PostgreSQL 17의 UTF-8 격리 DB에 연락처 10,000명, 각 3개의 댓글 총 30,000개, 동의 상태 6,667개를 넣었습니다.
계정·작업 공간은 하나이며 댓글·태그·숫자 필드 분포는 [활동 기간 측정](2026-10-16-segment-comment-activity-verification.md#실제-쿼리의-로컬-비용)과 같습니다.
연락처 번호를 3으로 나눈 나머지가 0이면 marketing grant, 1이면 revoke, 2이면 상태 행이 없습니다.
관련 테이블을 ANALYZE한 뒤 실제 `listContacts`가 실행한 SQL과 바인딩을 포착해 19개 조건의 `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`을 한 번씩 실행했습니다.
모든 미리보기는 평가 10,000명과 일치·제외 합계를 검증했고 Shared Read Blocks는 0이었습니다.

동의 상태의 기존 복합 기본 키를 사용하며 새 인덱스는 추가하지 않았습니다.
기간과 결합하면 집계 대상에 대한 반복 조회로 읽는 블록 수가 늘어납니다.
샘플 크기 50명으로 전체 분류 비용이 제한되지 않으며 작은 합성 데이터의 단일 측정은 운영 규모·차가운 캐시·동시 요청의 지연 시간을 보증하지 않습니다.

## 문서와 선례

CLAUDE의 연락처·세그먼트 계약, 기존 연락처·세그먼트·활동·초안 미리보기 명세와 수용 매트릭스를 같은 변경에서 맞췄습니다.
README의 일반 기능·전체 마이그레이션 안내와 AGENTS의 CLAUDE 위임은 현재 계약과 맞아 유지했습니다.
백엔드와 UI의 독립 리뷰에서 남은 차단 항목은 없습니다.
관련 Oracle 선례는 `[no precedent found]`이며 프로젝트·개인 계정 범위에서 `consent filter`, `comment_sender`로 조회했습니다.
Wiki freshness는 검증하지 않았으므로 선례 부재를 정책 승인으로 해석하지 않습니다.
