# 인박스 수동 답장 화면 검증

## 대상과 경계

GitHub #19의 [화면 계약](../specs/2026-09-28-inbox-manual-reply-ui.md)을 기존 #18 서버 계약 위에서 확인했습니다.
격리된 로컬 PostgreSQL과 workerd, 실제 공개 정적 파일을 제공하는 합성 API 브라우저를 사용했습니다.
운영 DB·Meta API·실제 DM 발송은 호출하지 않았습니다.
화면 승인·PR의 현재 head 검사·운영 배포와 실계정 왕복은 별도 게이트입니다.

## 서버 검사

`corepack pnpm check-types`와 `corepack pnpm test`가 통과했으며 단위 테스트는 103건입니다.
`TEST_DATABASE_URL=<disposable-local-db> corepack pnpm test:db`의 156건은 소유권·정책·감사·멱등성 계약을 검사했습니다.
`TEST_DATABASE_URL=<disposable-local-db> corepack pnpm test:cloudflare`의 34건은 workerd와 제한된 서버 DB 역할에서 동일 계약을 검사했습니다.
새 status GET은 다른 작업 공간의 대화를 404로 거부하고, 서버 발송 중지·상담 변경·24시간 창 종료·미해결 unknown을 표시하며 토큰 원문을 반환하지 않았습니다.
이 조회를 추가해도 실제 예약·발송의 버전·권한 검사는 유지됩니다.

## 브라우저 검사

이름을 지정한 agent-browser 세션에서 실제 `public/app` 파일과 합성 계정·수신·발신 데이터를 사용했습니다.
작성기가 없는 상태에서 검사가 실패했고, 합성 fixture를 제거했을 때도 `Synthetic fixture unavailable`로 실패했습니다.

- 대화별 초안, 두 번 제출한 요청 한 건, 다른 대화에 도착한 늦은 발송 응답을 검사했습니다.
- 접수 응답 유실 뒤 같은 UUID와 문구·상담 버전으로 확인하며 행이 중복되지 않음을 검사했습니다.
- 대화 전환 뒤의 늦은 읽기와 로그아웃 뒤의 읽기가 현재 화면을 바꾸지 않음을 검사했습니다.
- 상담 시작, unknown의 재전송 차단·해결 감사, 확실한 미발송 실패의 연결된 재예약을 검사했습니다.
- HTML 형태의 메시지는 문자로 표시되고 실행되지 않았습니다.
- 수신·발신의 별도 이전 페이지를 함께 병합하며 초안을 유지하고 마지막 페이지에서 버튼을 숨기는지 검사했습니다.
- 접수가 불명확한 해결 사유·확인 체크를 잠그고, 최신 결과에서 실행할 수 없는 사유 초안은 제거합니다.
  두 수정을 각각 제거한 상태에서 대응 검사가 실패하는 것을 확인한 뒤 복원해 통과했습니다.
- 실제 키보드 Enter는 줄바꿈, Ctrl+Enter는 답장 예약 한 건으로 처리됐습니다.
- 390px 화면의 문서 너비는 390px로 가로 넘침이 없었으며, 사유 입력에서 Tab으로 확인 체크와 처리 버튼에 순서대로 이동했습니다.
- 확인 체크는 기존 toggle 스타일의 18px 입력과 44px 클릭 가능한 label을 사용합니다.
  잘못된 크기의 입력에서 검사 실패를 확인한 뒤 수정해 통과했습니다.

## 독립 검토

서버 권한·발송 판정과 UI 세션·응답 경합을 별도 읽기 전용 로컬 리뷰로 검사했습니다.
두 검토에서 차단 사항은 없었으며 UI의 사유 잠금·숨은 초안 경고 두 가지는 수정 후 회귀 검사를 통과했습니다.
Oracle 전용 실행기는 조회 전 실패했으므로 선례 결과는 `[TOOL_FAILED]`로 남깁니다.

## 남은 운영 검증

#13의 운영 마이그레이션·배포 후 승인된 계정에서 저장 DM, 상담 전환, 수동 답장 도착, 제한 거부와 해결 기록을 확인해야 합니다.
로컬 합성 결과로 실제 Meta 권한·메시지 도착·추가 사용자 지원을 주장하지 않습니다.
