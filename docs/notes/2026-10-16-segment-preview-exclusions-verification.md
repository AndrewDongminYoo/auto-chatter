# 필터 제외 사유 미리보기 검증

## 범위와 결과

[#26](https://github.com/AndrewDongminYoo/auto-chatter/issues/26)의 [초안 미리보기](../specs/2026-10-16-segment-draft-preview.md)에 태그·단일 필드 조건의 제외 사유를 추가했습니다.
`GET /api/contacts?preview=true`는 같은 SQL 문장에서 평가 범위 `evaluated`, 일치 수 `total`, 상호 배타적인 `excluded.tag`·`field`·`both`와 제한된 샘플을 읽습니다.
모든 수는 10진수 문자열이며 `evaluated = total + tag + field + both`입니다.
작업 공간과 선택 계정을 먼저 제한하고, AND는 세 가지 불일치를 구분하며 OR는 두 조건이 모두 불일치한 연락처만 제외합니다.
없는 조건은 만족한 것으로 취급하고 일치 대상이 0명이어도 요약은 반환합니다.
일반 목록과 미리보기의 커서 거절 계약은 유지합니다.

## 자동 검사

- `corepack pnpm check-types`: TypeScript 타입 검사 통과.
- `corepack pnpm test`: HTTP 계약·입력 검증 등 단위 테스트 293개 통과.
- `TEST_DATABASE_URL=<격리된 로컬 UTF-8 automations_test> corepack pnpm test:db`: 실제 PostgreSQL 상태·질의 결과를 읽는 테스트 598개 통과.
- 같은 DB의 `corepack pnpm test:cloudflare`: 번들 생성과 제한된 서버 역할을 사용하는 Worker 런타임 검사 75개 통과.

API·DB 회귀 검사는 구현 전 `evaluated`와 `excluded`가 없어 실패했고 구현 후 통과했습니다.
0·1·50·51·55명, 반복 댓글의 중복 제거, 같은 sender의 계정별 구분, 다른 작업 공간·계정 차단을 확인했습니다.
태그만·필드만·조건 없음·AND/OR·일치 대상 0명의 집계와 저장된 세그먼트의 최신 태그 변경 반영을 확인했습니다.
API 검사는 `9007199254740993` 이상의 정수 문자열 보존과 내부 집계 필드 제거도 확인합니다.
workerd 검사는 일치 1명, 태그로 제외된 1명, 다른 작업 공간의 빈 평가 범위를 실제 HTTP 응답으로 확인합니다.

## 브라우저 검사

실제 `public/app/`를 로컬 HTTP 서버와 격리된 Chromium 세션에서 실행하고 합성 API 응답으로 17개 시나리오 묶음을 확인했습니다.
이는 화면 동작의 증거이며 실계정·운영 API 연결 검증은 아닙니다.
구현 전 화면은 제외 사유 영역이 없어 실패했습니다.
검사 fixture를 지우면 `Missing preview fixture; no UI evidence is valid`로 실패하고, 복원하면 전체 검사가 통과했습니다.

- AND의 세 가지 제외 사유와 OR의 양쪽 불일치만 표시합니다.
- 일치 대상이 0명이어도 제외된 55명을 표시하고, 제외 수가 0인 사유는 표시하지 않습니다.
- 큰 정수의 합을 정확히 계산하며 누락·숫자형·음수·소수·선행 0·합계 불일치는 이전 결과를 지우고 재시도를 안내합니다.
- 적용된 목록·카드 객체·편집 중인 태그·페이지 커서·dirty 상태를 유지합니다.
- 초안의 계정·숫자 0·boolean false·OR 조건을 사용하고 `segment_id`와 `after`를 보내지 않습니다.
- 오류 뒤 재시도, 중복 클릭, 조건 변경 뒤 늦은 성공·실패·종료 처리, 계정·필드 갱신, 기록 삭제와 로그아웃을 확인했습니다.
- 참여자와 계정의 HTML 문자열은 텍스트로 표시하며 미리보기 요청은 `preview=true`의 GET뿐입니다.

1280×1000 데스크톱과 390×844 모바일에서 AND·OR·0명·오류 결과를 직접 확인했고 가로 넘침이 없었습니다.
Enter로 실행한 뒤 미리보기 버튼의 포커스가 유지됐습니다.
병합 전 운영자의 화면 승인은 별도로 필요합니다.

## 로컬 질의 비용

PostgreSQL 17.11의 격리된 UTF-8 DB에 합성 작업 공간·계정 하나와 연락처 10,000명, 각 3개씩 댓글 30,000개를 만들었습니다.
연락처 1,000명은 `lead` 태그가 있고 모든 연락처에 숫자 필드를 저장했으며 짝수 번호 5,000명의 값이 0입니다.
댓글·태그·필드 값 테이블에 `ANALYZE`를 실행한 뒤 실제 `listContacts`가 전달한 SQL과 바인딩으로 `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)`을 각 조합마다 한 번 실행했습니다.
모두 캐시 적중이었으며 shared read blocks는 0이었습니다.

| 조건              | 모드     | 일치 수       | 평가 수       | 실행 시간 | shared hit blocks |
| ----------------- | -------- | ------------- | ------------- | --------- | ----------------- |
| 없음              | 일반     | 반환하지 않음 | 반환하지 않음 | 0.288 ms  | 432               |
| 없음              | 미리보기 | 10,000        | 10,000        | 12.213 ms | 847               |
| 태그 `lead`       | 일반     | 반환하지 않음 | 반환하지 않음 | 0.447 ms  | 1,960             |
| 태그 `lead`       | 미리보기 | 1,000         | 10,000        | 12.661 ms | 2,375             |
| `lead` AND 숫자 0 | 미리보기 | 1,000         | 10,000        | 15.870 ms | 1,632             |
| `lead` OR 숫자 0  | 미리보기 | 5,000         | 10,000        | 19.196 ms | 1,264             |
| 없는 태그         | 미리보기 | 0             | 10,000        | 15.760 ms | 429               |

모든 미리보기는 조건을 통과하지 못한 연락처까지 10,000개 그룹을 분류했습니다.
필터 판정용 집합에는 상세 필드 JSON을 만들지 않으며, 상세 필드 집계는 샘플을 읽는 51개 행에서만 실행됐습니다.
0명 결과에서는 상세 필드 집계가 실행되지 않았습니다.
분류와 샘플이 별도로 읽는 비용이 있고 정확한 평가·제외 수의 비용은 페이지 크기로 제한되지 않습니다.
이 표본은 운영 규모·경합·최악의 조건·네트워크 지연을 재현하지 않으며 운영 성능 보증으로 사용하지 않습니다.
