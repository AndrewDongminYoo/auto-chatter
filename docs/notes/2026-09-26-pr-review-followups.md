# PR 2 후속 보안 작업

## OAuth state 생성 제한과 정리

[보안 리뷰 P3](https://github.com/AndrewDongminYoo/auto-chatter/pull/2#discussion_r4110671861)는 인증된 사용자가 연결 시작 요청을 반복해 OAuth state를 계속 저장할 수 있다고 지적했습니다.
`src/app/instagram-oauth.ts`의 `beginInstagramOAuth`는 요청마다 행을 삽입하며, 10분 만료는 콜백 검증에만 적용됩니다.
사용자별 생성 제한과 만료·소비된 행의 자동 정리는 구현되어 있지 않습니다.
공유 DB의 저장 용량과 다른 사용자의 가용성에 영향을 줄 수 있습니다.

이번 PR의 마이그레이션·발송 경로 수정과 분리해 후속 작업으로 남깁니다.
공개 가입을 확대하기 전에 사용자별 생성 제한을 동시 요청에서도 적용하고 만료 상태를 정리하는 방식을 정해야 합니다.
서버 역할에 포괄적인 DELETE 권한을 부여하지 않는 범위에서 설계하고, 경쟁 요청과 만료·소비된 상태를 포함한 회귀 검증이 필요합니다.
별도 GitHub 이슈는 생성하지 않았습니다.
