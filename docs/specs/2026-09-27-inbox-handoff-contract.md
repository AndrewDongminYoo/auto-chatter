# DM 식별자와 상담 전환 계약

## 범위와 목적

[이슈 #17](https://github.com/AndrewDongminYoo/auto-chatter/issues/17)의 선행 계약입니다.
수신 인박스의 DM 상대와 댓글 연락처를 안전하게 구분하고, 수동 답장 구현이 사용할 조회 근거와 상담 전환 범위를 정의합니다.
이번 변경은 읽기 전용 문맥 API이며 수동 발송·상담 전환 쓰기·화면·마이그레이션·운영 배포는 포함하지 않습니다.

## 식별자와 근거

대화 키는 `(workspace_id, connection_id, recipient_id)`이며 `recipient_id`는 서명된 수신 DM의 `sender.id`에서 얻습니다.
댓글 연락처 키는 `(workspace_id, connection_id, sender_id)`입니다.
숫자 값이 같거나 표시 이름이 같다는 이유로 두 키를 연결하지 않습니다.
여러 작업 공간·계정 사이의 식별자를 합치지 않습니다.

연결 근거는 성공한 비공개 답장의 `private_reply_outbox.recipient_id`입니다.
워커는 Graph 발송 응답의 `recipient_id`를 기록하며, 성공 상태·공급자 메시지 ID·발송 시각과 원본 댓글 작성자가 함께 확인돼야 후보로 사용합니다.
응답에 숫자 `recipient_id`를 제공하는 전송기만 연결 근거를 남깁니다.
현재 Facebook Login 전송기는 이 값을 반환하지 않으며, 성공 발송이어도 상대 ID가 없고 다른 유효한 근거가 없으면 `unmapped`입니다.
원본 댓글의 작성자가 outbox의 작성자와 다르면 후보에서 제외합니다.
후보의 발송 시각이 현재 시각보다 뒤라면 응답 근거로 사용하지 않습니다.
`sent_at`는 공급자 성공 응답을 로컬 DB에 기록한 시각이며 실제 전달 시각이 아닙니다.
수신 메시지가 이 기록보다 빠를 수 있으므로 마지막 수신과 발송 기록의 순서를 연결 근거의 조건으로 사용하지 않습니다.
이 조회는 저장된 발송 응답을 읽으며 실제 공급자 조회로 현재 신원을 재검증하거나 마케팅 동의를 확인하지 않습니다.

## 읽기 API

`GET /api/connections/:connectionId/inbox/:recipientId/context`는 인증된 작업 공간의 저장된 대화만 조회합니다.
확인된 이메일의 세션과 `workspace_members` 멤버십이 필요하며 응답은 `Cache-Control: no-store`입니다.
연결 소유권이 없으면 `connection_not_found`, 대화가 없으면 `conversation_not_found`로 404를 반환합니다.
숫자 상대 ID는 1–40자로 제한하고 query 매개변수는 허용하지 않습니다.
기존 메시지 조회 응답은 바꾸지 않습니다.

응답은 `mapping_status`, `comment_sender_id`, `evidence_reply_id`, `automation_paused`, `last_message_at`를 제공합니다.
본문·발송 문구·토큰·이메일·공급자 응답 본문은 반환하지 않습니다.
연결 근거가 확인되지 않은 상태에서는 댓글 작성자·근거 ID·중지 상태를 모두 `null`로 반환합니다.

| 상태        | 판정                                                                                                                     |
| ----------- | ------------------------------------------------------------------------------------------------------------------------ |
| `unmapped`  | 조건을 충족하는 성공 발송 근거가 없습니다. 같은 숫자의 댓글 작성자만 존재해도 이 상태입니다.                             |
| `stale`     | 댓글 작성자가 하나이며 근거가 모두 현재 인박스 보관 시작 시각보다 오래됐거나 시작 시각이 없습니다.                       |
| `ambiguous` | 같은 대화에 둘 이상의 서로 다른 댓글 작성자가 후보로 나타납니다. 최신 한 명을 임의로 고르지 않습니다.                    |
| `verified`  | 댓글 작성자가 하나이며 현재 보관 시작 시각 이후의 근거가 있습니다. 같은 작성자의 여러 답장은 하나의 식별자로 취급합니다. |

판정은 후보 없음의 `unmapped`, 작성자 둘 이상인 `ambiguous`, 작성자 하나이고 최신 근거가 있는 `verified`, 나머지 `stale` 순입니다.
작성자가 서로 다르면 모든 근거가 오래됐어도 `ambiguous`이며, 최신 근거는 `sent_at >= inbox_enabled_at`로 판정합니다.

보관 시작 시각을 재연결·수신 재개 이후의 근거 경계로 사용하는 것은 보수적인 서비스 정책입니다.
Meta가 식별자 연결의 유효기간을 이렇게 정했다는 뜻이 아닙니다.
오래된 후보가 최신 후보와 다른 작성자를 가리키면 충돌로 판단합니다.
`verified`에서는 가장 최근의 유효한 근거 행 ID와 현재 댓글 연락처의 중지 상태를 읽습니다.
조회 시각의 상태는 이후 발송 권한을 예약하거나 고정하지 않습니다.

## 이후 수동 답장의 상담 전환 계약

[수동 답장 #18](https://github.com/AndrewDongminYoo/auto-chatter/issues/18)에서 아래 쓰기와 최종 guard를 구현해야 합니다.
이 문맥 조회만으로 상담 전환이 구현됐다고 표시하지 않습니다.

1. DM 대화의 상담 전환은 DM 대화 키로 별도 보관하며, 댓글 연락처 중지와 구분합니다.
2. 확인된 댓글 작성자의 자동화도 중지하되, 근거가 없는 댓글 작성자를 동일인으로 추정해 중지하지 않습니다.
3. 미확인·오래된·충돌 근거의 대화에 수동 답장을 허용하려면 DM 기준 중지와 기존 자동화 충돌을 차단하는 서버 계약이 먼저 필요합니다.
   그 계약이 준비되기 전에는 연결 근거 없는 대화의 수동 발송을 차단합니다.
4. 예약 시 하나의 트랜잭션으로 소유권·현재 근거·중지 범위를 확인하고 변경 전 상태·운영자·시각·사유를 감사 기록에 남깁니다.
5. 발송 직전 대화·연결·토큰·답장 창·중지 상태를 DB에서 다시 읽습니다.
   사용자가 조회한 문맥이나 이전 중지 상태를 발송 권한으로 사용하지 않습니다.
6. 재개는 상담 전환에서 만든 중지 원인만 해제합니다.
   기존에 사용자가 직접 중지한 연락처를 자동 재개하거나 `unknown`·실패·차단 결과를 초기화하지 않습니다.
7. 이미 외부 POST에 들어간 요청은 중지로 취소할 수 없습니다.
   대기 중 작업과 진행 중 작업의 한계를 화면과 감사 기록에 남깁니다.

## 수용 기준

- 다른 작업 공간과 계정의 같은 DM 상대 ID를 읽지 않습니다.
- 숫자가 같은 댓글 ID만으로 연결하지 않습니다.
- 성공하지 않았거나 원본 작성자가 다른 행은 근거가 되지 않습니다.
- 여러 게시물의 동일 작성자는 하나로 보되 서로 다른 작성자의 근거는 충돌로 처리합니다.
- 재연결 이후 오래된 근거와 미래 시각의 근거를 구분합니다.
- 중지 상태 변경 후 조회는 최신 값을 읽으며 조회가 설정을 바꾸지 않습니다.

## 출처와 검증 한계

현재 코드의 `src/instagram/reply-worker.ts`·`src/instagram/inbox.ts`·`src/app/inbox.ts`와 `db/schema.sql`을 기준으로 작성했습니다.

이 조건을 댓글 식별자만으로 충족했다고 간주하지 않습니다.
Meta의 비공개 답장 웹페이지 원문은 이번 조회에서 접근하지 못했으며, 실제 계정 권한과 수동 발송은 별도 검증이 필요합니다.

Oracle의 `wiki/concepts/diagnostic-report-pattern.md` 선례에 따라 확인한 근거와 없는 근거를 구분하고 상태를 명시했습니다.
`wiki/sources/claude--commands--fix-with-test.md`의 불확실한 결과를 추정하지 않는 원칙을 미확인 연결의 차단 계약에 적용했습니다.
