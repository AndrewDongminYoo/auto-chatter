# 인박스 대화 라벨과 내부 메모

## 범위

[이슈 #23](https://github.com/AndrewDongminYoo/auto-chatter/issues/23)의 두 번째 부분(#23-B)입니다.
첫 부분인 [검색·필터와 읽음 상태](2026-09-27-instagram-inbox.md#검색-필터와-읽음-상태)(#23-A) 위에, 인박스 대화에 붙이는 라벨과 멤버끼리만 보는 내부 메모를 더합니다.
리마인더(#23-C)는 다음 회차에서 다루고, 키워드로 라벨을 자동으로 붙이는 규칙은 별도 이슈로 나눕니다.
migration 033이 테이블 넷과 삭제 함수 변경을 더하며, 운영 DB 적용과 배포는 이 PR의 범위가 아닙니다.
PR #131과 migration 033은 2026-10-04 `main` 커밋 `6e3df5b`으로 운영 DB에 적용하고 배포했습니다([운영 기록](../notes/2026-09-26-cloudflare-runbook.md)). 운영에는 여러 멤버와 라벨이 없어, 라벨·라벨 필터·내부 메모를 운영 데이터로 조작하지 않았습니다.

## 정한 값

운영자가 정하지 않은 한도는 다음 값으로 정했습니다.

| 항목                       | 한도                          |
| -------------------------- | ----------------------------- |
| 라벨 이름                  | 앞뒤 공백을 뺀 1–30자         |
| 작업 공간의 사용 중인 라벨 | 50개(보관한 라벨은 세지 않음) |
| 대화 하나의 라벨           | 10개(보관한 라벨 포함)        |
| 메모 본문                  | 앞뒤 공백을 뺀 1–2,000자      |

글자 수는 PostgreSQL `length()`와 같은 코드 포인트 기준입니다.

## 라벨과 연락처 태그

라벨은 인박스 대화, 곧 `(workspace_id, connection_id, recipient_id)`에만 붙습니다.
[연락처 태그](2026-09-27-instagram-contacts.md)는 댓글 작성자 ID에 붙으므로 둘은 따로 저장하고, 라벨을 붙여도 댓글 작성자와 DM 수신자를 같은 사람으로 합치지 않습니다.
라벨은 플로·외부 전송·자동 답장 조건에 쓰이지 않습니다.

## 저장

- `instagram_inbox_labels`: 작업 공간의 라벨 정의입니다. 이름, 보관 여부, 만든 멤버와 시각을 저장합니다. 지우지 않고 보관만 하며, 보관하지 않은 라벨의 이름은 작업 공간 안에서 대소문자를 무시하고 하나뿐입니다(부분 고유 인덱스 `lower(name) WHERE NOT archived`).
- `instagram_inbox_conversation_labels`: 대화마다 한 행으로 라벨 ID 배열(`uuid[]`)과 버전을 저장합니다. 서버 역할에 DELETE 권한이 없으므로 라벨을 붙이고 떼는 일은 배열을 바꾸는 UPDATE입니다. 배열은 10개 이하이고 NULL과 중복이 없어야 합니다(`inbox_label_ids_valid` CHECK).
- `instagram_inbox_label_events`: 버전마다 한 행씩 붙인 라벨, 뗀 라벨, 실행한 멤버와 시각을 남기는 추가 전용 감사 기록입니다.
- `instagram_inbox_notes`: 작성 멤버, 본문, 시각을 저장하는 추가 전용 메모입니다.

서버 역할은 라벨 정의와 대화 라벨 행을 SELECT·INSERT·UPDATE하고, 감사 기록과 메모는 SELECT·INSERT만 할 수 있습니다. 네 테이블 모두 DELETE 권한이 없고 RLS가 켜져 있으며 Supabase API 역할은 접근할 수 없습니다.
라벨 ID 배열과 작성자·실행자 열에는 외래 키를 두지 않고, 쓰는 시점에 서버가 같은 작업 공간의 라벨과 멤버인지 확인합니다.

## API

| 요청                                                         | 최소 역할 | 동작                                                                        |
| ------------------------------------------------------------ | --------- | --------------------------------------------------------------------------- |
| `GET /api/inbox/labels`                                      | agent     | 보관한 라벨을 포함한 모든 라벨(`archived` 표시)                             |
| `POST /api/inbox/labels`                                     | admin     | `{name}`으로 라벨 추가                                                      |
| `PATCH /api/inbox/labels/:label`                             | admin     | `{name}`으로 이름 변경. 보관한 라벨은 `409 label_archived`                  |
| `DELETE /api/inbox/labels/:label`                            | admin     | 라벨 보관(지우지 않음). 되돌리는 API는 없습니다                             |
| `PUT /api/inbox/conversations/:connection/:recipient/labels` | agent     | `{expected_version, label_ids}`로 대화의 라벨 전체를 바꿈                   |
| `GET /api/inbox/conversations/:connection/:recipient/notes`  | agent     | 메모를 최신순 50개씩, `before`로 다음 쪽                                    |
| `POST /api/inbox/conversations/:connection/:recipient/notes` | agent     | `{body}`로 메모 추가(`201`)                                                 |
| `GET /api/inbox`                                             | agent     | 대화마다 `label_set`(버전과 라벨 ID·이름·보관 여부), `label=<라벨 ID>` 필터 |
| `GET /api/connections/:connection/inbox/:recipient`          | agent     | 메시지와 함께 그 대화의 `label_set`                                         |

상담원도 대화의 라벨을 바꾸고 필터로 고르려면 라벨 목록이 필요하므로 목록 조회는 상담원 이상이고, 추가·이름 변경·보관은 관리자 이상입니다.
GET이 아닌 요청은 모두 같은 출처여야 합니다.
이름이 비었거나 30자를 넘거나 제어 문자가 있으면 `400 invalid_label`, 사용 중인 같은 이름이 있으면 `409 label_name_exists`, 사용 중인 라벨이 50개면 `409 label_limit_reached`, 다른 작업 공간의 라벨이면 `404 label_not_found`입니다.
라벨 추가는 [저장된 필터](2026-09-27-contact-segments.md)처럼 작업 공간 행을 `FOR UPDATE`로 잠근 뒤 개수를 세므로, 49개일 때 동시에 들어온 두 추가 중 하나만 성공합니다.

### 대화 라벨 변경

`PUT .../labels`는 바꾼 뒤의 라벨 전체(최대 10개, 중복 없음)와 마지막으로 읽은 버전을 받습니다.
잠금 순서는 [대화 상태 변경](2026-10-01-inbox-conversation-assignment.md#api)과 같습니다: 작업 공간 행 `FOR SHARE`, 호출자의 멤버 행 `FOR SHARE`(제거 여부를 다시 확인), 연결 행 `FOR SHARE`, 대화별 advisory lock(`lockConversation`) 배타, 그 다음 라벨 행 `FOR UPDATE`입니다.
대화에 보관한 DM이 하나도 없으면 `404 conversation_not_found`, 버전이 다르면 `409 {error: "label_conflict", label_set}`으로 현재 라벨을 돌려줍니다.
새로 붙이는 라벨은 같은 작업 공간의 보관하지 않은 라벨이어야 합니다(없으면 `404 label_not_found`, 보관했으면 `409 label_archived`).
이미 붙어 있던 라벨은 보관된 뒤에도 그대로 둘 수 있고 뗄 수도 있지만, 뗀 뒤에는 다시 붙일 수 없습니다.
새로 붙이는 라벨 행은 `FOR SHARE`로 잠가 두므로, 확인한 뒤 커밋하기 전에 들어온 보관은 이 변경이 커밋될 때까지 기다리고, 먼저 시작한 보관이 커밋되면 이 변경은 보관된 라벨을 보고 거부됩니다.
바뀌는 라벨이 있으면 버전을 하나 올리고 감사 행을 하나 쓰며, 같은 라벨 묶음(순서만 다른 경우 포함)이면 버전과 감사 행 없이 현재 라벨을 돌려줍니다.

### 목록 필터

`label=<라벨 ID>`는 그 라벨이 붙은 대화만 고르고 상태·담당자·안 읽음·검색 필터, 커서와 함께 쓸 수 있습니다.
보관한 라벨로도 고를 수 있으며, 다른 작업 공간의 라벨 ID는 아무 대화와도 맞지 않습니다.
목록의 각 대화는 붙은 라벨을 이름순으로 담은 `label_set`을 함께 돌려줍니다.

### 내부 메모

메모는 작업 공간 멤버끼리 보는 글이며 고객에게 보내지 않습니다.
플로, 외부 전송, 메시지 목록과 DM 검색(`q`)은 메모를 읽지 않고, 화면은 메모를 메시지와 다른 칸에 보입니다.
메모는 고치거나 지울 수 없습니다. 바로잡을 내용은 새 메모로 남기며, 메모를 지우는 길은 아래 삭제 함수뿐입니다.
메모 추가는 라벨 변경과 같은 순서로 작업 공간 행, 멤버 행, 연결 행을 `FOR SHARE`로 잠근 뒤 대화가 있는지 확인하고 씁니다.
요청 키가 없으므로 응답을 받지 못한 추가를 다시 보내면 같은 메모가 두 번 남을 수 있습니다. 화면은 이 경우 다시 보내기 전에 메모 목록을 확인하라고 안내합니다.

## 삭제와 내보내기

[연결 데이터 삭제](2026-09-29-connection-data-deletion.md)는 그 연결의 대화 라벨, 감사 기록, 메모를 지우고 작업 공간의 라벨 정의는 남깁니다.
[사람 데이터 삭제](2026-09-30-person-data-deletion.md)는 그 사람에게 이어진 DM 수신자의 대화 라벨, 감사 기록, 메모만 지웁니다.
[작업 공간 삭제](2026-09-30-workspace-data-deletion.md)는 라벨 정의를 포함한 네 테이블을 모두 지웁니다.
세 함수 모두 지운 행 수를 테이블별로 기록합니다.
라벨 변경과 메모 추가가 연결 행을 `FOR SHARE`로 잠그므로, 삭제가 먼저 시작되면 삭제가 커밋된 뒤 `404`(작업 공간 삭제는 `403`)로 끝나고, 쓰기가 먼저 시작되면 삭제가 그 커밋을 기다렸다가 새 행까지 지웁니다.
[작업 공간 내보내기](2026-09-30-workspace-export.md)는 네 테이블을 각각의 표로 담고, 메모를 DM 메시지 표에 섞지 않습니다.

## 화면

- 인박스 목록의 각 대화에 붙은 라벨을 칩으로 보이고, 보관한 라벨은 "(보관됨)"을 붙여 다른 모양으로 보입니다.
- 필터 줄에 "라벨" 선택이 있고 보관한 라벨도 고를 수 있습니다.
- 대화를 열면 "라벨" 칸에서 체크박스로 고르고 "라벨 저장"으로 저장합니다. 붙일 수 있는 라벨과 이미 붙은 보관 라벨만 보이고, 10개를 고르면 나머지는 고를 수 없습니다. 다른 멤버가 먼저 바꿨으면 안내와 함께 최신 라벨을 다시 불러옵니다.
- 대화 화면 아래 "내부 메모" 칸은 메시지와 다른 배경과 "팀 전용" 표시로 구분하고, 메모를 최신순으로 보이며 Ctrl/⌘ + Enter로도 남길 수 있습니다.
- 관리자와 소유자에게만 설정 영역의 "인박스 라벨" 칸이 보이며 라벨을 추가하고 이름을 바꾸고 보관할 수 있습니다.

화면 확인 기록은 [로컬 화면 검증](../notes/2026-10-03-inbox-labels-notes-ui-verification.md)에 있습니다.
