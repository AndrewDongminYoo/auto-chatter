# 비밀번호 복구

## 문제

이메일 인증을 마친 사용자가 비밀번호를 잊으면 현재 화면에서 계정을 복구할 수 없습니다.

## 이번 범위

- 로그인 화면에서 이메일로 복구 링크를 요청합니다.
- Supabase Auth의 복구 링크가 `/app/`으로 돌아오면 주소 조각의 토큰을 즉시 지우고 새 비밀번호를 입력받습니다.
- 서버가 복구 토큰으로 비밀번호를 변경하고 세션 종료를 요청합니다.
- 존재하지 않는 이메일과 공급자가 거부한 복구 요청에는 같은 안내를 표시합니다.
- 만료되거나 잘못된 링크에는 다시 요청할 방법을 안내합니다.

## 제외

- 이메일 템플릿, SMTP와 Supabase의 발송 한도를 변경하지 않습니다.
- 가입·로그인 전체에 대한 별도 애플리케이션 단위 속도 제한은 이번 변경에 포함하지 않습니다.
- 운영 Supabase 설정과 Worker를 이 PR에서 바꾸지 않습니다.

## 수용 기준

1. 복구 요청은 이메일 주소를 검증한 뒤 Supabase Auth의 `/recover`만 호출하며, 계정 존재 여부나 공급자 오류 본문을 반환하지 않습니다.
2. 복구 토큰은 URL에서 제거하고 브라우저 저장소나 일반 로그인 쿠키에 저장하지 않습니다.
3. 유효한 복구 토큰으로 비밀번호를 변경하면 브라우저 세션을 지우고 로그인 화면으로 돌아갑니다.
4. 만료 링크와 공급자 장애를 구분해 안내하되 토큰과 계정 존재 여부를 노출하지 않습니다.
5. 키보드로 모든 단계에 접근할 수 있고 오류 안내를 화면 읽기 도구가 읽을 수 있습니다.

## 운영 확인

복구 링크는 Supabase Auth의 Site URL인 `https://auto-chat.donminzzi.kr/app/`으로 돌아옵니다.
운영에서 이메일 발송, 링크 만료, 새 비밀번호 로그인, 이전 세션 폐기는 별도로 실제 확인해야 합니다.
Supabase Auth의 기본 발송 제한과 인증 요청 제한을 사용합니다.
서비스 자체의 남용 제한과 인증 메일 재전송은 [인증 경로 마무리](2026-09-28-auth-completion.md)에서 다룹니다.
