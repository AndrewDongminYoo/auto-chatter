# 선택 활성화하는 Instagram 수신 인박스

## 목표와 계약

연결 계정의 관리자가 인박스를 선택 활성화하고 이후 받은 텍스트 DM과 확인 버튼 응답을 읽을 수 있게 합니다.
기존 수동 삭제 정책을 적용하며 원격 과거 메시지를 수집하지 않습니다.
기본값은 꺼짐이고 활성화 시각 이전 이벤트는 저장하지 않습니다.
수신 중지·연결 해제는 새 저장을 막지만 보관한 메시지는 소유한 작업 공간에서 계속 열람할 수 있습니다.
비활성화 후 재활성화하면 새 활성화 시각부터 저장합니다.

대화 식별자는 작업 공간·연결·DM 작성자 ID입니다.
댓글 작성자 ID와 같다고 추정하거나 태그·팔로우·동의 정보를 연결하지 않습니다.
기존 확인 응답 처리는 동일하게 유지하고 인박스 저장은 발송이나 확인 처리의 근거가 되지 않습니다.
본문은 로그에 기록하지 않고 화면에서 텍스트로 렌더링합니다.
계정 설정 변경은 인증과 같은 출처 검사를 거쳐 정확한 boolean 본문만 받습니다.

## 범위와 비목표

이번 회차는 수신 텍스트·확인 버튼 응답 저장, 대화·메시지 페이지 조회, 계정별 보관 스위치와 화면을 구현합니다.
첨부·echo·수정·삭제 메시지, 과거 가져오기, 발신 이력, 수동 발송, 팀 역할·배정·내부 메모와 운영 배포는 후속 범위입니다.
이는 공유 인박스의 수신 기반이며 전체 공유 인박스 완료를 의미하지 않습니다.

## 수락 기준

1. 꺼짐·수신 중지·미연결·활성화 전 이벤트는 인박스에 본문을 남기지 않습니다.
   인박스와 별개로, 플로의 응답 대기가 `save_field_id`로 지정한 필드에 응답을 저장하는 경우([#107](https://github.com/AndrewDongminYoo/auto-chatter/pull/107), [응답 대기](2026-09-30-flow-runs.md#응답-대기))와 발송 기록 전에 도착한 응답을 연결을 위해 임시로 남기는 경우([#108](https://github.com/AndrewDongminYoo/auto-chatter/issues/108), [발송 기록 전에 도착한 응답](2026-09-30-flow-runs.md#발송-기록-전에-도착한-응답))는 인박스 설정과 관계없이 본문을 저장합니다.
2. 같은 message ID를 재생해도 한 행만 저장하고 역순 이벤트가 최신 메시지 시각을 되돌리지 않습니다.
3. 다른 작업 공간은 설정·대화·본문을 조회하거나 수정할 수 없습니다.
4. 대화는 계정·수신자 ID의 안정적인 키 순서로, 메시지는 최신 수신 기록부터 페이지를 조회합니다.
5. 중복 확인 응답·버튼·팔로우 흐름의 기존 계약은 유지합니다.
6. RLS와 DML 서버 역할에 새 테이블을 포함하고 DELETE 권한을 추가하지 않습니다.
7. 실제 브라우저에서 선택·더 보기·실패·늦은 응답·로그아웃과 모바일 폭을 확인합니다.
8. 공개 문구는 선택 활성화한 계정에서만 인박스에 DM 본문을 보관한다는 구현과 일치합니다.
   1번의 두 예외(플로가 저장하도록 지정한 응답, 연결을 위해 임시로 보관하는 응답)도 공개 문구에 적습니다.

## 근거와 선례

현재 계약은 `src/instagram/message-events.ts`, `src/instagram/follow-flow.ts`, `src/app/settings.ts`, `db/schema.sql`과 공개 개인정보 문구에서 확인했습니다.
개인 계정 auto-chatter의 DM retention/inbox Oracle 조회는 `[no precedent found]`이며 Wiki freshness는 확인되지 않았습니다.
2026-09-27 [Meta Send API](https://www.postman.com/meta/instagram/folder/uxudqu0/send-api)는 일반 발송에 상대방의 선대화와 메시지 권한을 요구합니다.
수신 조회는 수동 발송 자격을 부여하지 않습니다.
