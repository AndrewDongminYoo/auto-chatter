# 연락처별 자동화 일시 중지

## 목표

상담원이 댓글 참여자 한 명의 자동화를 중지하고 재개할 수 있게 한다.
이는 ManyChat 대체제의 상담원 개입 기능을 위한 단계이며 공유 인박스나 수동 DM 발송을 완료했다고 주장하지 않는다.

## 계약

- 상태는 작업 공간·Instagram 연결·댓글 작성자 ID별로 저장한다.
- 인증과 같은 출처 검사를 거친 `PUT /api/connections/{connection_id}/contacts/{sender_id}/automation`은 정확히 `{paused: boolean}`만 받는다.
- 기존 댓글 연락처만 변경할 수 있고, 외부 작업 공간·다른 연결·존재하지 않는 연락처는 404로 처리한다.
- 연락처 목록은 현재 `automation_paused` 상태를 제공하며 기본값은 false다.
- 중지 중에는 첫 DM과 후속 DM을 선점하거나 큐 알림의 처리 대상으로 선택하지 않는다.
- 선점 뒤 중지가 확인되면 발송하지 않고 pending으로 되돌린다.
- Node와 Cloudflare의 마지막 발송 권한 조회에서도 같은 상태를 검사한다.
- 중지 중 받은 새 확인 DM은 자동화에 사용하지 않는다.
- 대기 발송은 보존한다.
  재개 후에는 원래 7일 댓글 응답·24시간 DM 응답·계정·규칙·토큰·쿨다운 조건을 다시 검사한다.
- 재개는 unknown·failed·blocked 상태를 초기화하거나 다시 발송하지 않는다.
- 중지 설정과 외부 POST는 원자적으로 묶이지 않는다.
  최종 검사 이후 이미 Meta로 전달되는 요청은 취소할 수 없다.
- 재개 시 유효한 대기 메시지가 발송될 수 있다는 내용을 화면에서 확인받는다.
- 입력 중인 연락처 초안은 설정 저장 성공·실패로 사라지지 않으며 로그아웃 뒤 늦은 응답은 화면을 복원하지 않는다.

## 비목표

DM 본문 저장, 공유 인박스, 상담원 배정, 수동 메시지, 자동 만료 중지, 일괄 변경, 팔로워 동의 추론, 발송 기간 연장과 운영 배포는 포함하지 않는다.
새 설정은 자동화 전달 제어 메타데이터이며 기존 수동 삭제 정책으로 처리한다.

## 수락 기준

1. 실제 DB API가 정확한 타입·본문, 소유권과 기존 연락처 검사를 실행한다.
2. 중지된 첫 DM·후속 DM은 Meta 호출 없이 대기하고 다른 연락처는 처리된다.
3. 검증 중 중지와 transport의 최종 검사에서 중지 모두 재시도 가능한 pending으로 보존된다.
4. 재개 후 기간 내 메시지만 발송되며 만료·unknown 상태는 자동 재발송하지 않는다.
5. Cloudflare 큐·cron과 Node의 마지막 검사에 동일한 범위가 적용된다.
6. 실제 로컬 화면에서 중지·재개·실패·초안·세션 종료와 390px 폭을 검사한다.
7. RLS와 제한된 서버 역할을 유지하고 마이그레이션 재실행을 확인한다.
