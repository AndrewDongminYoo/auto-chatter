# 연결 데이터 삭제 화면과 삭제 기록

## 목표와 범위

GitHub #81의 설정 화면을 [연결 단위 데이터 삭제 계약](2026-09-29-connection-data-deletion.md) 위에 추가합니다.
계정 관리자는 해제한 Instagram 연결의 기록을 설정 화면에서 삭제하고, 연결별 삭제 기록의 건수와 시각을 확인합니다.
서버 API, DB 함수, 이용자 단위 삭제의 실행 경로와 운영 배포는 바꾸지 않습니다.

## 삭제 동작

- 삭제 양식은 `active`와 `send_enabled`가 모두 false이고 저장된 토큰이 없는(`token_registered === false`) 연결에만 표시합니다. DB 함수의 `connection_active` 조건과 같으며, 만료된 토큰이 남아 있거나 수신만 중지한 연결에는 표시하지 않습니다.
- 양식은 접힌 "데이터 삭제" 영역 안의 label, 입력, 제출 버튼으로 구성하며 브라우저 대화 상자를 쓰지 않습니다.
- label에 숫자 Instagram 계정 ID를 표시하고, 입력값의 앞뒤 공백을 제거한 뒤 `confirm_account_id`로 보냅니다. 일치 여부는 서버가 판정합니다.
- 삭제 범위, 보관하는 기록, 되돌릴 수 없다는 사실을 양식 설명에 적습니다.
- 성공하면 입력을 비우고 양식을 닫은 뒤 삭제 건수를 알리고 삭제 기록을 엽니다. 닫힌 양식 안에 초점이 남지 않도록 "삭제 기록" 요약으로 초점을 옮깁니다.
- 성공하면 이 연결의 연락처 카드와 저장하지 않은 연락처 변경, 인박스 초안과 열린 대화를 화면에서 지운 뒤 연락처·인박스·처리 내역을 다시 불러옵니다. 다른 연결의 저장하지 않은 연락처 변경이 있으면 연락처 목록은 다시 불러오지 않고 이 연결의 카드만 지웁니다.

## 오류 안내

오류는 양식 안의 `role="alert"` 문단에 표시하고, 입력에 `aria-invalid`를 붙인 뒤 입력으로 초점을 옮깁니다.

| 코드                    | 안내 요지                                              |
| ----------------------- | ------------------------------------------------------ |
| `confirmation_mismatch` | 입력한 ID가 연결의 계정 ID와 다르므로 표시된 ID를 입력 |
| `connection_active`     | 아직 연결되어 있으므로 '연결 해제' 뒤 다시 시도        |
| `sending_in_progress`   | 발송 중인 메시지가 있으므로 몇 분 뒤 다시 시도         |
| `invalid_data_deletion` | 확인할 계정 ID를 입력                                  |

## 삭제 기록

- 같은 계정을 다시 연결하면 기존 연결 행을 재사용하므로 삭제 기록이 남습니다. 따라서 모든 연결에 접힌 "삭제 기록" 영역을 두고, 열 때 `GET /api/connections/:id/data-deletions`를 호출합니다.
- 각 기록은 완료 시각, 삭제 단위, 요청자, 삭제 총계와 0보다 큰 항목별 건수, 보관 항목별 건수를 표시합니다.
- 연결 단위 기록의 요청자는 현재 사용자이면 "내 요청", 아니면 "다른 관리자 요청"으로 표시합니다. 사용자 ID는 표시하지 않습니다.
- `scope=person` 기록은 "이용자 단위 삭제(운영자 처리)"로 표시하고 요청자를 표시하지 않습니다.
- 알 수 없는 건수 키는 키 이름 그대로 표시합니다.
- 세션 재설정 뒤에 도착한 응답과 이전 요청의 응답은 화면을 바꾸지 않습니다.

## 공개 문구

`/data-deletion`, `/service`, `/privacy`에 계정 관리자가 해제한 연결의 기록을 설정 화면에서 직접 삭제할 수 있다는 문장을 추가합니다.
이메일 요청과 운영자의 수동 처리 절차는 그 밖의 요청에 그대로 적용합니다.

## 검증

1. 공개 페이지 단위 테스트가 세 페이지의 앱 내 삭제 경로 문장을 확인합니다.
2. 실제 `public/app` 파일과 합성 API로 표시 조건, 키보드 조작, 오류 4종, 성공과 기록 표시, 390px 폭, 다크 모드, 늦은 응답을 브라우저에서 확인합니다.
3. 결과는 [화면 검증 기록](../notes/2026-09-30-connection-deletion-ui-verification.md)에 남깁니다. 운영 배포와 실계정 삭제는 별도로 승인을 받습니다.
