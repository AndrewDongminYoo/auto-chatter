# Instagram 게시물 선택기

## 문제

첫 규칙을 만들 때 숫자 게시물 ID를 찾아야 하며, 저장한 규칙에서도 게시물을 구별하기 어렵습니다.

## 목표

- 연동 계정을 고른 뒤 썸네일, 본문 일부, 게시 날짜로 게시물을 선택합니다.
- 게시물을 더 불러올 수 있고 조회 실패 시 입력을 유지하며 재시도합니다.
- 서버는 인증된 사용자의 연결과 암호화된 토큰만 사용합니다.
- 신규 규칙 저장 전에 게시물 소유를 확인합니다.
- 기존 규칙의 계정과 게시물은 변경하지 않습니다.
- 기존 규칙은 게시물이 삭제되거나 토큰이 만료되어도 문구 수정과 비활성화를 할 수 있습니다.

## 비목표

게시물 링크 검색, Instagram 콘텐츠 동기화, 자동 발송 정책 변경, 토큰 자동 갱신, 운영 배포는 이번 범위에 포함하지 않습니다.
숫자 ID를 직접 입력하는 기존 외부 API 형식은 유지합니다.

## 계약

인증된 GET `/api/connections/:id/media`는 최대 12개 게시물과 다음 커서를 반환합니다.
GET `/api/connections/:id/media/:mediaId`는 같은 계정의 게시물 상세를 반환합니다.
서버는 제공받은 다음 페이지 URL을 따라가지 않고, 고정 Graph 호스트에 커서만 전달합니다.
토큰과 provider 오류 본문은 브라우저로 반환하지 않습니다.
메타데이터는 DB에 추가 저장하지 않으며 새 규칙은 기본 비활성으로 작성합니다.

## 완료 기준

- 인증되지 않은 요청과 다른 workspace의 연결은 Graph 조회 전에 거부됩니다.
- 계정에 속하지 않는 게시물은 신규 규칙 저장 전에 거부됩니다.
- 잘못된 커서, 토큰 만료, provider 거절과 잘못된 응답은 명시적인 오류로 처리됩니다.
- 목록의 게시물은 키보드와 모바일에서 선택할 수 있습니다.
- 계정 변경과 비동기 응답 순서가 바뀌어도 이전 계정의 게시물을 선택하지 않습니다.
- 기존 규칙 수정은 조회 실패 시에도 원래 대상과 입력 내용을 유지합니다.

## 검증 한계

모의 provider 테스트와 브라우저 fixture는 실제 Meta 권한을 검증하지 않습니다.
Meta 문서 조회는 로그인 요구 또는 429로 제한됐습니다.
필드와 media edge는 Meta 공식 SDK 및 기존 실제 계정 조회 증거를 참고하지만, 새 목록 API의 실계정 호출은 운영 배포 전에 별도로 확인해야 합니다.
Oracle 조회 결과는 `[no precedent found]`입니다.
