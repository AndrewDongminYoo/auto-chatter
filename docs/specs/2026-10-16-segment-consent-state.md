# 댓글 연락처의 목적별 동의 기록 필터

## 문제와 범위

[#26](https://github.com/AndrewDongminYoo/auto-chatter/issues/26)의 동의 조건을 기존 댓글 연락처 목록·저장된 필터·초안 미리보기에 추가합니다.
기존 `channel_consent_state`에 현재 기록된 상태만 비교합니다.
조회 범위는 작업 공간·연결·Instagram·`comment_sender`·작성자·목적이며 DM 식별자와 연결하거나 다른 식별자의 동의를 옮기지 않습니다.
DM 대화의 동의 기록은 [DM 동의 기록](#dm-동의-기록)의 별도 조건으로 비교합니다.
이 조건은 전송 가능 여부, 동의의 법적 적절성이나 명시적 근거의 유효성을 판정하지 않습니다.

## 조건과 저장 계약

- `consent_purpose=service_reply|marketing`과 `consent_state=granted|revoked|no_record`를 함께 지정합니다.
  `granted`는 해당 범위의 현재 `decision=grant`, `revoked`는 `decision=revoke`, `no_record`는 현재 상태 행이 없다는 뜻입니다.
  근거 종류와 발생 시각은 상태를 다시 해석하는 기준으로 사용하지 않습니다.
  예를 들어 marketing의 import 근거 grant도 grant로 기록된 사실만 일치하며 발송 허가를 얻는 것은 아닙니다.
- 조회에서 한 키 누락·빈 문자열·중복·허용되지 않은 값은 DB 접근 전에 400으로 거절합니다.
  저장 요청에서 둘 다 생략하거나 null이면 조건 없음이며, 하나만 지정하거나 잘못된 값이면 거절합니다.
- 세그먼트는 nullable 목적·상태 컬럼을 쌍으로 저장합니다.
  기존 행은 둘 다 null이며 기존 생성·목록 응답에서는 두 키를 생략합니다.
  조건이 있으면 두 키를 생성·목록 응답에 반환하고 저장·선택·보관 후 수동 목록에서도 보존합니다.
- 계정·활동 기간과 마찬가지로 동의 기록 조건은 태그/필드 AND·OR와 별도의 AND입니다.
  OR가 동의 기록 불일치를 포함하지 않습니다.
  `segment_id`와 수동 동의 조건을 한 요청에서 혼합하지 않습니다.
- 현재 상태를 다시 조회하므로 철회·재동의·`all` 철회의 기존 투영 결과가 다음 조회에 반영됩니다.
  클라이언트의 `occurred_at`으로 별도 최신 상태를 계산하지 않습니다.
  이 기능은 원장이나 발송 상태를 쓰지 않습니다.

## 미리보기와 화면

평가 범위는 작업 공간·선택 계정의 모든 저장 댓글 연락처입니다.
선택한 활동 기간 밖 연락처는 기존 `excluded.activity`로 먼저 제외합니다.
기간 안이면서 동의 기록 조건에 맞지 않는 연락처는 `excluded.consent`로 제외합니다.
둘을 만족한 연락처만 기존 태그·필드·둘 다 불일치로 분류합니다.
`evaluated = total + activity + consent + tag + field + both`이며 각 사유는 중복되지 않습니다.
선택하지 않은 활동·동의 조건의 응답 키는 생략하고 합계에서 0으로 취급합니다.
요약과 최대 50명의 샘플은 같은 SQL 문장에서 읽고 0명 결과도 요약을 유지합니다.
기간 없는 기존 요청과 일반 목록의 응답 형태·커서 계약을 유지합니다.

화면은 목적과 기록 상태를 별도로 선택하게 하고, 목적을 지우면 상태도 지웁니다.
설명은 댓글 연락처에 직접 기록된 상태이며 DM 동의·발송 가능 여부를 뜻하지 않는다고 명시합니다.
미리보기는 연락처 편집값을 바꾸지 않고 조건 변경·세션 초기화 후 늦은 응답을 버립니다.
동의 제외 수가 누락되거나 정수 문자열이 아니거나 합계가 맞지 않으면 이전 결과를 지우고 재시도를 안내합니다.

## 성공 기준과 경계

1. API 검증 → 유효한 쌍과 큰 정수 제외 수를 보존하고 잘못된 쌍·중복·저장 필터 혼합을 400으로 거절합니다.
2. 실제 DB → 세 상태·두 목적·다른 계정/작업 공간·숫자가 같은 DM 식별자를 구분하고 기간/태그/필드 결합·재동의·페이지 경계를 확인합니다.
3. 마이그레이션 → 047의 기존 행 보존·반복 실행·쌍과 enum 제약을 검사하고 제한된 서버 역할로 저장·조회·보관을 실행합니다.
4. 브라우저 → 세 상태 선택·저장/복원·보관·실패 보존·0명·늦은 응답·모바일 폭과 실제 표시 문구를 확인합니다.
5. 비용 → 실제 목록 SQL의 합성 데이터 실행계획을 기록하며 페이지 크기로 전체 분류 비용이 제한된다고 주장하지 않습니다.

운영 DB는 전체 실행기로 migration 047을 적용한 뒤 새 코드를 배포해야 합니다.
운영 적용·배포·실발송은 이번 PR의 범위가 아닙니다.
이 PR은 DM 동의 조건·식별자 연결·동의 기록 수정·새 전송 guard·캠페인 대상 고정·#26 전체 완료를 포함하지 않았습니다.
DM 동의 조건은 아래 [DM 동의 기록](#dm-동의-기록)에서 별도로 추가했습니다.
관련 Oracle 선례는 `[no precedent found]`입니다.

## DM 동의 기록

2026-10-18에 [#26](https://github.com/AndrewDongminYoo/auto-chatter/issues/26)의 일부로 댓글 연락처를 확인된 DM 대화의 동의 기록으로 거르는 조건을 추가했습니다.
DM 조건은 두 PR로 나눕니다.
이 PR은 DM 동의 기록이며, 최근 N일 안에 받은 DM으로 거르는 DM 활동은 후속 범위입니다.

### 확인된 DM 대화

- 연락처 상세가 대화로 표시하는 DM 상대만 사용합니다.
  `src/app/inbox-identity.ts`의 `verifiedDmRecipientsSql` 하나를 연락처 상세와 이 조건이 함께 사용합니다.
- DM 상대는 같은 작업 공간·연결에서 다음을 모두 만족할 때 확인된 대화입니다.
  - 그 상대에게 `sent` 상태이고 제공자 메시지 ID가 있는 비공개 답장이 있습니다.
  - 그 상대의 모든 후보 답장이 이 댓글 참여자 한 명에게서 나왔습니다.
    다른 참여자의 오래된 답장이 하나라도 있으면 모호하므로 제외합니다.
  - 후보 중 하나 이상은 연결의 받은 메시지함 활성화 시각(`inbox_enabled_at`) 이후에 보냈습니다.
  - 상대 ID가 `^[0-9]{1,40}$`이고 그 상대의 DM이 하나 이상 저장되어 있습니다.
- 받은 메시지함을 켠 적이 없는 연결에는 새 근거가 없으므로 그 연결의 연락처에는 확인된 DM 대화가 없습니다.
- 다른 연결·작업 공간의 같은 숫자 ID와 비교하지 않으며, 댓글 참여자 ID와 같은 숫자의 DM 상대 기록도 옮기지 않습니다.
- 이 연결은 참고용입니다.
  전송 guard의 더 넓은 연결(`deliveryRecipientOptedOut`)은 바뀌지 않으며 발송 판단의 유일한 기준으로 남습니다.

### 조건과 일치

- `dm_consent_purpose=service_reply|marketing`과 `dm_consent_state=granted|revoked|no_record`를 함께 지정합니다.
  검사 규칙과 오류 코드(`400 invalid_contact_consent`)는 댓글 동의 기록 쌍과 같습니다.
- 확인된 DM 대화 중 하나 이상이 그 목적에 대해 `dm_recipient`의 현재 `decision=grant`(`granted`)나 `decision=revoke`(`revoked`)를 가지거나 현재 행이 없으면(`no_record`) 일치합니다.
  `all` 철회는 기존 투영대로 두 목적의 철회로 비교합니다.
- 확인된 DM 대화가 없는 연락처는 어떤 상태에도 일치하지 않으며 `no_record`로 세지 않습니다.
- 계정·활동 기간·댓글 동의 기록과 같이 태그/필드 AND·OR와 별도인 AND 제한입니다.
  `contact_segment_condition_operator`와 마이그레이션 056·057은 바꾸지 않습니다.
- `segment_id`와 수동 DM 동의 키를 한 요청에서 섞으면 `400 invalid_contact_request`입니다.
- 목록·미리보기·세그먼트·CSV 응답에는 DM 상대 ID가 없으며 CSV v1 열은 그대로입니다.
- 기록된 상태를 읽어 거르기만 합니다.
  발송 가능 여부를 증명하지 않고, 식별자를 합치지 않으며, 동의를 기록하지 않고, 전송 guard를 바꾸지 않습니다.

### 미리보기 제외 사유

- 순서는 `excluded.activity`(기간 지정 시), `excluded.consent`(댓글 동의 지정 시), `excluded.dm_identity`(DM 동의 지정 시 확인된 DM 대화 없음), `excluded.dm_consent`(확인된 대화가 있지만 어느 것도 요청한 상태가 아님), 기존 태그·필드·둘 다 분류입니다.
- 각 사유는 겹치지 않고 `evaluated = total + 표시된 모든 제외 수`입니다.
  선택하지 않은 조건의 키는 생략하며 0명 결과도 요약을 유지합니다.
- 화면은 두 사유를 "확인된 DM 대화 없음"과 "DM 동의 기록 조건 불일치"로 표시하고 합계 검사에 포함합니다.

### 저장과 마이그레이션 058

- 마이그레이션 `058_segment_dm_consent.sql`은 nullable `dm_consent_purpose`·`dm_consent_state` 열과 쌍·허용 값 CHECK(`contact_segment_dm_consent`)를 추가합니다.
  추가만 하며 전체 실행기가 다시 적용해도 같은 결과입니다.
  권한은 테이블 단위라 바꾸지 않고, 작업 공간 내보내기는 테이블 전체 열을, 삭제 함수는 행 전체를 다루므로 바꾸지 않습니다.
- 생성·수정은 같은 파서로 쌍을 받고, 응답은 쌍이 있을 때만 두 키를 포함합니다.
  수정의 변경 없음 검사에 두 열을 포함합니다.
- 목록·미리보기·`segment_id` 조회·세그먼트 CSV 내보내기가 같은 술어(`segmentConditionSql`의 `$16`·`$17`)를 사용합니다.
  내보내기의 배치 크기와 시계 위치는 술어 값 개수에서 계산합니다.
- 운영 DB는 전체 실행기로 migration 058을 적용한 뒤 새 코드를 배포해야 합니다.

### 비용과 비목표

- DM 동의 조건이 있을 때만 한 문장 안에서 선택 계정의 모든 후보 답장을 연결·받는 사람별로 한 번 묶고(`dm_verified`), 연락처는 그 결과와 비교합니다.
  비용은 선택 계정의 후보 답장 수와 연락처 수에 비례합니다.
  합성 데이터의 측정은 [검증 노트](../notes/2026-10-18-segment-dm-consent-verification.md)에 기록하며 페이지 크기로 비용이 제한된다고 주장하지 않습니다.
- DM 활동, 중첩 조건 언어, 발송 대상 지정, 캠페인, 새 전송 guard, 식별자 병합, 동의 기록 쓰기, 전송 쪽 동의 연결 변경은 포함하지 않습니다.
