# 인박스 상담 전환과 자동화 중지

## 목적과 범위

[식별자 계약](2026-09-27-inbox-handoff-contract.md)을 실제 서버 상담 전환으로 구현합니다.
[수동 답장 #18](https://github.com/AndrewDongminYoo/auto-chatter/issues/18)의 선행 PR이며 수동 발송 outbox·워커·발신 이력·UI·배포·실계정 발송은 포함하지 않습니다.

## 상태와 API

대화 키는 `(workspace_id, connection_id, recipient_id)`입니다.
`GET /api/connections/:connectionId/inbox/:recipientId/handoff`는 저장된 대화 또는 기존 상담 전환의 `active`·`version`을 읽습니다.
상담 전환이 없으면 버전 0의 비활성 상태입니다.
확인된 이메일 세션·작업 공간 멤버십·연결 소유권이 필요하며 본문과 토큰은 반환하지 않고 캐시하지 않습니다.

같은 경로의 `PUT`은 정확히 `active`와 `expected_version`을 받습니다.
상태가 바뀔 때 버전을 증가시키고 이전 버전의 상반된 요청은 409 `handoff_conflict`로 거부합니다.
같은 운영자의 직전 변경을 동일 버전·목표 상태로 반복하면 추가 변경과 감사 행 없이 같은 결과를 반환합니다.

시작은 현재 `verified` 문맥만 허용합니다.
`unmapped`·`stale`·`ambiguous`는 409 `handoff_identity_unverified`이며 댓글 작성자를 추정하지 않습니다.
시작 시 확인한 댓글 작성자와 근거 outbox ID를 보관합니다.
재개는 이 보관한 작성자에서 상담 전환 사유만 해제하므로 이후 연결 근거가 오래되거나 충돌해도 가능합니다.
수신 기록이 삭제됐어도 소유한 기존 상담 전환은 종료할 수 있습니다.

## 독립적인 중지 사유

기존 `instagram_contact_automation.paused`는 사용자 직접 중지로 유지합니다.
새 `handoff_paused`는 해당 작성자에 연결된 활성 상담 전환이 하나라도 있을 때 참입니다.
둘 중 하나라도 참이면 자동 발송을 중지합니다.
상담 전환은 직접 중지를 덮어쓰지 않으며 대화 하나를 재개해도 다른 대화의 상담 전환 사유는 유지합니다.

연결 행 잠금으로 상담 전환 트랜잭션을 직렬화합니다.
대화 상태·댓글 작성자별 상담 중지 사유·감사 행은 하나의 트랜잭션에서 갱신합니다.
재시작 때 작성자 근거가 달라졌다면 이전 작성자와 새 작성자의 활성 사유를 함께 계산합니다.
기존 연락처 재개 요청은 상담 전환이 활성화된 동안 409 `handoff_active`로 거부하며 직접 중지 값을 변경하지 않습니다.
이는 기존 화면이 상담 중인 연락처를 재개됐다고 안내하지 않도록 하는 서버 경계입니다.

## 발송 경계와 감사

첫 댓글 DM·팔로우 답장의 claim·검증 후 확인·공급자 POST 직전·크론 알림 모두 두 중지 사유를 확인합니다.
상담 전환 중 수신한 확인 응답의 receipt는 기존 직접 중지와 같은 재실행 방지 규칙을 따릅니다.
재개는 `unknown`·실패·차단 행을 초기화하거나 이미 지났던 응답 창을 연장하지 않습니다.
최종 검사 이후 공급자 POST에 들어간 요청은 취소할 수 없습니다.
대화 담당자와 열림·완료 상태([#22](2026-10-01-inbox-conversation-assignment.md))는 상담 전환과 독립적이어서, 배정·완료·다시 열기가 상담 전환이나 자동화 중지를 바꾸지 않습니다.

상태 변경마다 운영자 ID·시각·시작/재개 사유·버전·확인한 작성자·근거 ID·변경 전 직접 중지·상담 중지와 변경 후 상담 중지를 기록합니다.
감사 테이블은 서버도 UPDATE·DELETE할 수 없으며 API 역할은 모든 접근이 금지됩니다.
새 테이블의 RLS를 켜고 서버만 필요한 SELECT·INSERT·UPDATE를 허용하며 기존 역할의 권한을 넓히지 않습니다.
관리자 수동 삭제는 감사 행과 상담 전환 행을 관련 outbox·연결보다 먼저 삭제합니다.

## 수용 기준

- 다른 사용자·작업 공간·계정의 대화를 시작하거나 재개하지 않습니다.
- 미확인·오래된·충돌 근거를 시작에 사용하지 않습니다.
- 시작·재개의 반복과 오래된 버전의 반대 요청을 구분합니다.
- 직접 중지를 보존하고 대화 두 개 중 하나만 재개해도 다른 사유를 유지합니다.
- 근거 변화 이후 재개와 동시 시작·재개를 확인합니다.
- 두 자동화의 claim 및 발송 직전과 크론이 상담 중지를 읽습니다.
- 감사 기록의 수정·삭제와 API 역할의 읽기를 금지하고 마이그레이션 재실행을 확인합니다.
