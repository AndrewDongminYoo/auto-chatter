# 최근 댓글 저장 활동 조건

## 범위

[#26](https://github.com/AndrewDongminYoo/auto-chatter/issues/26)의 상대 활동 조건을 추가합니다.
연락처의 계정·작성자별 가장 최근 `instagram_comment_events.created_at`을 사용하며 Instagram 작성 시각이나 DM 활동을 추정하지 않습니다.
고정 UTC 기간·태그/필드 AND/OR·동의 기록 조건은 기존 계약을 유지합니다.

## 시간 계약

`last_comment_days`는 1~366의 정수이며 최근 N×24시간을 뜻합니다.
GET query는 앞자리 0 없는 십진수 문자열, 세그먼트 생성 JSON은 정수만 받습니다.
생략 또는 생성의 null은 상대 조건 없음이며 고정 `last_comment_from`·`last_comment_before`와 동시에 사용할 수 없습니다.
`segment_id`와 직접 조건의 혼합도 거절합니다.
유효하지 않은 일수나 혼합 조건은 400 `invalid_contact_activity` 또는 기존 혼합 요청 오류입니다.

한 조회 SQL의 `statement_timestamp()`를 한 번 정해 `as_of`로 사용합니다.
구간은 `[as_of - N×24시간, as_of)`이며 시작은 포함하고 조회 시각과 미래는 제외합니다.
일광 절약 시간이나 작업 공간·브라우저 시간대에 따라 길이가 바뀌지 않습니다.
가장 최근 저장 댓글이 구간에 있어야 하므로 구간 안 과거 댓글과 구간 밖 최신 댓글이 함께 있으면 제외합니다.
댓글 수·첫 댓글 시각은 기간으로 잘라내지 않습니다.

일반 조회의 결과와 미리보기 전체 수·제외 수·예시는 같은 SQL의 기준 시각을 사용합니다.
상대 조건 응답에는 실제 사용한 UTC 경계 `activity_window: {from,before}`를 마이크로초 문자열로 포함하며 빈 결과도 경계를 반환합니다.
조건을 저장할 때는 일수만 보관하며 조회할 때마다 다시 계산합니다.
다음 페이지 요청도 새로 계산하며 커서는 기존 계정·작성자 순서입니다.
페이지 전체를 동일 시점으로 고정한 스냅샷은 아니므로 시간 경과와 새 댓글로 이후 페이지의 대상이 바뀔 수 있습니다.
재현할 고정 기간이 필요하면 기존 UTC 기간 조건을 사용합니다.

## 달력 기간

2026-10-17에 세 번째 활동 조건 `last_comment_period`를 추가했습니다.
값은 `today`·`yesterday`·`this_month`·`last_month` 네 문자열뿐이며 주 단위는 시작 요일이 모호해 제외합니다.
GET query의 빈 값과 생략, 세그먼트 JSON의 생략과 `null`은 달력 조건 없음입니다.
JSON의 빈 문자열과 다른 값은 400 `invalid_contact_activity`입니다.
고정 UTC 기간·최근 일수와 동시에 사용할 수 없고 혼합하면 400 `invalid_contact_activity`이며, `segment_id`와 직접 조건의 혼합도 기존처럼 거절합니다.

한 조회 SQL이 `statement_timestamp()`로 `as_of`를 한 번 정하고, 같은 문장에서 호출자 작업 공간의 `workspaces.time_zone`을 읽습니다.
`as_of AT TIME ZONE time_zone`으로 현지 시각을 구하고 `date_trunc`와 하루·한 달 간격으로 현지 경계를 계산합니다.

| 값           | 현지 구간                            |
| ------------ | ------------------------------------ |
| `today`      | `[오늘 0시, 다음 날 0시)`            |
| `yesterday`  | `[어제 0시, 오늘 0시)`               |
| `this_month` | `[이번 달 1일 0시, 다음 달 1일 0시)` |
| `last_month` | `[지난달 1일 0시, 이번 달 1일 0시)`  |

각 현지 경계는 `<현지 시각> AT TIME ZONE time_zone`으로 UTC 시각으로 되돌리며 애플리케이션에서 시간을 계산하지 않습니다.
일광 절약 시간 처리는 PostgreSQL의 규칙을 따릅니다.
존재하지 않는 현지 시각에는 바뀌기 전의 UTC 오프셋을 적용하므로, 0시에 시계가 앞당겨지는 날의 0시는 그날의 첫 실제 시각이 됩니다.
예를 들어 `America/Santiago`의 2026-09-06 0시는 없으며, 이날의 `today`는 `[2026-09-06T04:00Z, 2026-09-07T03:00Z)`인 23시간입니다.
시계가 되돌아가는 날은 25시간이 될 수 있으며, `America/Los_Angeles`의 2026-11-01은 `[07:00Z, 다음 날 08:00Z)`입니다.
두 경우 모두 DB 테스트로 확인했습니다.

`today`와 `this_month`처럼 진행 중인 기간도 끝은 `as_of`가 아니라 기간의 끝입니다.
댓글 저장 시각은 열 기본값 `now()`이고 문장이 시작된 뒤 커밋된 댓글은 그 문장에 보이지 않으므로, 끝을 `as_of`로 자르지 않아도 수집한 댓글에 대한 결과가 같습니다.
가장 최근 저장 댓글을 판정하는 규칙, 미리보기의 제외 순서(활동, 동의, 태그/필드), 요청마다 다시 계산하는 규칙은 최근 일수와 같습니다.
작업 공간 시간대를 바꾸면 저장된 달력 조건도 다음 조회부터 바뀐 시간대로 계산합니다.

달력 조건을 사용한 목록·미리보기 응답은 `activity_window: {from, before, time_zone}`을 포함합니다.
`from`·`before`는 최근 일수와 같은 마이크로초 UTC 문자열이고 `time_zone`은 계산에 사용한 시간대이며, 빈 결과에도 포함합니다.
최근 일수 응답의 `activity_window`는 `{from, before}` 그대로이고, 활동 조건이 없는 응답에는 새 키가 없습니다.

세그먼트는 migration 055의 nullable `last_comment_period` 열에 값만 저장합니다.
`contact_segment_calendar_period` 제약은 네 값만 허용하며, 고정 기간·최근 일수와 함께 저장하는 행을 거부합니다.
053의 제약(최근 일수와 고정 기간 동시 사용 금지)과 함께 세 형태 중 하나만 있거나 아무것도 없는 행만 허용합니다.
생성·수정·목록 응답은 값이 있을 때만 `last_comment_period`를 포함하며 기존 세그먼트는 키를 생략합니다.
이 열은 기존 세그먼트의 내보내기·삭제 범위를 그대로 따르며 내보내기 열 목록을 고정한 검사는 없습니다.
화면은 활동 기간 방식에 달력 기간을 추가하고 네 기간을 오늘·어제·이번 달·지난달로 표시하며, 응답의 시간대와 UTC 경계를 상태 문구에 보여 줍니다.
기존 DB는 코드 배포 전에 migration 055를 전체 `deploy/migrate-multi-user.sql` 실행기로 적용해야 합니다.

## 권한과 화면

기존처럼 상담원은 목록·미리보기를 조회하고 관리자만 필터를 저장·보관합니다.
DB에는 nullable 정수 일수와 1~366 범위·고정 기간 동시 사용 금지 제약을 추가합니다.
기존 행과 응답은 조건 없음으로 유지합니다.
이 컬럼은 기존 세그먼트의 내보내기·삭제 범위를 그대로 따릅니다.

화면에서 고정 UTC 기간과 최근 일수를 구분해 선택합니다.
최근 일수는 1~366일이며 매번 다시 계산되는 24시간 단위임을 설명합니다.
미리보기에는 실제 UTC 경계를 표시하고 `excluded.activity`를 기존 우선 제외 사유로 검증합니다.
저장·선택·보관 후 직접 조건 전환에서 일수를 보존합니다.
조건 변경·세션 초기화는 이전 미리보기를 무효화하며 늦은 응답과 연락처 편집 보호는 기존 계약을 유지합니다.

## 검증과 제한

정확한 cutoff·직전·as_of·미래, 최신 댓글·동일 sender의 다른 계정·작업 공간 격리·AND/OR·동의와 제외 합계를 검사합니다.
제어된 DB 테스트의 시계는 실제 집계 SQL에서 시각 함수만 고정하고, 별도 실제 시계 조회로 기준 시각이 요청 사이에서 갱신되는지도 검사합니다.
저장·복원·보관·잘못된 입력·레거시 응답·DB 제약·50/51명 페이지·빈 결과·마이그레이션·제한된 서버 역할을 확인합니다.
실제 브라우저로 최근 일수와 고정 기간 전환·미리보기·실패 입력 보존·초기화·모바일을 확인합니다.

기존 DB는 배포 전 migration 053을 전체 `deploy/migrate-multi-user.sql` 실행기로 적용해야 합니다.
운영 DB·배포·실제 Meta·운영 규모 성능과 #26 전체 완료는 이번 범위가 아닙니다.
Advisor의 단일 시각과 반열린 구간 제안을 적용했습니다.
Oracle의 `segment activity`·`relative time` 및 좁은 재검색 결과는 `[no precedent found]`이며 source commit `c1681868ac634e4b2414874716bb75a7864113c4`의 최신성은 미확인입니다.
