# 최근 댓글 저장 활동 조건

## 범위

[#26](https://github.com/AndrewDongminYoo/auto-chatter/issues/26)의 상대 활동 조건을 추가합니다.
연락처의 계정·작성자별 가장 최근 `instagram_comment_events.created_at`을 사용하며 Instagram 작성 시각이나 DM 활동을 추정하지 않습니다.
고정 UTC 기간·태그/필드 AND/OR·동의 기록 조건은 기존 계약을 유지합니다.

## 시간 계약

`last_comment_days`는 1~366의 정수이며 최근 N×24시간을 뜻합니다.
GET query는 앞자리 0 없는 십진수 문자열, 세그먼트 생성 JSON은 정수만 받습니다.
생략 또는 생성의 null은 상대 조건 없음이며 고정 `last_comment_from`·`last_comment_before`와 동시에 사용할 수 없습니다.
`segment_id`와 직접 조건의 혼합도 거절합니다.
유효하지 않은 일수나 혼합 조건은 400 `invalid_contact_activity` 또는 기존 혼합 요청 오류입니다.

한 조회 SQL의 `statement_timestamp()`를 한 번 정해 `as_of`로 사용합니다.
구간은 `[as_of - N×24시간, as_of)`이며 시작은 포함하고 조회 시각과 미래는 제외합니다.
일광 절약 시간이나 작업 공간·브라우저 시간대에 따라 길이가 바뀌지 않습니다.
가장 최근 저장 댓글이 구간에 있어야 하므로 구간 안 과거 댓글과 구간 밖 최신 댓글이 함께 있으면 제외합니다.
댓글 수·첫 댓글 시각은 기간으로 잘라내지 않습니다.

일반 조회의 결과와 미리보기 전체 수·제외 수·예시는 같은 SQL의 기준 시각을 사용합니다.
상대 조건 응답에는 실제 사용한 UTC 경계 `activity_window: {from,before}`를 마이크로초 문자열로 포함하며 빈 결과도 경계를 반환합니다.
조건을 저장할 때는 일수만 보관하며 조회할 때마다 다시 계산합니다.
다음 페이지 요청도 새로 계산하며 커서는 기존 계정·작성자 순서입니다.
페이지 전체를 동일 시점으로 고정한 스냅샷은 아니므로 시간 경과와 새 댓글로 이후 페이지의 대상이 바뀔 수 있습니다.
재현할 고정 기간이 필요하면 기존 UTC 기간 조건을 사용합니다.

## 권한과 화면

기존처럼 상담원은 목록·미리보기를 조회하고 관리자만 필터를 저장·보관합니다.
DB에는 nullable 정수 일수와 1~366 범위·고정 기간 동시 사용 금지 제약을 추가합니다.
기존 행과 응답은 조건 없음으로 유지합니다.
이 컬럼은 기존 세그먼트의 내보내기·삭제 범위를 그대로 따릅니다.

화면에서 고정 UTC 기간과 최근 일수를 구분해 선택합니다.
최근 일수는 1~366일이며 매번 다시 계산되는 24시간 단위임을 설명합니다.
미리보기에는 실제 UTC 경계를 표시하고 `excluded.activity`를 기존 우선 제외 사유로 검증합니다.
저장·선택·보관 후 직접 조건 전환에서 일수를 보존합니다.
조건 변경·세션 초기화는 이전 미리보기를 무효화하며 늦은 응답과 연락처 편집 보호는 기존 계약을 유지합니다.

## 검증과 제한

정확한 cutoff·직전·as_of·미래, 최신 댓글·동일 sender의 다른 계정·작업 공간 격리·AND/OR·동의와 제외 합계를 검사합니다.
제어된 DB 테스트의 시계는 실제 집계 SQL에서 시각 함수만 고정하고, 별도 실제 시계 조회로 기준 시각이 요청 사이에서 갱신되는지도 검사합니다.
저장·복원·보관·잘못된 입력·레거시 응답·DB 제약·50/51명 페이지·빈 결과·마이그레이션·제한된 서버 역할을 확인합니다.
실제 브라우저로 최근 일수와 고정 기간 전환·미리보기·실패 입력 보존·초기화·모바일을 확인합니다.

기존 DB는 배포 전 migration 053을 전체 `deploy/migrate-multi-user.sql` 실행기로 적용해야 합니다.
운영 DB·배포·실제 Meta·운영 규모 성능과 #26 전체 완료는 이번 범위가 아닙니다.
Advisor의 단일 시각과 반열린 구간 제안을 적용했습니다.
Oracle의 `segment activity`·`relative time` 및 좁은 재검색 결과는 `[no precedent found]`이며 source commit `c1681868ac634e4b2414874716bb75a7864113c4`의 최신성은 미확인입니다.
