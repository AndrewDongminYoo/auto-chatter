# 마지막 댓글 저장 기간 필터

## 문제와 범위

[#26](https://github.com/AndrewDongminYoo/auto-chatter/issues/26)의 활동 조건 중 마지막 댓글 저장 시각으로 연락처를 고르는 조건을 추가합니다.
현재 연락처의 `last_comment_at`은 `(connection_id, sender_id)`별 `max(instagram_comment_events.created_at)`입니다.
수신 저장 코드가 이 컬럼을 직접 지정하지 않으므로 DB가 댓글을 저장한 시각이며 Instagram에서 댓글을 작성한 시각이나 DM 활동 시각이 아닙니다.
기존 연락처 식별자·권한·태그·필드 조건을 유지합니다.

## 시간과 저장 계약

- 선택적인 `last_comment_from`과 `last_comment_before`는 함께 지정합니다.
  API는 `YYYY-MM-DDTHH:mm:ss.sssZ` 형태의 유효한 UTC 시각만 받으며 연도는 0001–9999입니다.
  시작은 종료보다 빨라야 합니다.
  하나만 지정하거나 유효하지 않은 날짜·시간대 오프셋·빈 문자열이면 400입니다.
  세그먼트 생성에서 둘 다 생략하거나 null이면 조건 없음입니다.
- 구간은 `[from, before)`입니다.
  시작 시각은 포함하고 종료 시각은 제외합니다.
  가장 최근에 저장된 댓글이 구간 안에 있어야 하며, 과거 댓글 하나가 구간 안에 있다는 이유만으로 포함하지 않습니다.
- 일반 목록·미리보기·저장된 세그먼트는 같은 활동 조건을 사용합니다.
  활동 조건은 계정 범위 및 태그/필드의 AND/OR 결과와 별도의 AND로 결합합니다.
  OR가 기간 밖 연락처나 다른 작업 공간을 포함하게 만들지 않습니다.
- 세그먼트의 두 `timestamptz` 컬럼은 nullable이며 둘 다 null이거나 유한한 오름차순 구간이어야 합니다.
  기존 세그먼트는 조건 없음으로 유지하고 응답에도 기간 키를 추가하지 않습니다.
  기간이 있으면 생성·목록 응답에 canonical UTC 문자열을 반환합니다.
  `segment_id`와 수동 기간 조건의 혼합은 거절합니다.
- 고정 시각을 저장하며 상대 일수·작업 공간 시간대 변환·예약은 추가하지 않습니다.
  새 댓글을 저장하면 같은 세그먼트를 다시 조회한 결과가 바뀔 수 있으므로 대상 고정은 아닙니다.

## 미리보기와 화면

`evaluated`는 기존처럼 작업 공간·선택 계정의 전체 댓글 연락처 수입니다.
기간 조건이 있으면 `excluded.activity`를 10진수 문자열로 추가합니다.
기간 밖 연락처는 태그·필드 상태와 관계없이 이 사유에 먼저 넣습니다.
기간 안 연락처는 선택한 [동의 기록 조건](2026-10-16-segment-consent-state.md)을 다음으로 판정하고, 이를 통과한 연락처를 태그만·필드만·둘 다 불일치로 나눕니다.
합계는 `evaluated = total + activity + consent + tag + field + both`이며 선택하지 않은 기간·동의 조건은 키를 생략하고 0으로 취급합니다.
모든 집계와 샘플은 같은 SQL 문장에서 읽으며 0명 결과·기존 커서 거절·정수 정밀도 계약을 유지합니다.

화면은 시작·종료 입력에 UTC를 명시하고 저장 시각의 의미와 포함 경계를 설명합니다.
브라우저나 작업 공간 시간대를 암묵적으로 적용하지 않습니다.
저장·선택·보관 후 수동 목록 전환에도 기간을 보존하고, 초안 변경은 이전 미리보기를 무효화합니다.
미리보기의 기간 제외 요약이 없거나 합계가 맞지 않으면 결과를 지우고 재시도를 안내합니다.
편집 중인 연락처와 늦은 응답 차단은 기존 계약을 유지합니다.

## 검증과 경계

구간 직전·시작·종료 직전·종료·이후, 반복 댓글의 최신 시각, 다른 계정의 동일 sender, 작업 공간 격리와 50/51명 페이지 경계를 실제 로컬 PostgreSQL에서 확인합니다.
태그/필드 AND·OR와 기간 제외 우선순위, 저장·복원·보관·최신 댓글 반영, 입력 검증, 마이그레이션 반복 실행과 DB 제약을 검사합니다.
제한된 서버 역할을 쓰는 workerd HTTP 경로와 실제 브라우저의 UTC 직렬화·복원·실패·무효화를 확인합니다.
합성 데이터의 실행계획으로 조건의 비용을 기록하며 운영 지연 시간은 보증하지 않습니다.

기존 DB에는 마이그레이션 046을 전체 실행기로 적용한 뒤 새 코드를 사용해야 합니다.
운영 DB 적용·배포·발송은 이번 PR에 포함하지 않습니다.
DM 동의·DM 활동·상대 기간·다중 활동 조건·캠페인 대상 고정과 #26 전체 완료는 후속 범위입니다.
관련 Oracle 선례는 `[no precedent found]`이며 시간 의미론은 현재 코드와 이 계약에 근거합니다.
