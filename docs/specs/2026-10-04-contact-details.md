# 댓글 연락처 상세 조회

## 범위

[#25](https://github.com/AndrewDongminYoo/auto-chatter/issues/25)의 읽기 전용 하위 범위입니다.
기존 댓글 연락처 카드에 상세 보기를 더하고, 태그·활성 필드·중지 사유·현재 동의 기록·확인된 저장 DM 대화 요약을 함께 조회합니다.
[#17](https://github.com/AndrewDongminYoo/auto-chatter/issues/17)과 [#27](https://github.com/AndrewDongminYoo/auto-chatter/issues/27)은 열린 상태이며, 이 변경으로 #25 전체를 완료 처리하지 않습니다.
식별자 병합·분리, 원장 재계산, CSV 가져오기·내보내기, 동의 쓰기, 스키마 변경과 발송은 포함하지 않습니다.

## 읽기 계약

`GET /api/connections/:connectionId/contacts/:senderId`는 기존 태그 수정 경로의 GET입니다.
연결은 UUID, 댓글 작성자는 숫자 1–40자이며, query는 선택적인 `after` 하나만 허용합니다.
확인된 이메일의 인증 세션과 활성 `agent` 이상 멤버십이 필요합니다.
멤버십과 모든 상세 데이터는 하나의 `REPEATABLE READ READ ONLY` 트랜잭션에서 읽습니다.
스냅샷 이후의 변경은 다음 조회에 반영되며, 조회가 중지·동의 상태나 발송 권한을 고정하지 않습니다.
연결이 다른 작업 공간에 있거나 해당 연결에 작성자의 저장 댓글이 없으면 똑같이 `404 contact_not_found`입니다.
본문 응답은 `Cache-Control: no-store`입니다.

- 연락처 키, 연결 계정의 사용자 이름, 첫·최근 댓글 저장 시각, 댓글 수와 태그를 반환합니다.
- 활성 필드의 ID·이름·자료형·저장 값을 반환합니다. 미설정은 `null`이고 `0`, `false`, 빈 텍스트는 값입니다. 보관 필드는 제외합니다.
- `automation`은 합성된 `paused`와 원인인 `manual_paused`, `handoff_paused`를 따로 반환합니다.
- 댓글 연락처의 `consent`는 해당 작업 공간·연결·Instagram·`comment_sender`·작성자에만 적용되는 현재 `channel_consent_state`입니다. 각 대화의 동의는 해당 `dm_recipient` 범위에만 속합니다.
- 동의 항목은 목적·결정·근거 종류·근거 발생 시각·서버 기록 시각·마지막 이벤트 ID만 제공합니다. `all` 철회는 기존 원장이 투영한 두 목적의 철회로 보입니다. 근거 참조 텍스트, 운영자 ID, 이벤트 원문은 반환하지 않습니다.
- 대화 요약은 상대 ID·근거 답장 ID·수신 메시지 수·마지막 메시지 ID·첫/최근 수신 시각·열림/종료 상태·상담 전환 여부를 반환합니다. 큰 정수 ID와 집계 수는 문자열을 유지합니다.

댓글/DM 원문·발송 문구·자격 증명·상담 메모·개인 리마인더는 조회 결과에 포함하지 않습니다.
동의 기록의 부재는 허가가 아니며, 한 식별자의 동의가 연결된 다른 식별자에 옮겨 가지 않습니다.
화면의 기록은 현재 발송 가능 여부를 계산한 결과가 아닙니다.

## DM 연결 근거와 페이지

[기존 인박스 문맥 계약](2026-09-27-inbox-handoff-contract.md)의 공급자 확인 후보 SQL을 공통으로 사용합니다.
같은 작업 공간·연결에서 성공 상태, 공백이 아닌 공급자 메시지 ID, 미래가 아닌 발송 기록 시각, 원본 댓글 작성자 일치를 모두 확인합니다.
각 DM 상대의 **모든 후보**를 먼저 묶고 서로 다른 작성자가 한 명인지 판정한 뒤 선택한 연락처와 비교합니다.
다른 작성자의 오래된 후보도 충돌로 남습니다. 최근 후보만 보거나 선택한 작성자만 먼저 거르지 않습니다.
현재 인박스 보관 시작 시각 이후의 근거가 하나 이상 있고, 저장된 인박스 메시지도 있는 대화만 반환합니다.
댓글 ID와 DM ID의 숫자 또는 계정 이름이 같다는 이유로 연결하지 않습니다.
오래된·모호한·확인되지 않은 상대 ID나 근거 ID는 상세 결과에 노출하지 않습니다.

대화는 상대 ID의 텍스트 오름차순으로 한 번에 50개입니다.
`after`는 작업 공간·연결·댓글 작성자·마지막 상대 ID를 담은 base64url JSON이며 다른 조회 범위에 재사용하면 거절합니다.
커서는 소유권 증명이 아니고, 모든 페이지에서 멤버십·소유권·전체 연결 근거를 다시 확인합니다.
현재 SQL은 해당 연결의 근거를 집계하므로 페이지 제한이 전체 근거 스캔량을 제한하지는 않습니다.
한 연락처의 여러 페이지는 서로 다른 시점의 스냅샷입니다. 화면의 다음 페이지는 이전 대화 결과를 교체하며, 첫 페이지는 상세 새로고침으로 돌아갑니다.

## 화면

기존 목록과 편집기를 유지하고 카드 안에 키보드로 여는 `details`를 추가합니다.
사용자가 펼칠 때만 상세를 요청하고, 별도 새로고침과 다음 대화 버튼을 제공합니다.
태그·필드 편집 중인 DOM과 값은 상세 조회로 바꾸지 않습니다.
불러오기·오류·빈 결과는 한국어로 안내하고, 모든 저장 텍스트는 `textContent`로 표시합니다.
접기·다시 열기·목록 세대 변경·로그아웃 뒤 늦게 도착한 응답은 버립니다.
화면은 현재 확인된 저장 대화만 보인다는 범위를 명시하며, 빈 결과를 전체 이력 부재라고 표현하지 않습니다.
