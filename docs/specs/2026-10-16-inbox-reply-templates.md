# 인박스 답장 텍스트 템플릿

## 범위와 권한

[#24](https://github.com/AndrewDongminYoo/auto-chatter/issues/24)의 첫 단계로 작업 공간별 텍스트 템플릿을 제공합니다.
관리자·소유자가 만들고 수정·보관하며 상담원 이상은 활성 템플릿을 읽고 미리보기할 수 있습니다.
이 템플릿은 Meta 승인 템플릿이 아니며 발송 가능 여부·답장 창·동의를 바꾸지 않습니다.
기존 수동 작성기의 명시적 접수와 최종 발송 검사는 유지합니다.
예약 시각·자동 발송·다른 채널·#24 전체 완료는 포함하지 않습니다.

## 저장과 변수

- 템플릿은 작업 공간·이름·본문·버전·생성/수정 시각과 작성자·보관 상태를 저장합니다.
  이름은 NFC·trim 후 최대 60자이며 활성 이름은 대소문자를 구분하지 않고 유일합니다.
  작업 공간당 활성 템플릿은 최대 50개입니다.
  생성은 작업 공간 잠금으로 한도를 직렬화하고 수정은 `expected_version`으로 오래된 덮어쓰기를 거절합니다.
  보관은 행을 삭제하지 않으며 다시 보관해도 결과를 유지합니다.
- 본문과 최종 렌더링 문구는 기존 작성기와 같은 JavaScript 문자열 길이 기준 최대 1,000입니다.
  빈 문구·NUL은 거절합니다.
  변수는 정확한 `{{name}}` 문법이며 이름은 영문 소문자로 시작하는 소문자·숫자·밑줄 최대 32자입니다.
  서로 다른 변수는 최대 10개이며 같은 변수는 여러 번 사용할 수 있습니다.
  중괄호 쌍 오류·중첩·지원하지 않는 표현식은 저장 전에 거절합니다.
- 변수 값은 상담원이 직접 입력합니다.
  연락처 필드·DM/댓글 식별자·개인정보를 자동 조회하거나 추정해서 채우지 않습니다.
  미리보기 요청은 저장된 활성 템플릿의 ID·예상 버전과 변수 값만 사용합니다.
  누락·공백뿐인 값·알 수 없는 키·문자열이 아닌 값·길이 초과는 거절합니다.
  한 번만 치환하므로 입력 값에 들어 있는 중괄호를 다시 실행하지 않습니다.
  결과는 텍스트로만 표시하며 HTML·코드·지시문으로 실행하지 않습니다.
- 미리보기와 적용은 원장·outbox·고객 기록을 쓰거나 메시지를 보내지 않습니다.
  입력 변수 값은 서버에 저장하지 않습니다.
  템플릿 본문 자체는 작업 공간 설정이므로 내보내기와 전체 작업 공간 삭제 대상입니다.
  템플릿이 남은 작업 공간은 빈 작업 공간으로 취급하지 않습니다.

## API와 화면

`GET/POST /api/inbox/reply-templates`는 활성 목록과 생성을 담당합니다.
`PATCH/DELETE /api/inbox/reply-templates/:id`는 수정과 보관을 담당합니다.
`POST /api/inbox/reply-templates/:id/preview`는 현재 활성 버전의 문구를 읽어 반환합니다.
모든 경로는 서버 세션·작업 공간 권한을 검사하며 변경 요청의 동일 출처 검사와 기존 요청 제한을 유지합니다.
다른 작업 공간의 ID는 404입니다.
미리보기 중 버전이 달라졌거나 보관됐다면 다시 선택하도록 안내합니다.

관리 화면은 이름·본문·변수 문법과 보관을 제공하고 실패 시 편집 내용을 유지합니다.
작성기는 템플릿 선택·변수 입력·미리보기·“작성 내용에 추가”를 분리합니다.
미리보기 성공 전에는 적용할 수 없으며, 적용은 기존 초안을 보존하여 줄바꿈 뒤에 추가합니다.
합친 문구가 1,000자를 넘으면 초안을 바꾸지 않습니다.
접수 중이거나 접수 여부 확인이 필요한 작성기는 템플릿 적용으로 고정된 요청을 바꾸지 못합니다.
변수·템플릿·대화·세션 변경은 이전 미리보기를 지우고 늦은 응답을 버립니다.
템플릿 적용은 조회 시점 문구의 복사이며 이후 템플릿 수정·보관은 이미 복사한 초안을 바꾸지 않습니다.

## 검증과 운영 경계

1. API/DB → 역할·작업 공간 격리·생성 한도 경쟁·중복 이름·수정 충돌·보관·변수 누락/중첩/길이·한 번 치환을 확인합니다.
2. 저장소 경계 → 마이그레이션 반복 실행·RLS·제한된 서버 역할·내보내기·전체 삭제·빈 작업 공간 이동 방지를 확인합니다.
3. 브라우저 → 미리보기와 실제 추가 문구 일치·초안 보존·접수 잠금·오류·지연 응답·대화 전환·로그아웃·모바일·키보드를 확인합니다.
4. 게이트 → 타입·단위·격리 DB·workerd·Trunk·독립 리뷰·현재 커밋의 CI와 코드/보안 리뷰를 확인합니다.

기존 DB는 전체 실행기로 migration 048을 적용한 뒤 새 코드를 사용해야 합니다.
운영 DB 적용·배포·실발송은 이번 PR에서 수행하지 않습니다.
Oracle의 좁은 프로젝트 검색은 `[no precedent found]`이며 확대 검색은 일부 메타데이터만 반환해 전체 선례 부재를 뜻하지 않습니다.
