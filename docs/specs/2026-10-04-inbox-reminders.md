# 인박스 리마인더

## 범위

[이슈 #23](https://github.com/AndrewDongminYoo/auto-chatter/issues/23)의 세 번째이자 마지막 부분(#23-C)입니다.
[검색·필터와 읽음 상태](2026-09-27-instagram-inbox.md#검색-필터와-읽음-상태)(#23-A)와 [라벨·내부 메모](2026-10-03-inbox-labels-notes.md)(#23-B) 위에, 멤버가 인박스 대화에 자기만 보는 리마인더를 두는 기능을 더합니다.
리마인더는 앱 안에서만 보입니다. 이메일·푸시·DM 등 어떤 외부 발송도 하지 않고, cron 단계도 없습니다.
migration 034가 테이블 둘과 삭제 함수 변경을 더하며, 운영 DB 적용과 배포는 이 PR의 범위가 아닙니다.
PR #135와 migration 034는 2026-10-04 `main` 커밋 `b1f5654`으로 운영 DB에 적용하고 배포했습니다([운영 기록](../notes/2026-09-26-cloudflare-runbook.md)). 운영에는 여러 멤버와 리마인더가 없어, 리마인더 배지·필터·편집 칸을 운영 데이터로 조작하지 않았습니다.

## 정한 값

운영자가 정하지 않은 값은 다음처럼 정했습니다.

| 항목                       | 값                                                              |
| -------------------------- | --------------------------------------------------------------- |
| 멤버·대화마다 진행 중 개수 | 1개                                                             |
| 기한                       | PostgreSQL `clock_timestamp()` 기준 1분 뒤부터 2,160시간 뒤까지 |
| 메모                       | 앞뒤 공백을 뺀 1–200자, 또는 없음                               |

90일은 세션 시간대의 일광 절약 시간 변경에 따라 길이가 달라지지 않도록 2,160시간으로 잽니다.
메모 글자 수는 PostgreSQL `length()`와 같은 코드 포인트 기준이며, 공백뿐인 메모는 메모 없음으로 저장합니다.

## 저장

- `instagram_inbox_reminders`: 작업 공간, 연결, DM 수신자, 만든 멤버(`creator_id`), 기한(`due_at`, UTC `timestamptz`), 메모, 상태(`pending`·`done`·`cancelled`), 취소 사유(`manual`·`conversation_closed`·`member_removed`, 취소일 때만), 버전, 만든 시각과 바뀐 시각을 저장합니다. `(connection_id, workspace_id)`는 `instagram_connections`를 참조합니다.
- 진행 중(`pending`) 리마인더는 `(workspace_id, connection_id, recipient_id, creator_id)`마다 하나뿐입니다(부분 고유 인덱스). 인박스 목록은 이 인덱스 덕분에 대화마다 호출자의 리마인더를 한 행만 붙입니다.
- `instagram_inbox_reminder_events`: 만들기, 기한·메모 변경, 완료, 취소마다 한 행씩 버전, 종류, 사유, 그 뒤의 기한과 메모, 실행한 멤버를 남기는 추가 전용 감사 기록입니다. 대화 완료와 멤버 제거로 생긴 자동 취소는 실행한 멤버가 없고(`NULL`), 직접 취소를 포함한 나머지는 모두 멤버를 남깁니다(CHECK 제약).

서버 역할은 리마인더를 SELECT·INSERT·UPDATE하고, 감사 기록은 SELECT·INSERT만 할 수 있습니다. 두 테이블 모두 DELETE 권한이 없고, 상태 변경은 UPDATE입니다. RLS가 켜져 있고 Supabase API 역할은 접근할 수 없습니다.
기한이 된 상태는 저장하지 않고 읽을 때 `status = 'pending' AND due_at <= now()`로 계산하므로, "알림 보냄" 같은 상태도 없습니다.

두 테이블은 모두 연결을 참조하므로 행이 있으면 그 작업 공간에 연결도 있습니다. 그래서 초대 수락의 작업 공간 이동 검사(`currentWorkspaceMovable`, `deploy/assign-workspace-owner.sql`)는 이미 있는 연결 검사로 두 테이블을 덮으며 바꾸지 않았습니다. migration 테스트가 두 외래 키를 확인합니다.

## 시간대

화면은 작업 공간 시간대의 날짜와 시각(`YYYY-MM-DDTHH:MM`)을 보내고, 서버는 쓰는 시점의 `workspaces.time_zone`으로 PostgreSQL에서 `due_local::timestamp AT TIME ZONE time_zone`을 계산해 `due_at`에 저장합니다.
나중에 작업 공간 시간대를 바꿔도 저장한 리마인더의 시각은 움직이지 않고, 새 시간대로 다시 표시만 합니다.
응답은 `due_at`과 함께 현재 작업 공간 시간대의 벽시계 값 `due_local`과 그 시간대 `time_zone`을 돌려줍니다.

일광 절약 시간이 바뀌는 날에는 PostgreSQL의 변환 규칙을 따르며, 테스트가 다음 값을 고정합니다.

| 시간대             | 입력               | 저장(UTC)           | 다시 표시          |
| ------------------ | ------------------ | ------------------- | ------------------ |
| `America/New_York` | `2026-03-08T02:30` | `2026-03-08T07:30Z` | `2026-03-08T03:30` |
| `America/New_York` | `2026-11-01T01:30` | `2026-11-01T06:30Z` | `2026-11-01T01:30` |
| `Europe/Berlin`    | `2027-03-28T02:30` | `2027-03-28T01:30Z` | `2027-03-28T03:30` |
| `Europe/Berlin`    | `2026-10-25T02:30` | `2026-10-25T01:30Z` | `2026-10-25T02:30` |

곧 시계를 앞당겨 건너뛴 시각은 바뀌기 전의 UTC 오프셋으로 읽어 한 시간 뒤의 벽시계 시각으로 저장하고, 시계를 되돌려 두 번 있는 시각은 나중 것(바뀐 뒤의 표준시)으로 저장합니다.
이는 플로의 [정한 시각까지 기다리기](2026-09-30-flow-runs.md)(`wait_until`)가 두 번 있는 시각에서 아직 지나지 않은 첫 번째를 고르는 것과 다릅니다. 리마인더는 지금 이후 가장 가까운 시각이 아니라 멤버가 고른 날짜의 시각이기 때문입니다.

## API

모든 요청은 상담원(`agent`) 이상이면 쓸 수 있고, GET이 아닌 요청은 같은 출처여야 합니다.
리마인더는 만든 멤버만 보고 바꿀 수 있습니다. 소유자와 관리자도 다른 멤버의 리마인더를 읽거나 바꿀 수 없고, 다른 멤버의 리마인더 ID는 없는 리마인더처럼 `404 reminder_not_found`를 받습니다.

| 요청                                                             | 동작                                                                                           |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `POST /api/inbox/conversations/:connection/:recipient/reminders` | `{due_local, note?}`로 만들기(`201`)                                                           |
| `PATCH /api/inbox/reminders/:reminder`                           | `{expected_version, due_local?, note?}`로 기한·메모 변경                                       |
| `POST /api/inbox/reminders/:reminder/complete`                   | `{expected_version}`으로 완료                                                                  |
| `POST /api/inbox/reminders/:reminder/cancel`                     | `{expected_version}`으로 취소(사유 `manual`)                                                   |
| `GET /api/inbox/reminders`                                       | 호출자의 진행 중 리마인더를 기한순으로 50개씩, `due=true`면 기한이 된 것만, `after`로 다음 쪽  |
| `GET /api/inbox`                                                 | 대화마다 호출자의 진행 중 `reminder`, `reminder=due` 필터, `due_reminder_count`와 `checked_at` |
| `GET /api/connections/:connection/inbox/:recipient`              | 메시지와 함께 그 대화의 호출자 `reminder`                                                      |

- 날짜·시각 형식이 틀리면 `400 invalid_reminder_due`, 기한이 1분 뒤부터 90일 안이 아니면 `400 reminder_due_out_of_range`, 메모가 200자를 넘으면 `400 invalid_reminder_note`, 그 밖의 요청 형식 오류는 `400 invalid_reminder_request`입니다.
- 대화에 보관한 DM이 하나도 없으면 `404 conversation_not_found`, 다른 작업 공간의 연결이면 `404 connection_not_found`입니다.
- 완료한 대화에는 리마인더를 만들 수 없습니다(`409 conversation_closed`). 그래서 완료한 대화에는 진행 중 리마인더가 없습니다.
- 진행 중 리마인더가 이미 있으면 `409 {error: "reminder_exists", reminder}`로 그 리마인더를 돌려주고, 화면은 새로 만드는 대신 그것을 바꿉니다.
- 버전이 다르면 `409 {error: "reminder_conflict", reminder}`로 현재 리마인더를 돌려줍니다. 버전이 같아도 이미 완료·취소한 리마인더면 `409 reminder_not_pending`입니다.
- `due_local`을 보내지 않은 변경은 기한을 다시 검사하지 않으므로, 기한이 지난 리마인더의 메모도 바꿀 수 있습니다. 기한과 메모가 그대로인 변경은 버전과 감사 행 없이 현재 리마인더를 돌려줍니다.

### 잠금 순서

쓰기는 [대화 상태 변경](2026-10-01-inbox-conversation-assignment.md#api)과 같은 순서로 작업 공간 행 `FOR SHARE`, 호출자의 멤버 행 `FOR SHARE`(제거 여부를 다시 확인), 연결 행 `FOR SHARE`, 대화별 advisory lock(`lockConversation`) 배타, 그 다음 리마인더 행 `FOR UPDATE`를 잡습니다.

- 대화 완료와 리마인더 쓰기는 대화 lock으로 줄을 섭니다. 커밋 전의 리마인더 만들기 뒤에 시작한 완료는 그 커밋을 기다렸다가 새 리마인더도 취소하고, 커밋 전의 완료 뒤에 시작한 만들기는 완료를 보고 `409 conversation_closed`로 거부됩니다.
- 멤버 제거는 그 멤버 행을 `FOR UPDATE`로 잠그므로, 그 멤버의 커밋 전 쓰기를 기다렸다가 새 리마인더까지 취소하고, 제거가 먼저 커밋되면 쓰기는 `403 workspace_required`로 끝납니다.
- 연결·사람 삭제가 먼저 시작되면 쓰기는 삭제가 커밋된 뒤 `404`로 끝나고, 쓰기가 먼저 시작되면 삭제가 그 커밋을 기다렸다가 새 행까지 지웁니다. 작업 공간 삭제와는 작업 공간 행에서 줄을 서므로 교착이 없습니다.
- 같은 멤버가 같은 대화에 동시에 두 번 만들면 두 번째는 첫 번째를 기다린 뒤 `409 reminder_exists`를 받습니다. 부분 고유 인덱스가 마지막 보호막입니다.

## 자동 취소

- 대화를 완료하면(`PUT .../state`에서 열림 → 완료) 같은 트랜잭션에서 모든 멤버의 그 대화 진행 중 리마인더를 취소하고(`conversation_closed`), 리마인더마다 감사 행을 하나 씁니다. 담당자만 바꾸는 변경은 취소하지 않습니다.
- 멤버가 다시 열거나 새 DM으로 다시 열려도(`auto_reopen`) 취소한 리마인더는 되살리지 않습니다. 다시 열린 대화에는 새 리마인더를 만들 수 있습니다.
- 멤버를 제거하면(`removeMember`) 같은 트랜잭션에서 그 멤버의 진행 중 리마인더를 모두 취소하고(`member_removed`), 응답에 취소한 개수(`cancelled_reminders`)를 담습니다.

## 인박스 목록

`GET /api/inbox?reminder=due`는 호출자의 진행 중 리마인더가 기한이 된 대화만 고르고, 상태·담당자·라벨·안 읽음·검색 필터와 커서와 함께 쓸 수 있습니다.
목록의 각 대화는 호출자의 진행 중 리마인더(`id`, `due_at`, `due_local`, `due`, `version`, `note`)를 담고, 없으면 `null`입니다. 다른 멤버의 리마인더는 붙지 않습니다.
응답의 `due_reminder_count`는 필터와 상관없이 그 작업 공간에서 기한이 된 호출자의 진행 중 리마인더 수이고, `checked_at`은 그 수를 센 서버 시각입니다.

## 화면

- 인박스 제목 옆 "리마인더" 버튼에 기한이 된 내 리마인더 수를 배지로 보이고, 하나 이상이면 강조합니다. 버튼을 누르면 기한이 된 대화만 보는 필터가 켜지고(`aria-pressed`), 다시 누르면 꺼집니다.
- 목록의 대화에 내 리마인더가 있으면 "리마인더 · 10월 5일 14:00"처럼 작업 공간 시간대의 시각을 칩으로 보이고, 기한이 되면 "리마인더 기한"으로 다른 모양이 됩니다.
- 대화를 열면 "내 리마인더" 칸(나만 보기)에서 작업 공간 시간대의 날짜·시각과 메모를 정해 저장하고, 바꾸고, 완료로 표시하거나 취소합니다. 새 리마인더의 기본값은 한 시간 뒤를 10분 단위로 올린 시각입니다. 날짜 입력은 1분 뒤부터 90일 뒤까지를 고르게 하지만, 3시간 안에 시계가 되돌아가면 두 번 있는 시각의 나중 것이 아직 오지 않았을 수 있으므로 최솟값을 되돌아가는 만큼 낮추고, 1분 하한은 서버가 실제 시각으로 확인합니다. 메모 글자 수를 코드 포인트로 세어 200자를 넘으면 요청을 보내지 않습니다. 완료한 대화에서는 입력이 막히고 다시 열면 정할 수 있다고 안내합니다.
- 편집을 시작하면 그때의 리마인더 버전을 기억해 저장할 때 `expected_version`으로 보냅니다. 편집하는 동안 대화를 다시 불러와 다른 화면이 바꾼 리마인더가 보여도, 저장은 덮어쓰지 않고 `409 reminder_conflict`를 받습니다.
- 같은 탭에서 관리자가 작업 공간 시간대를 바꾸면, 편집하던 리마인더는 이전 시간대로 고른 값이므로 지우고 안내합니다. 저장된 리마인더는 새 시간대로 다시 불러올 때까지 입력을 막고, 열린 대화와 목록을 다시 불러옵니다. 시간대를 바꾸기 전에 보낸 리마인더 쓰기의 응답이 나중에 도착하면, 그 응답의 리마인더는 이전 시간대의 값이므로 적용하지 않고 대화를 다시 불러옵니다. 다른 탭이나 기기에서 바꾼 시간대는 막지 못합니다. 대화를 다시 불러오면 저장된 리마인더만 새 시간대로 보이고, 리마인더가 없는 대화의 시간대 표시와 기본값, 이전 시간대로 고른 초안은 페이지를 새로 열 때까지 남습니다.
- 배지는 목록을 불러올 때 서버의 수로 바뀝니다. 화면이 열려 있는 동안 1분마다 이미 불러온 `due_at`으로 칩, 편집 칸의 기한 상태, 배지를 요청 없이 다시 그리고, 이때 배지에는 목록을 불러온 뒤 기한이 된 불러온 대화를 더합니다. 기기 시계 차이는 목록 응답의 `checked_at`으로 보정합니다.

화면 확인 기록은 [로컬 화면 검증](../notes/2026-10-04-inbox-reminders-ui-verification.md)에 있습니다.
