# 다중 사용자 Instagram 자동화

## 승인된 범위

운영자는 여러 사용자가 로그인하고 각자 Instagram 전문 계정을 연결하는 서비스 구현을 요청했습니다.
게시물별 댓글 키워드, 답장 문구, 활성화 상태와 팔로우 조건을 웹에서 편집합니다.
팔로우 조건은 댓글 → 확인용 첫 DM → 사용자의 응답 → 팔로우 확인 → 조건별 메시지 순서로 처리합니다.
단일 계정 운영자 전용 화면으로 제한하지 않습니다.

## 공급자 제약

2026-09-26 [Meta 프로필 조회 문서](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/messaging-api/user-profile/) 원문에서 `is_user_follow_business`와 프로필 조회 동의 조건을 확인했습니다.
댓글만 남긴 사용자는 조회 동의를 제공한 것이 아니며, DM 발신 등 문서의 조건을 충족한 사용자만 조회합니다.
[비공개 답장 문서](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/messaging-api/private-replies/)에 따라 첫 댓글 답장은 7일 이내 한 번이며, 추가 메시지는 상대방 응답 후 24시간 안에 보냅니다.
다른 사람이 소유·관리하는 전문 계정에 서비스를 제공하려면 Advanced Access가 필요합니다.
앱 게시 완료는 이 권한 심사 완료의 증거가 아닙니다.

## 사용자와 계정 격리

- Supabase Auth에서 검증된 사용자 ID를 서버에서 작업 공간 membership과 연결합니다.
- API의 모든 연결·규칙·발송 상태 조회 및 수정에는 검증된 작업 공간 조건을 적용합니다.
- Instagram 연결에는 OAuth state 검증, 사용자 세션 연결, 일회성 소비와 만료를 적용합니다.
- Instagram 토큰은 서버에서 암호화해 계정별로 저장하고 브라우저에 반환하지 않습니다.
- 공개 웹훅의 서명 검사는 기존처럼 유지하고 수신 계정 ID로 저장된 연결을 찾습니다.
- Queue에는 연결 ID만 전달하고 실제 계정·토큰·설정은 DB에서 조회합니다.
- DB의 익명·인증 사용자 직접 접근 금지는 유지합니다.

## 규칙 설정

첫 버전은 게시물 하나당 규칙 하나를 유지하고, 규칙 안에서 여러 키워드를 OR로 처리합니다.
키워드 비교 방식은 부분 일치와 전체 일치이며, 전체 댓글 모드도 제공합니다.
앞뒤 공백, 대소문자와 Unicode NFC를 정규화합니다.
편집 칸은 키워드를 한 줄에 하나씩 보여 주므로, 가운데에 줄바꿈(CR·LF)이 든 키워드는 저장 요청에서 `400 invalid_keywords`로 거부합니다([#144](https://github.com/AndrewDongminYoo/auto-chatter/issues/144)).
제외 키워드가 일치하면 포함 키워드보다 우선해 발송하지 않습니다.
정규식과 임의 스크립트는 지원하지 않습니다.
기존 단일 키워드 규칙은 동일한 부분 일치 동작을 유지합니다.

## 발송 케이스

| 상태                            | 동작                                                            |
| ------------------------------- | --------------------------------------------------------------- |
| 키워드 불일치·제외 키워드 일치  | 발송하지 않습니다.                                              |
| 규칙 비활성·연결 비활성         | 새 자동화를 시작하지 않습니다.                                  |
| 팔로우 조건 없음                | 설정한 첫 비공개 답장을 한 번 보냅니다.                         |
| 팔로우 조건 있음·사용자 응답 전 | 확인용 첫 DM만 보내고 기다립니다.                               |
| 사용자 응답·팔로우 확인됨       | 설정한 완료 메시지를 보냅니다.                                  |
| 사용자 응답·미팔로우 확인됨     | 설정한 팔로우 안내를 보내고 다음 명시적 확인 응답을 기다립니다. |
| 동의 없음·조회 실패·필드 누락   | 확인 불가로 기록하고 완료 메시지를 보내지 않습니다.             |
| 24시간 창 만료                  | 새 사용자 응답이 올 때까지 후속 자동 발송을 중단합니다.         |
| 발송 결과 불명확                | `unknown`으로 유지하고 자동 재발송하지 않습니다.                |

팔로우 확인 결과는 영구적인 속성으로 간주하지 않고 조건별 발송 시점에 다시 조회합니다.
규칙 변경이 이미 시작한 대화의 문구를 바꾸지 않도록 시작 시 설정을 고정하고, 현재 연결·규칙 비활성화는 발송 직전에 다시 확인합니다.
메시지 echo, 중복 메시지 ID, 계정 자신의 이벤트로 추가 자동 발송하지 않습니다.
이 팔로우 확인 흐름은 필요한 이벤트 ID·시각·확인 명령 일치 여부를 저장합니다.
확인용 첫 DM의 발송 결과가 기록되기 전에 도착한 확인 응답과 버튼 응답은 [발송 기록 전에 도착한 응답](2026-09-30-flow-runs.md#발송-기록-전에-도착한-응답)에 따라 발송 기록 뒤에 확인합니다.
별도 [수신 인박스](2026-09-27-instagram-inbox.md)를 켠 연결은 보관 시작 시각 이후의 텍스트 DM과 확인 버튼 응답을 승인된 수동 삭제 정책에 따라 보관합니다.

## 첫 버전의 비목표

팀 역할 편집, 공유 인박스, AI 답변, 결제, 다른 채널, 시각적 플로 편집기는 포함하지 않습니다.
팔로우 목록 스크래핑이나 댓글만으로 팔로우 여부를 추측하지 않습니다.
실계정 발송은 대상·문구·범위를 확인한 별도 검증으로 처리하며 개발 테스트에서 활성화하지 않습니다.

## Oracle 근거

개인 프로젝트 `auto-chatter`로 조회한 Oracle의 sourceCommit은 `c1681868ac634e4b2414874716bb75a7864113c4`입니다.
현재 Wiki HEAD와의 일치 여부는 확인하지 않았습니다.
`wiki/concepts/publish-failure-protocol.md`의 외부 작업 결과가 불명확할 때 자동 복구하지 않는 선례를 반영해 기존 `unknown` 자동 재시도 금지를 유지합니다.
이 선례는 일반 원칙이며 Instagram 전용 정책은 아닙니다.
`follow status`, `automation rules`의 프로젝트 전용 선례는 반환된 범위에서 찾지 못했습니다.
