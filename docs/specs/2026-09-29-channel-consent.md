# Instagram 채널 동의와 수신 거부 계약

## 적용 범위

현재 동의 원장은 Instagram 연결에만 기록할 수 있습니다.
기록의 범위는 작업 공간, 연결, 채널, 식별자 종류와 값, 목적의 조합으로 정해집니다.
댓글 작성자 ID와 DM 수신자 ID를 같은 값이라는 이유만으로 연결하지 않습니다.

`service_reply`는 기존 댓글 또는 수신 DM에 따른 답장의 수신 거부 상태를 나타냅니다.
수신 거부 기록이 없더라도 기존 댓글·DM 시간 창과 모든 발송 정책을 통과해야 합니다.
`marketing`은 별도 목적이며, 같은 범위에 명시적으로 기록된 동의가 없으면 허용하지 않습니다.
가져온 연락처 정보는 마케팅 발송 권한을 부여하지 않습니다.
현재 마케팅 일괄 발송 기능은 없습니다.

## 기록과 재동의

인증된 작업 공간 소유자는 같은 출처의 `POST /api/connections/:connectionId/channel-consent-events`로 자신이 소유한 Instagram 연결의 동의 이벤트를 기록합니다.
요청에는 UUID 형식의 `request_key`, `identity_kind`, `identity_value`, `purpose`, `decision`, `evidence_kind`, `evidence_reference`, `occurred_at`을 보냅니다.
같은 요청 키와 같은 내용의 재요청은 기존 이벤트를 반환하고, 다른 내용으로 키를 재사용하면 충돌로 거부합니다.
`purpose=all`은 철회에만 사용할 수 있습니다.
`service_reply`의 동의 기록은 `evidence_kind=explicit`일 때만 허용합니다.
댓글, 수신 DM 또는 가져온 자료를 명시적 재동의의 근거로 바꾸어 기록할 수 없습니다.

이벤트는 삭제하거나 덮어쓰지 않으며, 현재 상태는 이벤트를 기록한 트랜잭션에서 함께 갱신합니다.
`occurred_at`은 근거가 발생한 시각을 보관하지만 상태 적용 순서를 결정하지 않습니다.
더 나중에 서버에 기록된 명시적 재동의만 같은 범위의 철회를 해제합니다.

## 발송 경계

첫 비공개 답장, 팔로우 확인 뒤의 답장, 인박스 수동 답장은 대기 행을 처리할 때와 공급자에게 전송하기 직전에 수신 거부를 확인합니다.
댓글 작성자와 DM 수신자의 연결은 같은 작업 공간·Instagram 연결에서 공급자가 발송을 확인했고 댓글 이벤트의 작성자도 일치하는 과거 발송 행으로만 확인합니다.
확인된 수신자가 여러 명이면 모두 검사하며, 한 명이라도 철회했으면 발송하지 않습니다.
연결 근거와 현재 철회 상태는 하나의 DB 읽기에서 판단합니다.

철회로 막힌 자동 답장은 `blocked / recipient_opted_out` 상태로 남습니다.
수동 답장은 `failed / recipient_opted_out` 상태가 되며 안전한 재시도 대상으로 표시하지 않습니다.
재동의해도 이미 막힌 행을 자동으로 다시 보내지 않습니다.
동의 상태를 읽지 못한 발송 전 오류는 `pending / consent_unavailable`로 돌리고 나중에 다시 확인합니다.
마지막 확인 이후 공급자 요청이 시작되기 전의 짧은 간격에는 새 철회가 반영되지 않을 수 있습니다.

## 운영 상태

이 계약은 로컬 코드와 격리된 DB·Cloudflare 테스트로 검증했습니다.
2026-09-30 운영 DB에 migration 016을 적용하고 이 계약을 포함한 Worker를 배포했습니다. 적용 결과와 권한 조회는 [운영 적용 기록](../notes/2026-09-26-cloudflare-runbook.md)에 있습니다.
실제 Meta 발송, 사용자 대상 동의 설정 화면, DM 문구를 자동으로 수신 거부로 해석하는 기능은 이 범위에 포함되지 않습니다.
