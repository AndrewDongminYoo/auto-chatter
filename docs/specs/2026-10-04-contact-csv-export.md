# 관리자 연락처 CSV 내보내기

## 범위와 권한

[#25](https://github.com/AndrewDongminYoo/auto-chatter/issues/25)의 CSV **내보내기만** 구현합니다.
기존 [작업 공간 JSON 내보내기](2026-09-30-workspace-export.md)와 같은 소유자·관리자 권한입니다.
상담원은 직접 URL을 호출해도 거절합니다. 기존 JSON 내보내기는 그대로 유지합니다.
연락처 상세는 [PR #139](https://github.com/AndrewDongminYoo/auto-chatter/pull/139)로 이미 병합됐으며 이 CSV 변경에서 수정하지 않습니다.
이 내보내기 회차에는 CSV 가져오기·중복 검증·미리보기·식별자 병합/분리·동의 원장 변경을 포함하지 않았습니다.
후속 [태그 사전 검사](2026-10-17-contact-csv-preview.md)는 v1 파일의 기존 연락처 태그 교체 예상 결과만 읽기 전용으로 확인합니다.
#17·#27의 외부 검증과 #25의 전체 완료 조건은 열린 상태로 남습니다.

## 파일 범위와 형식 v1

작업 공간의 저장된 댓글 연락처 전체를 내보냅니다. 연결 해제한 계정도 포함합니다.
[저장된 세그먼트 내보내기](#저장된-세그먼트-내보내기)는 같은 형식으로 그 세그먼트가 고르는 연락처만 내보냅니다.
작업 공간·연결·댓글 작성자별 한 행이며 반복 댓글은 합칩니다. 다른 연결의 같은 작성자 ID는 별도 행입니다.
현재 화면의 50명 페이지·필터·저장 전 태그/필드 수정은 내보내기 범위에 영향을 주지 않습니다.
댓글·DM 원문 테이블, DM 연결 근거, 동의 근거, 자격 증명, 멤버·상담 메모·개인 리마인더는 제외합니다.
**활성 사용자 정의 필드에는 수집한 답장 등 개인정보가 들어 있을 수 있습니다.**

UTF-8 BOM을 한 번 붙이고, 모든 셀을 큰따옴표로 감싸 내부 큰따옴표는 두 번 쓰며, 쉼표와 CRLF로 구분합니다.
연락처가 없으면 같은 헤더만 반환합니다. 헤더는 아래 14개로 고정하며 필드 이름으로 동적 열을 만들지 않습니다.

| 열                          | 값                                                                         |
| --------------------------- | -------------------------------------------------------------------------- |
| `format_version`            | `1`                                                                        |
| `exported_at`               | 모든 행에 같은 트랜잭션 시각, UTC·마이크로초                               |
| `workspace_id`              | 호출자의 작업 공간 UUID                                                    |
| `channel`                   | `instagram`                                                                |
| `identity_kind`             | `comment_sender`                                                           |
| `connection_id`             | 연결 UUID                                                                  |
| `sender_id`                 | 댓글 작성자 문자열에 표시용 작은따옴표 하나를 덧붙인 값                    |
| `connection_username`       | 연결 계정 이름. 연락처의 프로필 이름이 아님                                |
| `first_comment_recorded_at` | 첫 댓글의 서비스 저장 시각, UTC·마이크로초                                 |
| `last_comment_recorded_at`  | 최근 댓글의 서비스 저장 시각, UTC·마이크로초                               |
| `comment_count`             | PostgreSQL이 반환한 십진수 문자열                                          |
| `automation_paused`         | 직접 중지 또는 상담 전환 중지이면 `true`, 나머지 `false`. 발송 자격이 아님 |
| `tags_json`                 | 문자열 배열 JSON, 문자순 정렬                                              |
| `fields_json`               | 활성 필드 UUID를 키로 `{name,type,value}`를 담은 JSON 객체, UUID 순서      |

필드의 `0`, `false`, 빈 텍스트, 날짜와 숫자는 자료형을 유지하고 미설정/NULL·보관 필드는 뺍니다.
필드 JSON은 PostgreSQL에서 만든 텍스트 그대로 사용하여 JavaScript 숫자 정밀도로 반올림하지 않습니다.
ID와 댓글 수도 JavaScript Number로 변환하지 않습니다.
행은 연결 UUID, 작성자 텍스트의 `C` 정렬 순서입니다.

## 표시용 작은따옴표와 수식 문자열

`sender_id`는 항상 작은따옴표 하나를 먼저 붙여 숫자 자동 변환에 따른 앞자리 0과 큰 숫자의 손실을 피하도록 표시합니다.
연결 계정 이름은 빈 문자열, 원래 작은따옴표로 시작하는 문자열, 선행 공백·제어·서식 문자 뒤의 `=`, `+`, `-`, `@`와 전각 형태, 선행 탭/CR/LF가 있는 경우에만 같은 표시를 붙입니다.
일반 계정 이름은 그대로 둡니다. 원래 이름이 `'shop`이면 파일 셀 값은 `''shop`입니다.

원래 스칼라 문자열을 복원하려면 맨 앞의 작은따옴표가 있을 때 **하나만** 제거합니다.
계정 이름의 NULL은 표시 없는 빈 셀이고, 원래 빈 문자열은 작은따옴표 하나인 셀이므로 구분됩니다.
태그와 필드 셀은 `[` 또는 `{`로 시작하는 JSON이며, 중첩 문자열은 JSON 이스케이프와 CSV 인용을 함께 적용합니다.
이 파일은 스프레드시트 표시용 형식입니다.
후속 사전 검사는 원본 v1 식별 표현과 `tags_json`을 읽지만 스프레드시트 재저장으로 변형된 값의 복원은 보장하지 않습니다.
스프레드시트 앱마다 작은따옴표 해석이 다를 수 있고, 편집·변환·다시 저장한 파일에서는 보호 표시가 사라질 수 있습니다.
생성한 파일의 인코딩 검증을 모든 앱과 저장/재열기의 안전성 보장으로 확대하지 않습니다.

## API·스냅샷·한도

`GET /api/contacts/export.csv`는 query 없이 전체 연락처를 내보내며, 받는 매개변수는 [세그먼트 내보내기](#저장된-세그먼트-내보내기)의 `segment_id` 하나뿐입니다.
그 밖의 매개변수, 중복 매개변수, UUID가 아닌 `segment_id`는 `400 invalid_contact_export_request`입니다.
멤버십과 역할을 `REPEATABLE READ READ ONLY` 트랜잭션 안에서 조회하며, 멤버가 없거나 제거됐으면 `403 workspace_required`, 상담원이면 `403 role_forbidden`입니다.
연락처·태그·중지·필드를 같은 스냅샷에서 내부적으로 25행씩 읽습니다. 클라이언트 커서는 없습니다.
삭제/권한 변경이 스냅샷 전에 커밋되면 반영되지만, 이미 시작한 스냅샷 내보내기는 그 이후 변경 전 데이터를 포함할 수 있습니다.
긴 쓰기 잠금으로 삭제를 막거나 이미 다운로드한 파일을 회수하지 않습니다.

서비스 한도는 연락처 5,000개, 최종 CSV 5 MiB(UTF-8 BOM·인용·CRLF 포함), 내보내기 작업 10초입니다.
바이트는 행을 보관하기 전에 실제 UTF-8 크기로 계산하며 한도를 넘으면 전체 요청을 거절합니다.
10초 예산은 연결 획득·조회·직렬화 전체에 하나만 적용하고, 각 DB 쿼리의 남은 시간을 제한합니다.
인증 미들웨어와 오류 후 연결 정리까지 포함한 HTTP 응답의 절대 10초 완료를 보장한다는 뜻은 아닙니다.
늦게 획득한 연결은 즉시 닫고, 시간 초과 뒤 아직 실행 중일 수 있는 쿼리의 클라이언트도 닫아 풀로 반환하지 않습니다. 연결 종료는 읽기 트랜잭션을 롤백합니다.
다른 오류는 명시적으로 롤백하고, 롤백이 실패하면 연결을 닫습니다.

행/바이트 초과는 `422 contact_export_too_large`, 시간 초과는 `503 contact_export_timeout`입니다.
성공적으로 모두 직렬화하고 커밋한 뒤에만 파일 응답을 만듭니다. 부분 CSV나 조용한 잘라내기는 없습니다.
본문은 `text/csv; charset=utf-8`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`이며 파일명은 서버가 만든 `auto-chatter-contacts-v1-YYYY-MM-DD.csv`입니다(세그먼트 내보내기는 [아래](#저장된-세그먼트-내보내기)).
조회 중 쓰기·큐 알림·공급자 호출·셀 내용 로그를 남기지 않습니다.

## 저장된 세그먼트 내보내기

[#26](https://github.com/AndrewDongminYoo/auto-chatter/issues/26)의 후속 범위로, 저장된 [세그먼트](2026-09-27-contact-segments.md) 하나가 고르는 연락처만 같은 v1 형식으로 내보냅니다.
저장하지 않은 직접 조건의 내보내기, 예약 내보내기, 가져오기 변경, 새 열은 포함하지 않습니다.

`GET /api/contacts/export.csv?segment_id=<UUID>`는 전체 내보내기와 같은 소유자·관리자 권한입니다.
`segment_id`는 한 번만 받으며 대소문자를 구분하지 않는 UUID여야 합니다. 다른 키와 함께 보내거나 반복하면 횟수를 쓰지 않고 `400 invalid_contact_export_request`입니다.
[요청 횟수 한도](#요청-횟수-한도)는 전체 내보내기와 같은 사용자별 `CONTACT_EXPORT_LIMIT`를 함께 씁니다. 별도 제한기는 없습니다.

멤버십과 관리자 권한을 확인한 뒤 같은 `REPEATABLE READ READ ONLY` 트랜잭션에서 세그먼트를 읽습니다.
보관됐거나 없거나 다른 작업 공간의 세그먼트는 `404 segment_not_found`이며 파일을 만들지 않습니다.
상담원은 세그먼트를 읽기 전에 `403 role_forbidden`을 받으므로, 응답으로 세그먼트 ID의 존재를 알 수 없습니다.

세그먼트는 같은 시각의 `GET /api/contacts?segment_id=<UUID>`와 같은 연락처를 고릅니다.
태그와 태그 집합, 필드 조건과 조건 집합, `condition_operator`, 계정, 고정·최근 N일·달력 활동 기간과 작업 공간 시간대, 목적별 동의 기록을 모두 적용합니다.
두 경로는 저장된 정의를 해석하는 `savedSegmentConditions`와 SQL 조건·매개변수 위치를 만드는 `segmentConditionSql`(`src/app/contacts.ts`)을 함께 쓰므로 고르는 연락처가 갈라지지 않습니다.
조건이 참조하는 필드는 연락처 목록과 같은 검사를 같은 스냅샷에서 거칩니다.

최근 N일과 달력 기간의 기준 시각(`as_of`)은 내보내기마다 한 번만 정합니다.
그 값은 파일의 `exported_at`, 즉 트랜잭션 시작 시각입니다.
따라서 내보낸 파일은 `exported_at` 시점의 스냅샷입니다.
세그먼트 조건은 내보내기마다 10초 한도 안의 한 문장에서 한 번만 계산하며, 이 문장은 맞는 연락처의 키(`connection_id`, `sender_id`)만 파일 순서대로 돌려주고 키가 연락처 한도보다 많으면 행을 읽기 전에 전체를 거절합니다.
행 내용은 그 키를 25개씩 넘겨 전체 내보내기와 같은 행 SQL로 읽으므로, 묶음마다 조건과 DM 확인 경로를 다시 계산하지 않습니다([#229](https://github.com/AndrewDongminYoo/auto-chatter/issues/229)).
연락처 목록은 페이지마다 그 조회 시각으로 다시 계산하므로, 다른 시각에 받은 목록과는 다를 수 있습니다.

행은 전체 내보내기와 같은 14개 열, 같은 표시용 작은따옴표와 이스케이프, 같은 정렬 순서이며 세그먼트에 맞는 연락처만 남깁니다.
세그먼트 이름과 조건은 파일에 넣지 않습니다.
연락처 5,000개·5 MiB·10초·내부 25행 묶음 한도와 `contact_export_*` 오류를 그대로 적용하며, 한도를 넘으면 전체를 거절합니다.
맞는 연락처가 없으면 헤더만 반환합니다.

파일명은 `auto-chatter-contacts-v1-segment-<세그먼트 ID>-YYYY-MM-DD.csv`입니다.
세그먼트 ID를 소문자로 넣어 파일을 구분하며, 세그먼트 이름은 파일명에 넣지 않습니다.
세그먼트에 포함된 것은 메시지 수신 동의나 발송 자격을 뜻하지 않습니다.
마이그레이션은 추가하지 않습니다.

## 요청 횟수 한도

[#196](https://github.com/AndrewDongminYoo/auto-chatter/issues/196)에 따라 `CONTACT_EXPORT_LIMIT`가 인증된 사용자별로 1시간 고정 창 5회까지 허용합니다.
기존 `AUTH_LIMITER` Durable Object를 재사용하며, 이름은 `contact-export:<사용자 ID>`입니다.
다른 사용자 및 작업 공간 JSON 내보내기(`WORKSPACE_EXPORT_LIMIT`)와 횟수를 공유하지 않습니다.
첫 요청이 창을 열고, 창 경계에 요청이 몰리면 짧은 시간에 최대 10회가 통과할 수 있습니다.

세션을 확인한 뒤 허용하지 않는 쿼리 매개변수가 있으면 기존 `400 invalid_contact_export_request`를 반환하며 횟수를 쓰지 않습니다.
유효한 요청은 DB 풀을 열기 전에 한도를 검사합니다.
한도 초과는 `429 contact_export_rate_limited`, 바인딩 누락이나 제한기 호출 실패는 `503 contact_export_unavailable`이며, 모두 DB를 읽지 않고 파일도 만들지 않습니다.
한도를 통과한 뒤에는 기존 스냅샷 안에서 멤버십·관리자 권한을 확인합니다.
따라서 이후 권한이나 크기·시간 한도로 실패한 요청도 횟수를 쓰며, 한도를 이미 넘은 상담원 요청은 역할 확인보다 먼저 429를 받습니다.
대시보드는 기존 오류 표시 영역에 한국어 재시도 안내를 보여 줍니다.
이 변경의 로컬·CI 검증은 운영 배포나 운영 제한기 상태를 증명하지 않습니다.

## 화면

소유자·관리자에게만 연락처 새로고침 옆의 “전체 연락처 CSV” 버튼과 전체 범위·저장 전 수정 제외·개인정보 안내를 보여줍니다.
표시 형식·복원·다시 저장의 주의점은 기본적으로 접힌 “CSV 값 읽는 방법”에서 키보드로 펼쳐 확인합니다.
중복 요청을 막고 진행·실패·완료는 한국어 aria-live 영역에 표시합니다.
필터 변경은 진행 중인 전체 내보내기를 취소하거나 좁히지 않고, 태그·필드 편집 DOM도 바꾸지 않습니다.
로그아웃·작업 공간 재조회/전환·화면에서 실행한 연결 데이터 삭제는 이전 요청의 다운로드를 무효화합니다.

저장된 필터를 고르면 소유자·관리자는 “선택한 필터로 내보내기”로 그 [세그먼트](#저장된-세그먼트-내보내기)를 내보낼 수 있습니다.
저장된 필터를 고르지 않았을 때, 필터 수정 중 저장하지 않은 조건·이름 변경이 있을 때, 필터 저장·보관 요청이나 다른 내보내기가 진행 중일 때는 버튼을 쓸 수 없습니다.
화면의 초안이 아니라 저장된 정의를 내보내며, 안내 문구가 이를 알립니다.
두 내보내기는 한 번에 하나만 진행하고 같은 진행·실패·완료 영역과 무효화를 씁니다. 진행 중인 세그먼트를 보관하면 그 다운로드도 취소합니다.
다른 필터를 고르는 것은 진행 중인 요청을 취소하지 않으며, 파일명에는 요청한 세그먼트의 ID가 들어갑니다.
텍스트 응답 디코딩에서 BOM이 제거될 수 있으므로 실제 Blob에는 정확히 하나를 복원하고, 객체 URL은 다운로드 후 해제합니다.
