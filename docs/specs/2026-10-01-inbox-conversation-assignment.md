# 인박스 대화 담당자와 열림·완료 상태

## 범위

[이슈 #22](https://github.com/AndrewDongminYoo/auto-chatter/issues/22)의 계약입니다.
[역할·초대](2026-09-30-workspace-roles.md)와 [수동 답장](2026-09-27-inbox-manual-replies.md) 위에서 대화마다 담당자와 열림·완료 상태를 두고, 모든 변경을 감사 기록에 남깁니다.
migration 029가 테이블과 삭제 함수 변경을 더하며, 운영 DB 적용은 이 PR의 범위가 아닙니다.

## 상태와 저장

대화 키는 인박스와 [상담 전환](2026-09-27-inbox-human-handoff.md)과 같은 `(workspace_id, connection_id, recipient_id)`입니다.
`instagram_inbox_conversations`는 상태(`open`·`closed`), 담당자 사용자 ID(없으면 미배정), 버전, 마지막 변경자와 시각을 저장합니다.
상태 행이 없는 대화는 버전 0의 열린 미배정 대화이므로 기존 대화는 따로 채우지 않습니다.
`instagram_inbox_conversation_events`는 버전마다 한 행씩 변경 전후 상태·담당자, 사유(`manual`·`auto_reopen`·`member_removed`), 실행자와 시각을 남깁니다.
자동으로 다시 열린 경우에만 실행자가 없고, 멤버 제거에 따른 배정 해제의 실행자는 제거한 소유자입니다.
서버 역할은 상태 행을 SELECT·INSERT·UPDATE하고 감사 행은 SELECT·INSERT만 할 수 있으며, 두 테이블 모두 DELETE 권한이 없습니다.
담당자 열에는 외래 키를 두지 않고, 멤버 여부는 변경할 때 서버가 확인합니다.
연결·사람·작업 공간 삭제 함수가 두 테이블을 지우며(사람 삭제는 DM 수신자 기준), 작업 공간 내보내기에 두 테이블이 포함됩니다.

## API

| 요청                                                        | 최소 역할 | 동작                                                         |
| ----------------------------------------------------------- | --------- | ------------------------------------------------------------ |
| `GET /api/inbox`                                            | agent     | 대화마다 `state`(상태·담당자 ID와 이메일·버전) 포함          |
| `GET /api/connections/:connection/inbox/:recipient`         | agent     | 메시지와 함께 `state`(마지막 변경자와 시각 포함) 반환        |
| `PUT /api/inbox/conversations/:connection/:recipient/state` | agent     | `{expected_version, status?, assignee_user_id?}`로 상태 변경 |
| `GET /api/inbox/assignees`                                  | admin     | 배정할 수 있는 제거되지 않은 멤버의 ID·이메일·역할           |

`GET /api/inbox`는 `status=open|closed`와 `assignee=me|none` 필터를 받습니다.
`PUT`은 같은 출처 요청에서 `expected_version`과 `status`·`assignee_user_id` 중 하나 이상을 받고, `assignee_user_id: null`은 배정 해제입니다.
작업 공간 행을 먼저 `FOR SHARE`로 잠가 작업 공간 삭제와 차례를 정하고, 연결 행을 `FOR SHARE`로 잠가 연결·사람 데이터 삭제와 직렬화하고, 상태 행을 `FOR UPDATE`로 잠근 뒤 버전을 비교하며, 상태와 감사 행을 같은 트랜잭션에서 씁니다. 한 요청은 버전을 하나만 올립니다.
바뀌는 값이 없으면 버전과 감사 행 없이 현재 상태를 돌려줍니다.
버전이 다르면 `409 {error: "conversation_conflict", state}`로 현재 상태와 마지막 변경자를 돌려주므로, 동시에 같은 대화를 맡으면 한 요청만 성공합니다.
대화가 없으면 `404 conversation_not_found`, 형식이 틀리면 `400 invalid_conversation_request`입니다.

## 권한

열림·완료는 상담원 이상 모두 바꿀 수 있습니다.
상담원은 미배정 대화를 자신에게 배정하거나 자신의 배정만 해제할 수 있고, 그 밖의 배정 변경은 `403 role_forbidden`입니다.
관리자와 소유자는 제거되지 않은 같은 작업 공간의 멤버 누구에게나 배정하거나 배정을 해제할 수 있습니다.
제거된 멤버나 다른 작업 공간의 사용자에게 배정하면 `409 assignee_unavailable`입니다.
`PUT`은 호출자와 새 담당자의 멤버 행을 `FOR SHARE`로 잠근 뒤 상태 행을 잠그므로, 멤버 제거와 동시에 그 멤버에게 배정하는 요청은 제거보다 먼저 커밋되어 제거로 해제되거나, 제거를 기다린 뒤 거부됩니다.

## 자동 변경

인박스에 새로 저장된 DM이나 확인 버튼 응답은 같은 트랜잭션에서 완료한 대화를 다시 엽니다(`auto_reopen`). 담당자는 그대로 둡니다.
다시 열 때는 상태 API와 삭제 함수처럼 연결 행을 `FOR SHARE`로 먼저 잠근 뒤 대화 행을 바꾸므로, 같은 사람의 데이터 삭제와는 교착 없이 차례를 기다립니다. 완료한 대화가 없으면 연결 행을 잠그지 않습니다.
이미 저장한 메시지 ID가 다시 오면 아무것도 바꾸지 않습니다.
소유자가 멤버를 제거하면 같은 트랜잭션에서 그 멤버가 담당한 대화를 모두 미배정으로 바꾸고 대화마다 `member_removed` 감사 행을 남깁니다. 상태는 바꾸지 않습니다.
멤버 제거와 `PUT`은 `delete_workspace_data`처럼 작업 공간 행을 먼저 잠그므로, 멤버 행을 먼저 잡고 연결 행을 기다리다 작업 공간 삭제와 교착하지 않고 차례를 기다립니다.
제거 중인 멤버가 담당한 완료 대화 두 개 이상이 같은 웹훅 묶음에서 다시 열리는 드문 경우에는 두 트랜잭션이 대화 행을 다른 순서로 잠가 PostgreSQL 교착 상태 감지로 한쪽이 실패할 수 있습니다.

## 자동화와의 관계

담당자와 열림·완료는 상담 전환과 자동화 중지를 바꾸지 않고, 상담 전환도 담당자와 상태를 바꾸지 않습니다. 화면은 두 상태를 함께 보여 줍니다.
완료해도 자동화가 재개되지 않으며, 다시 열려도 상담이 시작되지 않습니다.
다음 한계는 테스트(`src/app/inbox-conversations.db.test.ts`)와 화면 문구에 함께 적습니다.

- 멤버를 제거해도 그 멤버가 예약한 수동 답장과 시작한 상담 전환은 취소되지 않습니다. 이미 공급자 요청에 들어간 수동 답장도 그대로 발송되고, 기다리던 수동 답장은 제거 뒤에도 발송됩니다.
- 담당자를 바꾸거나 완료해도 예약된 답장, 발송 중인 답장, 상담 전환 버전과 자동화 중지는 그대로입니다.
- 자동 답장이 공급자 요청에 들어간 뒤 시작한 상담 전환은 그 답장을 되돌릴 수 없습니다. 같은 사람의 다음 자동 답장부터 중지됩니다. 이는 상담 전환의 [발송 경계](2026-09-27-inbox-human-handoff.md#발송-경계와-감사)와 같은 계약입니다.

## 화면

인박스에 "전체 대화", "내 대화"(나에게 배정된 열린 대화), "미배정"(열린 미배정 대화), "완료" 보기가 있습니다.
대화 목록과 대화 화면에 상태와 담당자를 보이고, 대화 화면에는 마지막 변경자와 시각(자동으로 다시 열렸으면 그 사실)을 보입니다.
상담원에게는 "내가 담당"·"담당 해제"와 "완료 처리"·"다시 열기"를, 관리자 이상에게는 담당자 선택도 보입니다.
충돌하면 안내를 표시하고 대화를 다시 불러와 현재 상태와 변경자를 보여 줍니다.
화면 확인 기록은 [로컬 화면 검증](../notes/2026-10-01-inbox-conversation-assignment-ui-verification.md)에 있습니다.
