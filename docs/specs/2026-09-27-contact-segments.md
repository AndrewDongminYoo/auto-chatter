# 저장된 연락처 세그먼트

## 목적

반복해서 사용하는 연락처 계정·태그 검색 조건을 이름으로 저장합니다.
[ManyChat 연락처 문서](https://help.manychat.com/hc/en-us/articles/14281110746012-Contacts-tab-Overview)의 저장된 검색 조건을 기준으로 2026-09-27 확인했습니다.
연락처 목록은 조건을 실행할 때 계산하며 참여자 스냅샷이나 발송 동의로 취급하지 않습니다.

## 계약

- 세그먼트는 작업 공간에 속하며 이름, 선택적인 Instagram 연결과 태그를 저장합니다.
- 이름은 NFC·앞뒤 공백 제거 후 1–60자이며 제어 문자는 거부합니다.
- 태그는 기존 연락처와 같은 정규화를 사용하며 빈 입력은 조건 없음입니다.
- 세그먼트 생성 시 다른 작업 공간의 계정을 참조하거나 다른 작업 공간의 세그먼트를 조회·보관하면 404입니다.
- 기존 수동 connection_id 필터의 다른 작업 공간·존재하지 않는 계정에 대한 빈 목록 응답은 유지합니다.
- 계정이 없는 조건은 작업 공간의 모든 계정에 적용하며 동일 sender를 다른 계정과 합치지 않습니다.
- 작업 공간당 활성 세그먼트는 최대 50개이며 같은 이름은 하나만 허용합니다.
- 생성·[수정](#이름과-조건-수정)·보관 처리는 서버 인증·동일 출처 검사 후 수행합니다.
- 보관은 archived 설정을 바꾸고 연락처·태그·댓글을 제거하지 않습니다.
- 저장된 조건으로 연락처를 조회하면 최신 태그 상태와 기존 50건 페이지 이동을 사용합니다.
- 태그와 단일 사용자 정의 필드는 `condition_operator=and|or`로 결합합니다. 생략한 기존 필터는 AND이며 응답에도 기존 형태를 유지합니다. OR는 태그와 필드 조건이 모두 있을 때만 허용하고 저장·복원·보관 뒤 수동 조회에도 보존합니다.
- 선택적인 [마지막 댓글 저장 기간](2026-10-16-segment-comment-activity.md)을 고정 UTC `[from,before)`로 저장·복원합니다.
  기간은 태그/필드 AND/OR와 별도로 적용하고 기존 세그먼트 응답은 기간 키를 생략합니다.
- [최근 댓글 활동](2026-10-16-segment-relative-activity.md)은 `last_comment_days` 정수 1~366만 저장하고 매 조회의 직전 N×24시간을 계산합니다.
  고정 기간과 동시에 사용할 수 없고 미리보기·페이지의 실제 UTC 경계를 반환합니다.
  다음 페이지도 다시 계산하므로 전체 대상의 시점 고정은 아닙니다.
- 선택적인 [목적별 동의 기록](2026-10-16-segment-consent-state.md)은 `consent_purpose`·`consent_state` 쌍으로 저장·복원하며 정확한 댓글 식별자의 현재 상태만 비교합니다.
- workspace·계정·활동 기간·동의 기록·페이지 커서는 항상 별도의 AND 제한입니다. OR에 맞는 태그가 있어도 외부·보관된 필드나 잘못된 타입·값을 허용하지 않습니다. 필드의 eq·입력됨·미입력·숫자/날짜 비교 계약은 그대로 적용합니다.
- 화면은 태그와 필드가 모두 있을 때 조건 결합을 선택하게 합니다. 하나가 제거되면 AND로 돌아가며 저장 실패 때 결합과 초안을 유지합니다.
- 세그먼트와 수동 조건을 한 요청에서 혼합하면 400입니다.
- UI는 조건 저장·선택·보관을 제공하며 태그 초안 확인, 실패 뒤 입력 보존과 로그아웃 뒤 늦은 응답 차단을 유지합니다.
- 저장 영역의 [초안 대상 미리보기](2026-10-16-segment-draft-preview.md)는 현재 폼 조건의 전체 대상 수와 선택 계정 범위의 평가 수·태그/추가 정보별 제외 사유를 조회 시점의 값으로 표시하며 최대 50명을 읽고 5명까지 예시를 표시합니다.
  기간을 지정하면 기간 밖 연락처를 먼저 제외하고, 동의 기록 조건을 지정하면 그 다음에 기록이 맞지 않는 연락처를 제외합니다.
  이를 통과한 연락처를 태그만·필드만·둘 다 불일치로 나누며 OR는 둘 다 불일치만 추가로 제외합니다.
  마지막으로 적용한 목록과 연락처 편집값은 유지하며 발송 가능 여부·고정 대상을 뜻하지 않습니다.

## 이름과 조건 수정

2026-10-17에 [#26](https://github.com/AndrewDongminYoo/auto-chatter/issues/26)의 일부로 활성 세그먼트의 이름과 조건 수정을 추가했습니다.
수정해도 세그먼트 ID는 유지됩니다.

- `PUT /api/contact-segments/<id>`는 활성 `admin` 이상만 호출할 수 있으며, `agent`와 제거된 멤버는 403입니다.
- 본문은 생성과 같은 키에 필수 `expected_version`(1 이상의 안전한 정수)을 더한 전체 정의이며 부분 변경이 아닙니다.
  생략한 선택 조건 키는 생성과 같이 그 조건이 없다는 뜻이므로 기존 조건을 지웁니다.
- 생성과 수정은 `parseSegmentDefinition` 하나로 본문을 검사하므로 같은 정의를 받아들이고 같은 코드로 거부합니다.
  모양·이름 오류는 `400 invalid_segment`이고, 조건 값 오류는 생성과 같은 `invalid_field_condition`·`invalid_contact_activity`·`invalid_contact_consent`·`invalid_contact_condition`·`invalid_contact_tags`입니다.
  `expected_version`은 수정에서만 허용하며, 생성 본문에 넣으면 `400 invalid_segment`입니다.
- 트랜잭션은 다음 순서로 잠급니다.
  1. `lockWorkspaceForMember`가 생성과 같이 작업 공간 행을 `FOR UPDATE`로 잠그고 호출자의 활성 멤버십과 역할을 다시 확인합니다.
  2. 세그먼트 행을 `FOR UPDATE`로 잠급니다.
     없거나 다른 작업 공간의 세그먼트, 보관된 세그먼트는 모두 `404 segment_not_found`입니다.
     보관된 세그먼트는 수정할 수 없으며, 같은 코드를 사용하므로 보관된 ID와 없는 ID를 응답으로 구별할 수 없습니다.
  3. 저장된 `version`이 `expected_version`과 다르면 아무것도 쓰지 않고 `409 segment_conflict`와 현재 세그먼트(`segment`, 목록 항목과 같은 형태)를 반환합니다.
  4. 참조하는 필드를 `FOR SHARE`로 잠그고 생성과 같이 계정 소유를 확인합니다.
     `archiveContactField`는 필드를 `FOR UPDATE`로 잠근 뒤 활성 세그먼트의 참조를 확인합니다.
     따라서 수정이 먼저 필드를 잡으면 보관은 수정이 커밋할 때까지 기다린 뒤 `409 field_in_use`가 되고, 보관이 먼저 커밋하면 수정은 `404 field_not_found`가 됩니다.
  5. 이름과 모든 조건 열이 저장된 값과 같으면 쓰지 않고 현재 버전 그대로 현재 세그먼트를 반환합니다.
     비교는 정규화한 값에 대해 SQL `IS DISTINCT FROM`으로 하므로, 앞뒤 공백이나 대소문자만 다른 태그도 변경 없음입니다.
  6. 다르면 모든 정의 열을 바꾸고 `version`을 1 올립니다.
     다른 활성 세그먼트와 정규화한 이름이 같으면 `409 segment_name_exists`이며, 보관된 세그먼트의 이름은 사용할 수 있습니다.
- 성공 응답은 200이며 목록 항목과 같은 형태에 `version`을 포함합니다.
  `GET /api/contact-segments` 항목과 생성 응답에도 `version`이 추가되며 다른 필드는 바뀌지 않습니다.
- 활성 세그먼트 50개 제한은 생성만 세며, 수정은 활성 수를 바꾸지 않습니다.
- 세그먼트는 고정 대상이 아닙니다.
  `segment_id`로 조회하는 연락처 목록과 미리보기는 요청마다 저장된 현재 정의를 읽으므로, 수정 뒤 다음 요청부터 새 조건으로 계산합니다.
  `segment_id`와 수동 조건을 섞을 수 없다는 규칙은 그대로입니다.
- 수정 이력과 감사 테이블은 없습니다.
  생성과 보관에도 이력이 없으므로 수정도 같은 수준으로 둡니다.
- 마이그레이션 054는 `version integer NOT NULL DEFAULT 1`과 `CHECK(version >= 1)`을 추가하며, 기존 행은 1에서 시작합니다.
  기존 DB는 코드 배포 전에 054를 전체 실행기(`deploy/migrate-multi-user.sql`)로 적용해야 합니다.
- `deploy/supabase-access.sql`과 `deploy/init-app-user.sh`는 이 테이블에 열 단위가 아닌 표 단위 SELECT·INSERT·UPDATE를 부여하므로 새 열에 권한을 추가하지 않습니다.
  작업 공간 내보내기는 이 테이블의 모든 열을 내보내므로 `version`도 자동으로 포함되며, 내보내는 열 목록을 고정한 테스트는 없습니다.
- 화면은 소유자와 관리자에게 선택한 저장 필터의 "필터 수정"을 표시합니다.
  수정을 시작하면 기존 조건 폼과 필터 이름 입력에 저장된 값을 채우고, 저장 버튼을 "변경 저장"으로 바꾸며 "수정 취소"를 제공합니다.
  새 필터 이름을 입력해 둔 상태라면 그 이름을 버릴지 먼저 확인하고, 취소하면 수정을 시작하지 않습니다.
  수정 중에는 다른 저장 필터를 고를 수 없습니다.
- 화면은 200을 받으면 수정 모드를 끝내고 목록을 다시 불러온 뒤 수정한 필터를 선택한 채 저장된 조건을 폼에 채웁니다.
  저장 요청이 진행되는 동안 운영자가 조건을 바꿨다면 그 조건은 저장되지 않았으므로, 폼을 덮어쓰거나 선택을 되돌리지 않고 그대로 두며 저장되지 않았다고 알립니다.
- 화면은 `409 segment_conflict`를 받으면 입력값을 유지하고 지금 저장된 값을 텍스트로 표시합니다.
  보관하던 버전은 운영자가 "저장된 값 불러오기"를 누를 때만 바뀌므로 다른 변경을 조용히 덮어쓰지 않습니다.
- 화면은 `404 segment_not_found`를 받으면 수정 모드를 끝내고 목록을 다시 불러오며, 입력한 이름과 조건은 새 필터로 저장할 수 있게 남깁니다.
  작업 공간 다시 불러오기, 세션 초기화, 필터 보관도 수정 모드를 끝냅니다.
- 기존 생성·보관 버튼은 화면에서 역할별로 숨기지 않으며, `agent`의 요청은 서버가 `403 role_forbidden`으로 거부합니다.

## 비목표와 한계

중첩 조건 조합 언어, 다중 태그·필드, DM 동의·DM 활동·달력 날짜 기반 상대 기간과 그 제외 사유, 발송 대상 지정, CSV는 후속 범위입니다.
태그와 단일 필드의 AND/OR와 이름·조건 수정은 #26의 일부이며 전체 이슈를 완료하지 않습니다. AND/OR는 마이그레이션 037, 고정 활동 기간은 046, 목적별 동의 기록은 047, 최근 일수는 053, 수정 버전은 054를 전체 실행기로 적용한 뒤 사용하는 계약입니다.
수정은 이력을 남기지 않으므로, 이전 조건을 남겨야 하면 새 세그먼트로 저장합니다.
운영 마이그레이션·배포·실발송은 이 PR에서 수행하지 않습니다.
인덱스가 있어도 댓글 집계의 대량 운영 지연 시간을 보장하지 않습니다.

## 수용 기준

로컬 PostgreSQL에서 작업 공간 격리, 다른 계정 거부, 이름 중복·정규화, 50개 제한의 동시 생성, 최신 태그 반영과 보관 뒤 조회 거부를 확인합니다.
workerd와 제한된 서버 역할로 생성·조회·보관을 실행하고 RLS 활성화와 DELETE 권한 부재를 확인합니다.
실제 로컬 UI에서 조건 저장·조회·보관, 실패 입력 보존·미저장 태그 보호·모바일 폭·늦은 응답 차단을 검사합니다.
프로젝트 관련 Oracle 선례는 `[no precedent found]`이며 Wiki freshness는 확인되지 않았습니다.
