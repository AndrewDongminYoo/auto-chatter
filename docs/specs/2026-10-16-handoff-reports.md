# 상담 전환 이력 리포트

## 범위

[#50](https://github.com/AndrewDongminYoo/auto-chatter/issues/50)의 다음 단계로, 관리자가 선택 기간에 기록된 상담 전환 시작과 해제를 확인합니다.
보존된 `instagram_inbox_handoff_events`를 읽으며 기존 상담 전환·직접 중지·발송 guard는 변경하지 않습니다.
플로 귀속, 현재 활성 상담 수, 상담 해결과 성공 전환율, 캠페인·비용 분석은 포함하지 않고 #50은 계속 열어 둡니다.

## API와 권한

`GET /api/reports/handoffs`는 활성 `owner` 또는 `admin`만 사용할 수 있습니다.
필수 `from`·`before`는 정확한 `YYYY-MM-DD` 형식이며 작업 공간 시간대의 시작일을 포함하고 종료일을 제외합니다.
조회 기간은 1~366일이고 `expected_time_zone`은 현재 저장된 시간대와 정확히 같아야 합니다.
선택적인 `connection_id`는 같은 작업 공간의 계정이며 비활성 계정도 포함합니다.
계정 필터가 없으면 작업 공간 전체를 집계합니다.

잘못되거나 중복된 키, 미지원 `flow_id`, 잘못된 날짜·UUID·기간은 400 `invalid_report_query`입니다.
없는 계정과 다른 작업 공간의 계정은 모두 404 `connection_not_found`이고 바뀐 시간대는 409 `report_time_zone_changed`입니다.
현재 멤버십·시간대·계정 소유권·집계를 한 SQL 문장의 스냅샷으로 확인합니다.
이미 시작한 조회를 이후의 권한 변경으로 회수하지는 않습니다.
각 날짜의 자정과 DST 경계는 PostgreSQL이 변환하며 실제 UTC 경계와 조회 시각을 반환합니다.
겹치거나 존재하지 않는 자정도 PostgreSQL의 시간대 규칙을 따릅니다.

## 네 지표의 의미

대상은 `created_at`이 지정 기간에 속한 보존 이벤트입니다.
현재 handoff 행의 `active`나 `updated_at`, 답장 접수·발송 시각으로 기간을 정하지 않습니다.
응답의 `counts`는 다음 십진수 문자열 네 개입니다.

| 키            | 화면           | 계산과 의미                                                        |
| ------------- | -------------- | ------------------------------------------------------------------ |
| total         | 변경 횟수      | 기간 내 이벤트 전체 수이며 started + cleared와 같음                |
| started       | 상담 전환 시작 | reason이 handoff_started인 이벤트 수                               |
| cleared       | 상담 전환 해제 | reason이 handoff_resumed인 이벤트 수                               |
| conversations | 변경된 대화 수 | 기간 내 이벤트에 등장한 (connection_id, recipient_id) 고유 조합 수 |

같은 대화의 시작·해제·재시작은 각각 다른 이벤트입니다.
동일 요청을 다시 받아 이벤트를 추가하지 않는 기존 멱등 처리에서는 건수가 늘지 않습니다.
고유 대화 수는 계정이 다르면 같은 recipient도 별개로 계산하며, 사람 수나 시작 횟수와 같지 않습니다.
기간 전에 시작한 대화를 기간 안에 해제했다면 해제 1회와 대화 1개로 포함합니다.

해제는 해당 대화의 상담 전환 사유가 해제됐다는 뜻입니다.
직접 중지·다른 대화의 상담 전환·발송 설정·정책 제한이 남아 있을 수 있으므로 자동 발송 재개나 상담 해결을 뜻하지 않습니다.
`evidence_reply_id`는 식별자 연결 근거이며 플로가 상담 전환을 일으켰다는 증거가 아니므로 플로별 귀속을 계산하지 않습니다.
삭제된 이벤트는 집계에서 사라지며 영구적인 과거 통계나 청구 원장이 아닙니다.
연락처·수신자·운영자·이벤트 식별자, 본문과 자격 증명은 반환하지 않습니다.

## 화면과 CSV

홈에서 날짜와 계정을 선택해 조회합니다.
초기 기간은 작업 공간 시간대의 최근 7일이고 브라우저가 시간대를 지원하지 않으면 날짜를 직접 입력합니다.
화면은 기간·시간대·계정·조회 시각을 표시하며 조회 시각의 지역화에 실패하면 UTC로 표시합니다.
CSV는 화면에 표시한 응답 하나에서 만들고 재조회하지 않습니다.
고정 지표명·건수·검증된 기간·시간대·계정 UUID만 내보내며 계정 이름과 고객 데이터는 제외합니다.
입력 변경·새 조회·작업 공간 재로딩·로그아웃은 결과와 CSV를 무효화하고 늦은 응답을 무시합니다.

## 검증과 운영 경계

실제 DB의 반복 전환·멱등 재요청·같은 recipient의 여러 계정·해제만 있는 기간·현재 상태와의 독립성·삭제·권한·필터 소유권·마이크로초 경계·DST·빈 결과를 검사합니다.
대표 과거 데이터를 포함한 실제 집계 SQL의 실행 계획에서 계정 필터 유무 모두 날짜 조건으로 인덱스 읽기 범위를 좁히는지 확인합니다.
화면·CSV·늦은 응답·역할 초기화·좁은 화면은 브라우저로 확인합니다.
기존 DB는 배포 전에 전체 `deploy/migrate-multi-user.sql` 실행기로 migration 052의 기간 인덱스를 적용해야 합니다.
일반 인덱스 생성은 트랜잭션 완료까지 해당 테이블의 쓰기를 대기시킬 수 있어 운영 적용은 별도 승인 범위입니다.
로컬 검증으로 운영 DB·실제 인증·Meta 발송·운영 규모 성능을 검증했다고 주장하지 않습니다.

## 판단 근거

Advisor는 이벤트 수와 현재 상태를 섞지 않고 식별자 연결 근거에서 플로 인과성을 추정하지 않도록 조정했습니다.
Oracle의 `wiki/concepts/diagnostic-report-pattern.md`와 `wiki/sources/claude--skills--tdd-bugfix-swarm--skill.md`는 직접 계산할 수 있는 사실·실제 검증·남은 한계를 구분하는 방향을 뒷받침합니다.
조회 provenance는 `c1681868ac634e4b2414874716bb75a7864113c4`이고 최신성은 미확인입니다.
검색은 27건 중 10건만 반환했으며 반환된 범위에서 Instagram 상담 전환 의미론의 직접 선례는 확인하지 못했습니다.
