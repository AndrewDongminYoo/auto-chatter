# 인박스 수동 답장 화면

## 목표와 범위

GitHub #19의 작성기와 발신 이력을 기존 인박스에 추가합니다.
PR #67에서 병합한 [수동 답장 계약](2026-09-27-inbox-manual-replies.md)을 사용합니다.
상담 시작·자동화 재개, 수신·수동 발신 이력, 대화별 초안, 발송 제한 안내, 안전한 재예약과 확인 필요 결과의 해결 기록을 제공합니다.
운영 배포·실제 DM 발송·팀 배정·첨부 파일·자동 발신 이력 통합·새 메시징 정책은 범위에 포함하지 않습니다.

## 서버 판정

소유권이 확인된 `GET /api/connections/:connection/inbox/:recipient/reply-status`가 현재 상담 버전, 답장 가능 여부와 제한 코드, 검사 시각, 답장 창 종료 시각을 반환합니다.
워커와 같은 판정 함수를 사용하며 토큰과 식별자 연결 근거의 원문은 반환하지 않습니다.
이 조회는 화면 안내이며 실제 POST의 예약·발송 검사를 대신하지 않습니다.
상담 시작 가능 여부는 기존 소유권이 적용된 context 조회를 사용합니다.

## 요청과 화면 상태

- 초안은 계정·DM 사용자별로 메모리에 보관하고 로그아웃 시 지웁니다.
- Enter는 줄바꿈이며 Ctrl 또는 Command+Enter로 명시적으로 제출합니다.
- 접수 전에 UUID 요청 키와 문구·상담 버전을 고정하고 중복 클릭을 차단합니다.
- 네트워크 오류나 5xx로 접수 여부를 확인하지 못하면 문구를 변경하지 않고 동일 요청을 다시 조회하는 접수 확인 동작을 제공합니다.
- 세션 재설정과 대화 전환 뒤의 늦은 응답은 다른 대화 화면을 바꾸지 않습니다.
- 예약·발송 중·완료·명확한 거부·확인 필요 상태를 텍스트로 구분합니다.
- 명확한 미발송 실패만 운영자 사유와 새로운 요청 키로 재예약합니다.
- `unknown`은 재전송하지 않으며, 사용자가 확인한 뒤 사유를 기록하는 `no_retry` 결정만 제공합니다.
- 수신·발신의 독립 커서를 유지하고 각각의 서버 페이지를 병합해 표시합니다.
- 새로고침은 초안을 유지하고 서버 상태를 갱신합니다.

## 검증

1. 서버 조회의 소유권·정책·창 종료·비밀값 제외를 DB 테스트로 확인합니다.
2. 브라우저에서 초안·중복 클릭·응답 유실·대화 전환·늦은 응답·로그아웃·재예약·해결 기록을 합성 API로 검사합니다.
3. 390px 모바일과 데스크톱, 키보드 입력과 초점, 긴 문구와 빈 상태를 확인합니다.
4. 로컬 적대적 리뷰와 CI·현재 커밋의 코드·보안 리뷰를 완료한 뒤 화면 승인을 요청합니다.

## 선례와 실행 경계

개인 계정의 `auto-chatter` Oracle에 `manual reply`, `stale response`를 조회했으나 전용 실행기의 시작 오류로 실패했습니다.
`[TOOL_FAILED]`이며 선례가 없다는 결과로 해석하지 않습니다.
현재 저장소의 서버 계약과 세션·오래된 응답 보호 관례를 기준으로 구현합니다.
모의 브라우저 검증은 운영 마이그레이션·실제 Meta 권한·DM 도착 검증을 대신하지 않습니다.
