# 버전 고정 플로 실행 계약 (첫 구현)

## 범위

[이슈 #29](https://github.com/AndrewDongminYoo/auto-chatter/issues/29)의 첫 구현입니다.
발행된 플로 버전이 댓글에 따라 결정적으로 실행되고, 실행 경로와 발송 결과를 이력으로 남깁니다.
이번 구현은 댓글 트리거, `has_tag`·`field_equals` 분기, 그리고 경로의 첫 `instagram_message`를 댓글 비공개 답장으로 보내는 동작만 실행합니다.
태그·필드 동작과 메시지 변수(#31), 대기·지연과 사용자 응답 대기(#32), 팔로우 확인, 첫 메시지 이후의 후속 노드와 편집 화면(#30)은 포함하지 않습니다.
문서 형식과 발행 검증은 [플로 초안·버전·발행 검증 계약](2026-09-29-flow-version-contract.md)을 따릅니다.

## 켜기 스위치

`flows.enabled`의 기본값은 false이며, 발행만으로는 실행되지 않습니다.
켜기(`POST /api/flows/:id/enable`)는 플로 행과 트리거 연결 행을 차례로 잠근 뒤, 현재 발행 버전이 다음 조건을 모두 만족할 때만 성공합니다.

- 보관되지 않았고 발행 버전이 있습니다. 아니면 각각 `409 flow_archived`, `409 flow_not_published`를 반환합니다.
- 트리거 연결이 활성이고 OAuth 자격 증명을 가집니다. 환경 변수로 관리하는 연결의 Node 워커는 플로 답장을 발송하지 않으므로 `login_mode_required`로 거부합니다.
- 모든 노드를 이 실행기가 실행할 수 있습니다.

실행할 수 없으면 `422 {error: "flow_not_executable", errors}`를 반환하고, 오류는 발행 검증과 같은 `code`·`path`·`node_id`·`edge_index` 형식을 씁니다.

| 코드                        | 뜻                                        |
| --------------------------- | ----------------------------------------- |
| `unsupported_node`          | 이번 구현이 실행하지 않는 노드 타입       |
| `unsupported_message`       | 변수(`{{`)나 `button_title`을 쓰는 메시지 |
| `unsupported_after_message` | 메시지 노드에서 나가는 연결               |
| `connection_unavailable`    | 트리거 연결이 없거나 비활성               |
| `login_mode_required`       | 트리거 연결에 OAuth 자격 증명이 없음      |

켜진 플로를 다시 발행하면 새 버전도 같은 조건을 통과해야 하며, 통과하지 못하면 `422 flow_invalid`로 버전을 만들지 않습니다.
끄기(`POST /api/flows/:id/disable`)는 항상 성공하고, 보관은 스위치를 함께 끕니다.
기존 댓글 규칙처럼, 연결을 해제하면 그 연결을 트리거로 쓰는 플로도 꺼지므로 다시 연결해도 자동으로 실행되지 않습니다.
DB 제약은 켜진 플로가 보관되지 않았고 발행 버전을 가리키도록 강제합니다.

## 실행 시작

댓글 수집 트랜잭션에서, 같은 연결·게시물에 켜진 기존 댓글 규칙이 없으면 켜진 발행 플로를 찾습니다.
두 기능은 발행과 규칙 켜기 검사 때문에 한 게시물을 함께 소유할 수 없습니다.
트리거는 기존 댓글 규칙과 같은 매칭 함수로 키워드·모드·제외어를 검사하며, 맞지 않으면 실행을 만들지 않습니다.
실행은 그 시점의 발행 버전 ID를 기록하고, 이후 다시 발행하거나 초안을 바꿔도 이미 만든 실행과 그 답장은 바뀌지 않습니다.
분기는 같은 트랜잭션에서 읽은 연락처 태그와 필드 값만으로 평가하므로, 같은 문서와 같은 값은 항상 같은 경로를 만듭니다.
`field_equals`는 저장된 세그먼트 조건과 같게 NULL 값을 미설정으로 보고, `eq`는 JSON 값과 타입이 모두 같을 때만 참입니다.

중복은 제약으로 막습니다.
같은 댓글의 재전송은 댓글 이벤트 고유 제약에서 멈추고, 실행은 `(flow_id, event_id)`마다 하나이며, 답장은 기존 outbox의 이벤트별·보낸 사람과 게시물별 고유 제약을 그대로 따릅니다.

## 상태와 단계 기록

| 실행 상태    | 뜻                                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------------------ |
| `delivering` | 메시지를 outbox에 넣었습니다. 발송 결과는 outbox 행이 소유합니다.                                      |
| `ended`      | 연결이 없는 포트에 도달해 메시지 없이 끝났습니다.                                                      |
| `skipped`    | 같은 보낸 사람과 게시물에 이미 답장이 있어 큐에 넣지 않았습니다(`duplicate_recipient`).                |
| `failed`     | 실행할 수 없는 노드에 도달했거나(`unsupported_node`) 문서를 해석하지 못했습니다(`invalid_definition`). |

`flow_step_runs`는 실행이 지난 노드마다 노드 ID, 타입, 결과를 순서대로 기록합니다.
결과는 조건의 `true`·`false`, 트리거의 `next`, 메시지의 `queued`·`duplicate_recipient`, 또는 `unsupported_node`입니다.
실행되지 않는 노드를 건너뛰지 않으며, 켜기 검사를 통과한 버전에서는 `unsupported_node`에 도달하지 않습니다.
사용자 응답 대기 상태는 대기 노드가 생기는 #32에서 추가합니다.

## 발송

플로 답장은 `private_reply_outbox`에 `rule_id` 대신 `flow_run_id`를 가진 행으로 들어가며, 두 값 중 정확히 하나만 설정할 수 있습니다.
따라서 claim, 재시도, 속도 제한, stale 복구, 동의·연락처 중지·상담 전환 검사와 `unknown` 비재시도 규칙은 기존 비공개 답장과 같습니다.
발송 직전 검사는 규칙 대신 플로가 켜져 있는지 확인하고, 꺼졌으면 `blocked / inactive_flow`로 기록합니다.
다시 발행해도 이미 큐에 들어간 답장은 고정된 버전의 문구로 발송됩니다.
플로 답장에는 팔로우 설정(`follow_config`)이 없습니다.

## 이력 API

`GET /api/flows/:id/runs`는 최근 실행 50건을 최신순으로 반환합니다.
각 항목은 실행 ID, 버전 번호, 실행 상태와 실패 코드, 단계 목록, 그리고 답장이 있으면 outbox의 `delivery_status`·`delivery_failure_code`·`sent_at`을 가집니다.
보낸 사람 ID와 댓글 본문은 이력에 포함하지 않습니다.
다른 작업 공간의 플로는 404로 보입니다.

## 저장과 삭제

서버 역할은 `flow_step_runs`를 추가만 할 수 있고, `flow_runs`는 중복 답장을 기록하기 위해 UPDATE할 수 있으며, 두 테이블 모두 DELETE할 수 없습니다.
`delete_connection_data`와 `delete_person_data`는 해당 범위의 실행과 단계 기록을 지우고 삭제 건수에 포함합니다.
이용자 단위 삭제는 잠금 뒤에 새 답장이나 실행이 생긴 댓글 이벤트를 남깁니다.
작업 공간 내보내기는 두 테이블을 포함합니다.

## 운영 적용

migration 021은 관리자 migration 러너와 접근 권한 스크립트에 포함됩니다.
번호는 작업 공간 삭제(PR #91)가 쓰는 020 다음입니다.
이 계약은 운영 DB에 적용하지 않았고 실계정에서 검증하지 않았습니다.
