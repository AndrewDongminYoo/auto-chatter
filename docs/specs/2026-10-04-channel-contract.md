# 채널 계약과 Instagram 경계

[#37](https://github.com/AndrewDongminYoo/auto-chatter/issues/37)의 첫 코드 범위입니다. 실제 연결·저장·발송 채널은 Instagram 하나이며, 두 번째 어댑터는 단위 테스트 안에서만 존재합니다. 새 공급자 권한·가격·승인 템플릿 정책은 정하지 않습니다.

## 계정·식별자·이벤트

`src/channels/contract.ts`의 계정 주소는 채널과 공급자 계정 ID입니다. 작업 공간·연결 ID가 붙은 주소도 소유권 증거가 아니며, 기존 DB 조회가 소유권을 검증합니다. 동의 식별자는 작업 공간·연결·채널·식별자 종류·값을 모두 비교합니다. 같은 문자열인 댓글 작성자와 DM 수신자를 합치지 않습니다.

댓글, 텍스트 DM, 답장 ID에 묶인 확인 postback을 구분합니다. 댓글에 없는 생성 시각을 만들어 넣지 않습니다. 수신 키는 채널·계정·댓글/메시지 종류·공급자 이벤트 ID의 JSON 튜플입니다. 텍스트와 postback은 메시지 수신 공간을 공유합니다. 이 키는 기존 DB 유일 제약이나 발신 요청 키를 대체하지 않습니다.

`src/instagram/channel-adapter.ts`는 기존 두 파서를 그대로 호출합니다. Node/Worker 진입점은 원문 서명을 검증한 뒤 공통 이벤트를 만들고, 이를 기존 저장 입력으로 되돌립니다. 댓글 다음 메시지 순서, 각각의 트랜잭션, 재전송 중복 방지, 계정별 queue 알림은 유지합니다. 요청으로 어댑터를 선택할 수 없습니다.

## 지원 설명과 실제 발송 자격

capability는 구현된 동작의 안내 메타데이터입니다. 지원 `true`는 발송 허가가 아니며 App Review·구독·토큰 유효성의 증거도 아닙니다. 동의, 시간 창, 소유권, 식별자 연결, 상담 상태, 토큰, 활성 스위치, claim, cooldown과 최종 발송 검사는 그대로 적용합니다.

| 실행 경로                  | 댓글 텍스트 답장 | 팔로우 텍스트·확인 버튼 | 직접 텍스트 답장 | 첨부·승인 템플릿·마케팅 |
| -------------------------- | ---------------- | ----------------------- | ---------------- | ----------------------- |
| Cloudflare Instagram OAuth | 지원             | 지원                    | 지원             | 미지원                  |
| Node Instagram Login       | 지원             | 지원                    | 미지원           | 미지원                  |
| Node Facebook Login        | 지원             | 미지원                  | 미지원           | 미지원                  |

확인 버튼은 현재 답장 ID에 묶인 postback입니다. 승인 메시지 템플릿이 아니며 시간 창을 연장하지 않습니다. 모든 Instagram 설명의 `approved_message`는 `false`입니다.

`src/channels/policy.ts`는 기존 순수 동의 판정을 옮기고 Instagram 모듈에서 다시 내보냅니다. 정확히 같은 범위의 서비스 근거·시간 창만 유효하며, 가져온 연락처는 마케팅 동의가 아닙니다. 시간 계산은 유한한 시각과 현재 이전 근거만 인정하고 경계에 도달하면 닫힙니다. 기존 댓글 7일·직접 답장 24시간 검사 순서와 오류 코드를 유지하며, 팔로우 SQL은 바꾸지 않습니다.

## 한 번의 직접 답장 결과

어댑터는 기존 직접 답장 `send()`의 try/catch 안에서만 성공 ID와 오류를 분류합니다. DB 결과·감사 기록 저장은 catch 밖에 둡니다. 전송 뒤 DB 저장 실패를 공급자 오류로 바꾸지 않습니다.

| 결과                     | 기존 상태·재시도 의미                          |
| ------------------------ | ---------------------------------------------- |
| 유효한 메시지 ID         | `sent`, 원본 메시지 ID 보관                    |
| 전송 전 일시 차단        | `pending`, 기존 지연, 안전한 재전송 표시 없음  |
| 전송 전 확정 차단        | `failed`, 수신 거부는 재전송 불가              |
| 공급자 제한 거절         | `failed`, 수동 재시도 가능, 기존 연결 cooldown |
| 기타 확정 거절           | `failed`, 수동 재시도 가능                     |
| 그 밖의 오류·잘못된 응답 | `unknown`, 자동 재전송 없음                    |

실제 기존 오류 클래스만 확정 거절로 인정합니다. 이름만 같은 객체는 `unknown`입니다. 자동 댓글·팔로우 worker의 별도 재시도 정책과 CAS·감사 기록은 바꾸지 않습니다.

## API와 화면

`reply-status`는 `channel: "instagram"`과 버전 1 capability를 추가합니다. 기존 자격 필드는 현재 서버 판정 그대로입니다. 새 직접 답장 POST의 `content_type`은 생략하거나 `"text"`로 지정할 수 있으며 같은 요청 키로 같은 한 건을 가리킵니다.

- 유효한 기존 요청에 `attachment` 또는 `provider_template` 타입만 추가하면 역할·연결 소유권 확인 뒤 `422 channel_capability_unsupported`를 반환합니다. outbox·감사 기록·queue 알림을 만들지 않습니다.
- 알 수 없는 타입, 추가 필드, 잘못된 본문·요청 키·버전은 계속 400입니다. `attachment_url`을 붙인 요청은 타입과 관계없이 수락하지 않습니다. 재시도·해결 요청의 스키마도 유지합니다.
- 지원 메타데이터가 없거나 잘못되면 화면은 새 예약을 막고 새로고침을 안내합니다. 실제 예약은 지원과 기존 자격을 모두 요구합니다. DOM 버튼을 강제로 활성화해도 제출 검사에서 막습니다.
- 작성기 안에서 텍스트 전용 범위를 안내하고 파일 붙여넣기·드롭을 차단합니다. 혼합 파일/텍스트 동작도 초안을 바꾸거나 예약하지 않습니다. 일반 텍스트 붙여넣기·Enter 줄바꿈·Ctrl/⌘+Enter는 유지합니다.
- 접수 여부가 불확실한 요청은 기존 본문·요청 키로 접수 확인할 수 있습니다. capability 안내가 이 확인을 막지 않으며, `unknown`에는 새 재전송 기능을 만들지 않습니다.

## 운영 상태

새 테이블·마이그레이션·환경 변수·실제 두 번째 채널은 없습니다. [로컬 검증 기록](../notes/2026-10-04-channel-contract-verification.md)은 운영 적용이나 실계정 왕복을 입증하지 않습니다. [#17](https://github.com/AndrewDongminYoo/auto-chatter/issues/17)·[#27](https://github.com/AndrewDongminYoo/auto-chatter/issues/27)의 남은 실계정 검증은 열린 상태이고, 이 변경으로 #37의 전체 운영 수용 완료를 주장하지 않습니다.
