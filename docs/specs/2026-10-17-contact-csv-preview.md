# CSV 태그 변경 사전 검사

## 범위

[#25](https://github.com/AndrewDongminYoo/auto-chatter/issues/25)의 CSV 검증·중복·미리보기 조건을 구현합니다.
기존 [CSV v1 내보내기](2026-10-04-contact-csv-export.md)의 14열 헤더와 식별 표현을 재사용합니다.
소유자·관리자가 파일의 `tags_json`을 수정한 후 기존 댓글 연락처의 태그 교체 예상 결과를 확인합니다.
실제 저장·신규 연락처·식별자 병합·동의·필드·자동화 중지 변경은 하지 않습니다.
미리보기는 적용 권한이나 발송 자격을 부여하지 않으며 #25 전체 완료가 아닙니다.

## 입력과 결과

`POST /api/contacts/import-preview`는 쿼리 없이 JSON `{csv: string}`만 받습니다.
기존 동일 출처·인증·사용자 및 작업 공간 API 요청 한도를 적용합니다.
파일은 UTF-8, 최대 128KiB, 헤더 제외 최대 500개의 CSV 레코드입니다.
JSON 이스케이프를 고려한 HTTP 본문 한도는 `6×128KiB+32` 바이트이며 실제 CSV 크기도 별도로 검사합니다.
BOM은 파일 시작에서 한 번 허용하며 인용 셀 안의 쉼표·큰따옴표 이스케이프·줄바꿈을 보존합니다.
레코드 구분은 CRLF 또는 LF이며 깨진 인용·다른 헤더·NUL·잘못된 유니코드는 전체 요청을 거절합니다.
한도 초과 시 일부 성공으로 자르지 않습니다.

각 레코드는 v1·현재 workspace·Instagram·comment_sender를 확인합니다.
연결 UUID를 정규화하고 sender의 표시용 작은따옴표를 정확히 하나 제거합니다.
표시용 작은따옴표가 없으면 숫자 재저장에 따른 손실을 추정하지 않고 잘못된 식별자로 표시합니다.
형식·범위·태그 오류를 먼저 판정한 뒤 나머지 행에서 같은 연결·sender가 중복되면 해당 행을 모두 제외합니다.
다른 연결의 동일 sender는 별개입니다.
태그는 기존 저장과 같은 최대 20개·정규화·빈 값/제어 문자 금지·40자 규칙을 적용합니다.
빈 배열은 기존 태그를 모두 제거할 예상 변경이며 값을 저장하지 않습니다.

태그 이외의 내보내기 시각·계정 이름·댓글 시각과 수·중지 상태·필드 값은 변경에 사용하지 않고 반환하지 않습니다.
CSV의 workspace나 connection을 신뢰하지 않고 서버의 현재 관리자 멤버십·연결 소유권·기존 댓글 연락처를 조회합니다.
외부 또는 없는 연락처는 같은 조회 불가 결과이며 기존 태그를 노출하지 않습니다.
유효·중복·형식 오류·조회 불가·변경 있음·변경 없음의 행별 결과와 합계를 반환합니다.
반환된 현재 태그와 예상 태그는 한 SELECT의 스냅샷이며 이후 실행을 고정하지 않습니다.
DB에 파일·태그·이력·새 신원을 저장하거나 발송을 예약하지 않습니다.

## 화면

관리자만 파일 선택과 사전 검사 버튼을 봅니다.
실제 저장하지 않는다는 설명과 태그 이외의 열을 무시한다는 안내를 표시합니다.
기존 내보내기와 동일하게 스프레드시트 재저장으로 변형된 값의 복원은 보장하지 않습니다.
파일은 브라우저에서 크기·UTF-8을 검사한 뒤 검사 요청으로만 보냅니다.
행 번호는 물리적 줄 번호가 아닌 헤더 다음 CSV 레코드 번호입니다.
목록은 20행씩 추가 표시하고 합계는 모든 레코드의 판정입니다.
파일 변경·다시 검사·세션 초기화·작업 공간 재조회·화면의 연결 삭제는 이전 결과와 지연 응답을 무효화합니다.
같은 출처의 다른 탭에서 로그인·로그아웃·비밀번호 초기화를 수행하면 데이터가 없는 세션 변경 신호를 받아 파일과 결과를 지우고 사전 검사를 비활성화합니다.
다시 사용하려면 작업 공간을 재조회하여 현재 권한을 확인해야 합니다.
뒤로 가기 캐시에서 복원된 문서도 이전 결과를 지웁니다.
탭 간 신호를 받을 수 없는 브라우저에서는 사전 검사를 제공하지 않습니다.
연락처 태그/필드 편집 초안은 보존합니다.
결과의 문자열은 텍스트로 렌더링하며 수식이나 HTML로 실행하지 않습니다.

## 검증

실제 내보내기 파일 왕복, 여러 줄 인용, 앞자리 0과 큰 ID, 중복, 태그 정규화, 파일/행 한도와 깨진 입력을 검사합니다.
관리자·상담원·제거된 멤버·타 작업 공간·연결별 같은 sender를 실제 DB와 제한된 Worker 역할로 확인합니다.
미리보기 전후 테이블 내용을 직접 비교해 변경이 없음을 검증합니다.
브라우저에서 파일 교체·실패·지연 응답·초안 보존·모바일을 확인합니다.
타입·단위·DB·Cloudflare·Trunk를 실행하며 운영 DB·배포·Meta 호출은 제외합니다.

Advisor의 기존 v1 형식 재사용 제안을 적용했습니다.
Oracle의 `wiki/concepts/evidence-basis-discipline.md`에 따라 물리적 줄 수 대신 파싱된 레코드를 세고 DB 무변경을 직접 검사합니다.
