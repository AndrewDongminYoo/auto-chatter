# 인박스 일회성 예약 답장

## 목표와 범위

[#24](https://github.com/AndrewDongminYoo/auto-chatter/issues/24)의 템플릿 이후 단계로 기존 수동 답장에 예정 시각과 수정·취소를 추가합니다.
템플릿 미리보기에서 복사한 문구도 작성기의 일반 텍스트로 예약합니다.
반복 예약·캠페인·첨부·새 공급자 정책·운영 배포·실발송은 포함하지 않습니다.
이 변경의 로컬 검증은 #24 전체의 운영 완료를 뜻하지 않습니다.

## 예약과 시간대

기존 `POST .../inbox/:recipient/replies`의 즉시 접수 계약을 유지하고 선택적인 `schedule_local`·`expected_time_zone` 쌍을 추가합니다.
값은 `YYYY-MM-DDTHH:mm` 형식이며 현재 작업 공간 시간대로 해석합니다.
서버는 `scheduled_at` 절대 시각과 해석에 사용한 `schedule_time_zone`을 저장합니다.
이후 작업 공간 시간대 변경은 저장된 절대 시각을 바꾸지 않습니다.
화면이 알고 있는 `expected_time_zone`과 서버의 현재 작업 공간 시간대가 다르면 새 예약·수정을 409로 거부합니다.
응답 유실 뒤 같은 요청을 확인하는 동안 시간대가 바뀌어도 기존 접수는 최초 문구·시각·시간대의 감사 fingerprint로 확인하며 아직 접수되지 않은 요청을 다른 시각으로 해석하지 않습니다.
일광 절약 시간의 생략·중복 시각은 기존 리마인더와 같은 PostgreSQL `timestamp AT TIME ZONE` 규칙으로 해석하고 결과의 실제 예정 시각을 화면에 표시합니다.
예약이 나중에 수정·취소되어도 최초 생성 요청의 접수 확인은 현재 행을 반환하고 중복 예약을 만들지 않습니다.
현재보다 최소 1분 뒤이면서 현재 확인된 답장 창 종료보다 이른 시각만 접수합니다.
예약 시점에도 기존 상담 버전·신원·동의·발송 스위치·토큰·답장 창 검사를 통과해야 합니다.
새 DM을 기대해 현재 창 밖에 예약하지 않습니다.

`scheduled_at`은 사용자가 정한 발송 예정이고 `next_attempt_at`은 워커의 다음 검사 시각입니다.
최초에는 두 시각이 같으며 일시적인 발송 전 조회 실패는 `next_attempt_at`만 변경합니다.
워커와 Cloudflare 깨우기 조회는 예정 시각 이전의 예약을 보내지 않습니다.
미래 예약은 나중에 접수한 즉시 답장을 막지 않습니다.
이미 예정 시각이 지난 예약과 즉시 답장의 pending은 생성 순서를 유지합니다.
sending·미해결 unknown은 생성 순서와 관계없이 같은 대화의 다른 행을 막습니다.
미래 예약을 앞질러 처리한 즉시 답장이 unknown이면, 먼저 생성한 예약도 운영자가 그 unknown을 해결할 때까지 보류합니다.

## 수정과 취소

`PATCH .../replies/:id/schedule`은 `{request_key, expected_version, text, schedule_local, expected_time_zone}`으로 예정 시각과 문구를 함께 수정합니다.
`POST .../replies/:id/cancel`은 `{request_key, expected_version}`으로 취소합니다.
생성한 활성 멤버와 현재 owner/admin만 변경할 수 있으며 다른 작업 공간은 조회할 수 없습니다.
현재 pending인 시각 지정 예약만 수정·취소할 수 있습니다.
즉시 답장과 sending·sent·failed·unknown·cancelled는 수정할 수 없습니다.
행 잠금과 `schedule_version`으로 경합을 제어하며 오래된 버전은 409입니다.
각 변경의 요청 키는 기존 감사 이벤트의 고유 키를 사용하고 같은 요청의 접수 확인은 중복 변경을 만들지 않습니다.
취소는 cancelled 상태와 감사 이벤트를 같은 트랜잭션에 기록하며 발송하지 않습니다.
이미 sending으로 선점한 예약은 변경을 거부하므로 성공한 취소 뒤 외부 POST가 발생하지 않습니다.
취소에는 현재 답장 가능 상태나 발송 스위치가 필요하지 않습니다.
수정은 현재 발송 조건을 다시 검사하고 저장된 상담 버전을 임의로 새 버전으로 바꾸지 않습니다.

## 발송 직전 검사

시각 지정 예약의 생성자가 같은 작업 공간의 활성 owner/admin/agent인지 워커와 실제 POST 직전 guard에서 확인합니다.
멤버 제거·다른 작업 공간 이동은 `scheduled_actor_unavailable`로 차단합니다.
owner/admin에서 agent로 바뀌어도 agent에게 수동 답장 권한이 있으므로 허용합니다.
수신 거부·답장 창 만료·상담 버전 변경 등은 기존 정책 실패 분류와 사유를 유지합니다.
정책 실패는 자동 재시도하지 않고, 일시적인 조회 실패와 불명확한 발송 결과의 처리도 기존 계약을 유지합니다.
최종 검사를 통과해 이미 시작한 외부 POST는 이후 권한 변경으로 취소할 수 없습니다.

## 화면과 이력

작성기는 즉시 접수와 시각 지정 예약을 구분하고 해석할 작업 공간 시간대를 표시합니다.
접수 여부가 불명확하면 문구·시각·요청 키를 고정해 같은 요청만 확인합니다.
대화별 입력을 유지하고 로그아웃 시 지우며 늦은 응답이 다른 대화의 입력을 덮어쓰지 않습니다.
발신 이력은 예정 시각·시간대·취소·실패 사유를 표시하고 변경 권한이 있는 pending 예약에만 수정·취소를 제공합니다.
실패한 저장은 입력을 유지하고 버전 충돌을 조용히 덮어쓰지 않습니다.

## 데이터와 검증

기존 `instagram_manual_replies`와 append-only 감사 테이블을 확장합니다.
새 테이블이나 런타임 DELETE 권한은 추가하지 않습니다.
기존 전체 내보내기·연결/개인/작업 공간 삭제 경로가 새 필드와 cancelled 행도 처리하는지 검사합니다.
schema와 migration 049를 같은 내용으로 갱신하고 전체 마이그레이션 실행기에 포함합니다.

DB 테스트로 중복 접수·버전 충돌·역할·시간대·예정 시각·멤버 제거·정책 변경·발송 선점 경합을 확인합니다.
workerd 테스트로 실제 Cloudflare API를 검사하고, Queue·cron 모듈을 호출하는 DB 테스트로 깨우기와 발송 직전 경계를 검사합니다.
합성 API를 사용하는 실제 브라우저에서 예약·수정·취소·접수 불명확·대화 전환·로그아웃을 확인하고 화면 승인을 요청합니다.
