# 세그먼트·발송 한도 수용 증거 정리

## 문제와 범위

[#64](https://github.com/AndrewDongminYoo/auto-chatter/issues/64)의 기능별 증거 연결 중 #26·#60 행을 현재 병합 코드와 대조합니다.
수용 매트릭스는 #60을 미구현으로 표시하고 #26의 최근 구현·검증 근거를 연결하지 않아 다음 작업 선정에 오래된 상태를 전달합니다.
기준 커밋은 PR #204가 병합된 `8717c51c3af34e265ddb8b0e5c3fcceea04af322`입니다.

## 수용 기준

- #26의 태그·단일 필드 AND/OR, 숫자·날짜 비교, 초안 미리보기 범위를 코드와 검증 기록에 연결합니다.
- #60의 연결별 비공개 답장 예산, 삭제 호출 이월, Cron 깨우기 순서를 코드와 테스트에 연결합니다.
- 코드 존재·테스트 정의·기존 실행 결과를 구분하고 확인한 커밋과 CI 실행을 명시합니다.
- 정확한 전체 수·제외 사유·동의/활동 조건·캠페인 대상 고정, 캠페인과 비용 상한 통합 등 남은 범위를 유지합니다.
- 수정 문서의 내부 경로·앵커와 문서 린트를 검사합니다.

## 경계

이번 작업은 문서 주장 수정이며 제품 코드·테스트·DB·의존성을 바꾸지 않습니다.
공급자 정책의 현재 값, 운영 DB 적용·배포, 실계정 동작과 전체 기능 매트릭스는 재검증하지 않습니다.
기존 공급자·운영 열을 승격하거나 #26·#60·#64를 닫지 않습니다.
화면 변경이 없어 별도 시각 승인은 해당하지 않습니다.
프로젝트 선례 조회 결과는 `[no precedent found]`이며 현재 코드와 실행 기록을 근거로 삼습니다.
