# 저장 전 필터 초안 대상 미리보기

## 문제와 범위

[#26](https://github.com/AndrewDongminYoo/auto-chatter/issues/26)의 저장 전 대상 확인을 기존 연락처 필터에 추가합니다.
연락처 목록은 마지막으로 적용한 조건을 표시하지만 필터 저장은 현재 폼의 조건을 사용하므로, 두 조건이 다를 수 있습니다.
저장 영역의 독립 미리보기는 연락처 목록과 편집 중인 태그·필드 값을 바꾸지 않고 현재 초안에 맞는 대상을 확인하게 합니다.

## 계약

- 미리보기 버튼은 현재 계정·태그·단일 필드·AND/OR 초안으로 기존 `GET /api/contacts?preview=true`를 호출합니다.
  저장된 필터를 선택했더라도 화면에 복원된 조건을 사용하며 `segment_id`나 페이지 커서를 보내지 않습니다.
- 기존 서버의 인증·작업 공간 격리·조건 검증과 최대 50명 첫 페이지를 그대로 사용합니다.
  별도 API, 추가 저장소와 권한을 만들지 않습니다.
- 명시적인 `preview=true`는 같은 SQL 문장에서 필터를 통과한 연락처 그룹 수와 최대 50명 첫 페이지를 반환합니다.
  `total`은 PostgreSQL bigint의 정밀도를 유지하는 10진수 문자열이며, 댓글 수가 아닌 `(connection_id, sender_id)`별 대상 수입니다.
  커서와 OFFSET 없이 양수 LIMIT를 사용하므로 SQL 결과가 비면 정확한 수는 `"0"`입니다.
  `preview`의 다른 값·중복 값과 `after` 동시 사용은 빈 커서도 포함해 400으로 거절합니다.
  일반 목록은 기존 질의와 응답 형태를 유지하며 `total`을 반환하지 않습니다.
- 조회 시점의 전체 수와 최대 5명의 참여자·연결 계정 예시를 표시합니다.
  `total`이 없거나 유효한 음이 아닌 정수 문자열이 아니면 결과를 표시하지 않고 재시도를 안내합니다.
  사용자 입력은 기존 `node`의 `textContent`로 표시합니다.
- 결과는 조회 시점의 저장된 데이터에 대한 참고입니다.
  편집 중인 연락처 변경은 포함하지 않으며 필터 저장은 대상 고정이나 발송 동의가 아닙니다.
- 조건·계정 목록·필드 정의 변경, 연락처 기록 삭제와 세션 초기화는 미리보기를 지웁니다.
  이전 요청의 성공·실패·종료 처리가 새 요청이나 새 세션을 덮지 않습니다.
- 요청 중에는 미리보기 버튼의 중복 실행을 막습니다.
  실패 시 이전 결과를 표시하지 않고 다시 시도할 수 있게 합니다.
  필터 저장의 기존 검증과 동작은 유지하며 미리보기를 필수로 만들지 않습니다.

## 수용 기준과 제외 범위

실제 브라우저에서 적용된 목록과 다른 초안, 편집 중인 카드 보존, 0명·소수·50명 초과, 타입별 필드 값, 실패·재시도, 조건 변경 중 응답 역전, 로그아웃 뒤 늦은 응답과 텍스트 렌더링을 확인합니다.
데스크톱·좁은 화면·키보드 동작을 검사하고 병합 전 운영자의 시각 승인을 받습니다.
전체 수 계산은 일치하는 연락처 그룹을 모두 처리하므로 일반 첫 페이지보다 비쌀 수 있습니다.
로컬 합성 데이터의 질의 계획과 실행 시간을 기록하지만 운영 규모·지연 시간을 보증하지 않습니다.
다른 시간의 데이터 변경을 자동 감지하거나 제외 사유·동의/활동 조건·중첩 조건·캠페인 대상 고정·발송을 구현하지 않습니다.
#26 전체 완료와 운영 배포·실계정 검증을 주장하지 않습니다.
프로젝트 선례 조회 결과는 `[no precedent found]`입니다.
