# 작업 공간 역할과 서버 권한 검사 (첫 구현)

## 범위

[이슈 #21](https://github.com/AndrewDongminYoo/auto-chatter/issues/21)의 첫 구현입니다.
한 작업 공간에 여러 멤버가 역할을 가지고 참여할 수 있도록 저장 구조를 바꾸고, 모든 작업 공간 API가 서버에서 역할을 검사하게 합니다.
초대와 초대의 만료·재사용 차단, 멤버 제거와 역할 변경 API, 역할에 맞춘 화면은 다음 구현에서 다룹니다.
그 전까지 소유자가 아닌 멤버는 관리자 연결의 SQL로만 추가할 수 있습니다.

## 역할과 저장

`workspace_members.role`은 `owner`, `admin`, `agent` 중 하나입니다.
migration 022는 기존 멤버를 모두 `owner`로 두고, 작업 공간당 멤버를 한 명으로 제한하던 고유 제약을 없앱니다.
작업 공간마다 소유자는 한 명까지만 둘 수 있고, 한 사용자는 여전히 한 작업 공간에만 속합니다.
`POST /api/workspace`로 새 작업 공간을 만든 사용자와 `deploy/assign-workspace-owner.sql`로 지정한 사용자는 소유자가 됩니다.
소유자 지정 스크립트는 다른 소유자가 있는 작업 공간과, 다른 멤버가 남아 있는 이전 작업 공간에서의 이동을 거부합니다.

## 권한

| 작업                                 | owner | admin | agent |
| ------------------------------------ | ----- | ----- | ----- |
| 인박스·대화 맥락 조회                | 가능  | 가능  | 가능  |
| 상담 전환·수동 답장                  | 가능  | 가능  | 가능  |
| 연락처 조회·태그·필드 값·자동화 중지 | 가능  | 가능  | 가능  |
| 수신 동의·거부 기록                  | 가능  | 가능  | 가능  |
| 연결·규칙·플로·필드·세그먼트 조회    | 가능  | 가능  | 가능  |
| 규칙·플로·필드·세그먼트 변경         | 가능  | 가능  | 불가  |
| 계정 연결·해제·발송 스위치           | 가능  | 가능  | 불가  |
| 인박스 보관 켜기·끄기                | 가능  | 가능  | 불가  |
| 연결 데이터 삭제·삭제 기록 조회      | 가능  | 가능  | 불가  |
| 작업 공간 내보내기                   | 가능  | 가능  | 불가  |
| 멤버 초대·제거·역할 변경 (다음 구현) | 가능  | 불가  | 불가  |

청구 기능은 아직 없으므로 권한을 정하지 않았습니다.
권한이 부족하면 `403 {error: "role_forbidden"}`, 멤버가 아니면 기존처럼 `403 {error: "workspace_required"}`를 반환합니다.
다른 작업 공간의 자원은 기존처럼 404로 보입니다.

## 검사 방식

`src/app/settings.ts`의 `workspaceFor`는 필요한 최소 역할을 필수 인자로 받으므로, 작업 공간 API마다 권한이 코드에 드러나고 누락은 타입 검사에서 실패합니다.
멤버십과 역할은 요청마다 DB에서 읽으므로, 역할을 낮추거나 멤버를 제거하면 그 변경이 커밋된 뒤의 다음 요청부터 적용됩니다.
검사를 통과한 뒤 진행 중인 요청은 역할 변경과 같은 트랜잭션으로 묶이지 않으므로 끝까지 실행될 수 있습니다.
Supabase 세션 자체는 만료 전까지 유효하지만, 제거된 멤버는 작업 공간 API를 쓸 수 없습니다.
작업 공간 내보내기는 자체 스냅샷 안에서 멤버십과 역할을 함께 읽어 관리자 이상만 허용합니다.
화면은 아직 역할에 따라 버튼을 숨기지 않으므로, 상담원이 관리 동작을 누르면 서버의 거부 응답이 표시됩니다.

## 운영 적용

migration 022는 관리자 migration 러너에 포함됩니다.
이 계약은 운영 DB에 적용하지 않았습니다.
