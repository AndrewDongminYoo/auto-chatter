# 고정 대상과 현재 세그먼트의 차이

## 제안과 근거

운영자가 승인한 범위의 구현 계약입니다.
[#26](https://github.com/AndrewDongminYoo/auto-chatter/issues/26)의 변경 감지를 기존 [고정 대상](2026-10-18-segment-target-snapshots.md)에 추가합니다.
현재 `segment-snapshots.ts`와 대시보드는 고정 대상의 생성·조회·CSV를 제공하며, 현재 세그먼트와 명단을 비교하는 기능은 제공하지 않습니다.
[#35](https://github.com/AndrewDongminYoo/auto-chatter/issues/35)의 메시지·비용·승인·예약을 시작하기 전에 관리자가 고정 당시와 현재 대상의 차이를 확인하도록 합니다.

## 선행 이슈와 이번 작업의 경계

#26의 선행 이슈는 #25이고, #25의 선행 이슈는 #17과 #27입니다.
[수용 매트릭스](../notes/2026-09-27-manychat-acceptance-matrix.md)의 #25에는 식별자 병합·분리가 미구현으로 남아 있으므로 #26 전체의 선행 조건이 충족됐다고 판단하지 않습니다.
이번 비교는 기존 댓글 작성자 연락처·저장된 세그먼트 조건·고정 명단만 읽으며 그 미구현 기능을 요구하지 않는 하위 작업입니다.
식별자를 합치거나 DM 수신자로 대체하지 않으며, #25·#26·#35의 전체 완료를 선언하거나 이슈를 자동 종료하지 않습니다.

## 비교 기준

고정 대상에 지금 남아 있는 `(connection_id, sender_id)` 집합을 기준 명단으로 사용합니다.
같은 작업 공간에서 고정 대상의 원래 세그먼트를 찾아 **현재 저장된 정의**를 현재 데이터와 시각으로 한 번 평가합니다.
고정 당시의 조건 사본을 다시 실행하는 기능은 추가하지 않습니다.
필터를 수정했다면 고정 당시 버전과 현재 버전을 함께 표시하며, 두 버전이 다를 때 차이에는 필터 수정의 영향도 포함된다고 안내합니다.
버전은 이름만 바꿔도 달라질 수 있으므로 버전 차이를 조건 변경의 증거로 표현하지 않습니다.

집합 비교의 결과는 다음과 같습니다.

- 추가: 현재 대상에만 있는 연락처 수입니다.
- 제외: 기준 명단에만 있는 연락처 수입니다.
- 유지: 두 집합에 모두 있는 연락처 수입니다.

연결이나 이용자 데이터 삭제로 이미 사라진 명단 행은 기준 명단에 포함하지 않으며 식별자를 복원하지 않습니다.
원래 저장한 인원 수와 지금 남아 있는 인원 수를 별도로 보여 줍니다.
조건 변화·활동 기간 경과·필터 수정 가운데 무엇이 개별 차이를 일으켰는지는 추정하지 않습니다.

## 조회 API

`GET /api/segment-snapshots/<snapshot_id>/comparison`은 활성 `owner` 또는 `admin`만 사용할 수 있습니다.
쿼리 매개변수는 받지 않습니다.
UUID가 아닌 ID나 쿼리 매개변수는 400 `invalid_snapshot_request`, 없거나 다른 작업 공간의 고정 대상은 404 `snapshot_not_found`입니다.
원래 세그먼트가 보관됐다면 기존 활성 세그먼트 조회와 같은 404 `segment_not_found`로 비교를 거절합니다.
이때 기존 명단 조회와 CSV 다운로드는 계속 사용할 수 있습니다.

응답 필드는 다음과 같습니다.

| 필드                                                | 의미                                                              |
| --------------------------------------------------- | ----------------------------------------------------------------- |
| `snapshot_id`, `segment_id`                         | 비교한 고정 대상과 원래 세그먼트입니다.                           |
| `snapshot_as_of`                                    | 고정 당시 평가 시각입니다.                                        |
| `compared_at`                                       | 현재 대상 평가 문장의 시각이며 마이크로초까지의 UTC 문자열입니다. |
| `snapshot_segment_version`, `segment_version`       | 고정 당시와 비교 시점의 세그먼트 버전이며 정수입니다.             |
| `counts.original`                                   | 고정 당시 저장한 인원 수입니다.                                   |
| `counts.baseline`                                   | 지금 남아 있는 기준 명단의 인원 수입니다.                         |
| `counts.current`                                    | 현재 세그먼트에 맞는 연락처 수입니다.                             |
| `counts.added`, `counts.removed`, `counts.retained` | 추가·제외·유지 인원 수입니다.                                     |

모든 `counts` 값은 정확한 십진수 문자열입니다.
`baseline = removed + retained`, `current = added + retained`를 만족합니다.
댓글 작성자·DM 수신자 식별자나 태그·필드 값·본문은 응답에 포함하지 않습니다.

## 일관성과 실행 경계

하나의 `REPEATABLE READ READ ONLY` 트랜잭션에서 활성 멤버십과 관리자 역할, 고정 대상, 현재 활성 세그먼트, 필드 유효성을 읽습니다.
기존 CSV 내보내기의 멤버십 재검사 방식과 `savedSegmentConditions`, `contactConditionFields`, `validateFieldCondition`을 재사용합니다.
평가는 `segmentConditionSql`의 목록·CSV·고정 대상과 같은 선택 조건을 사용하고, 한 문장에서 기준 명단과 비교합니다.
상대 활동 기간과 달력 기간은 그 문장의 한 `statement_timestamp()` 및 같은 스냅샷의 작업 공간 시간대를 사용합니다.
생성 경로와 달리 새 명단을 쓰지 않고 잠금을 기다리지 않으므로 읽기 스냅샷을 고정할 수 있습니다.
동시에 수정·삭제가 커밋돼도 한 응답 안에서 서로 다른 상태를 섞지 않습니다.

현재 대상은 5,000명을 넘어도 정확히 집계합니다.
고정 생성의 5,000명 제한이나 상세 조회의 50행 페이지를 비교 집계에 적용하지 않으며, 전체 명단을 JavaScript로 가져오지 않습니다.
고정 대상·조건 사본·원래 집계·명단 행은 수정하지 않습니다.
마이그레이션, 신규 의존성, 발송, 동의 변경, 발송 가능 여부 판정, 자동 감시·알림은 범위에 포함하지 않습니다.
비교 요청이 끝난 뒤의 데이터 변화까지 보장하지 않습니다.

## 화면

고정 대상 상세에 `현재 필터와 비교` 버튼과 결과 영역을 추가합니다.
원래 인원 수·남은 기준 인원 수·현재 인원 수·추가·제외·유지 수와 두 평가 시각을 표시합니다.
다시 누르면 새로 평가하며, 새 요청을 시작할 때 이전 결과를 지웁니다.
비교는 저장된 정의를 읽는다고 안내하고, 선택한 필터에 미저장 수정이 있는 동안에는 비교를 막습니다.
필터 저장으로 버전이 바뀌면 이전 비교 결과를 지웁니다.
다른 명단 열기·필터 전환·작업 공간 또는 세션 초기화는 결과와 진행 중 응답을 무효화합니다.
실패하면 이전 성공 결과를 남기지 않으며 명단과 CSV 기능은 유지합니다.
비교 결과는 발송 가능한 대상 수로 표시하지 않습니다.

## 수용 조건

1. 태그·필드·동의·활동 조건과 중첩 그룹을 포함한 현재 대상이 같은 시각의 기존 연락처 목록과 일치합니다.
2. 인원이 같아도 구성원이 바뀌면 추가와 제외를 각각 세며, 빈 집합·같은 sender의 다른 연결·다른 작업 공간을 정확히 구분합니다.
3. 삭제 후에는 남은 명단을 기준으로 비교하고, 원래 수와 남은 수를 혼동하지 않으며 저장 데이터를 바꾸지 않습니다.
4. 세그먼트 버전 변경과 동시 수정·삭제에서 한 응답의 정의·집합·집계가 같은 스냅샷을 읽습니다.
5. 50명과 5,000명을 넘는 현재 대상도 잘림 없이 집계합니다.
6. 관리자 권한·격리·잘못된 요청·보관 상태를 DB API 및 workerd 경로로 검사합니다.
7. 화면의 결과·오류·늦은 응답 무효화를 테스트하고, 실제 브라우저의 정적 화면을 운영자에게 검토받습니다.

## 승인과 운영 상태

구현과 로컬 검증 결과는 [검증 기록](../notes/2026-10-19-segment-snapshot-comparison-verification.md)에 남깁니다.
운영 배포·실사용은 검증하지 않았습니다.
계획 승인은 이 비교 기능에 한정하며 #26이나 #35 전체의 완료를 뜻하지 않습니다.
병합은 운영자가 수행하며 운영 배포·실계정 조회·발송은 별도 요청 범위로 남깁니다.
