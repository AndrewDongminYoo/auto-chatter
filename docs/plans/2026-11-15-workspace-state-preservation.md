# 작업 공간 상태 보존 구현 계획

## 방향과 소유 파일

승인된 #352 범위에서 `public/app/app.js`의 작업 공간 갱신과 인증 오류 처리를 분리하고, 필요한 보고서 모듈만 수정합니다.
회귀 테스트는 `src/app/`의 기존 테스트 패턴을 따르며 새 테스트를 추가하면 `package.json`의 실행 목록에 등록합니다.
세션 동작 설명은 `docs/agents/feature-invariants.md`에 반영합니다.
새 의존성과 저장소 밖 제품 변경은 필요하지 않습니다.

## 구현 순서

1. 실제 보고서 컨트롤러와 시작 처리의 회귀 테스트를 작성하고 현재 코드에서 입력 초기화·중복 화면 실패를 확인합니다.
2. 사용자·작업 공간·권한 경계와 갱신 요청 순서를 구분하고, 관련 없는 기능 초기화를 제거합니다.
3. 보고서의 동일 문맥 재구성을 멱등하게 만들고, 무효한 조회 결과와 이전 세션 응답을 차단합니다.
4. 전체 버튼 잠금을 규칙 저장 범위로 좁히고 네트워크·인증·부분 로딩 오류를 구분합니다.
5. 합성 API 브라우저 검증과 전체 단위 테스트, 타입 검사, lint, Trunk를 실행합니다.
6. 변경 규모에 맞는 로컬 리뷰와 문서 검사를 마친 뒤 PR 리뷰를 진행하고 화면 결과 승인을 받습니다.

## 완료 검사

`corepack pnpm check-types`, `corepack pnpm lint`, `corepack pnpm test`, `trunk check --all`을 실행합니다.
DB·provider 계약은 변경하지 않으며 실제 발송과 운영 배포는 수행하지 않습니다.
테스트와 합성 미리보기는 운영 장애의 발생 여부나 실계정 동작을 증명하지 않습니다.
