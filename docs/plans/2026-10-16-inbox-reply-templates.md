# 인박스 답장 템플릿 구현 계획

## 방향과 범위

[답장 템플릿 계약](../specs/2026-10-16-inbox-reply-templates.md)에 따라 기존 수동 작성기에 복사할 문구를 관리합니다.
Advisor의 범위 축소 권고에 따라 #24의 예약 발송을 분리하고 기존 접수·발송 guard는 변경하지 않습니다.
변수는 상담원이 직접 입력하며 다른 식별자의 필드를 추정하지 않습니다.
관련 Oracle 선례는 `[no precedent found]`입니다.

## 구현과 확인

1. 새 API의 역할·저장·미리보기 테스트를 추가하고 현재 404 실패를 확인합니다.
2. 템플릿 테이블과 migration 048·전체 실행기·RLS/서버 권한·작업 공간 삭제·내보내기·이동 보호를 함께 추가합니다.
   새 테이블은 작업 공간에만 속하므로 연결·개인 삭제 대상은 아닙니다.
3. 기존 역할·입력 오류·트랜잭션 관례를 사용해 목록·생성·수정·보관·미리보기를 구현합니다.
   문구 파서는 제한된 변수 이름만 읽고 한 번 치환하며 누락·추가·형식·길이 오류를 거절합니다.
4. 관리 화면과 작성기의 선택·변수 입력·미리보기·초안 추가를 연결합니다.
   실제 브라우저에서 실패 보존·늦은 응답·접수 잠금·모바일을 검사합니다.
5. CLAUDE·인박스·작업 공간 삭제/이동/내보내기 명세·수용 매트릭스를 코드와 함께 갱신합니다.
6. 타입·단위·DB·workerd·Trunk와 독립 리뷰 후 한 기능 커밋·PR·호스팅 리뷰·CI를 완료합니다.
   화면 승인과 병합은 운영자에게 맡깁니다.

최소 검증은 `corepack pnpm check-types`, `corepack pnpm test`, 격리된 `automations_test`의 `corepack pnpm test:db`·`corepack pnpm test:cloudflare`, 변경 경로를 지정한 `trunk check --no-fix`입니다.
새 런타임 의존성과 운영 외부 작업은 추가하지 않습니다.
