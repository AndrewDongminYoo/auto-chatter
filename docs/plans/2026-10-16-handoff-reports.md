# 상담 전환 이력 리포트 구현 계획

## 승인과 범위

PR #213의 화면 확인·병합 후 다음 이슈 선정과 pr-loop를 계속 진행하라는 요청에 따라 #50의 다음 단계를 구현합니다.
[명세](../specs/2026-10-16-handoff-reports.md)를 이번 계약으로 사용합니다.
기존 이벤트 원장에서 계정·기간별 시작·해제·전체 변경 횟수와 고유 대화 수를 읽습니다.
플로 귀속·현재 활성 수·전환율·청구 정책·기존 발송 동작은 변경하지 않습니다.
병합과 운영 DB·배포·발송은 위임되지 않았습니다.

## 순서와 성공 기준

1. 새 DB 테스트에서 미구현 라우트 실패를 확인하고 관리자 권한·시간대·필터·네 지표를 구현합니다.
2. 기간 인덱스가 없는 실제 집계 실행 계획의 실패를 확인한 뒤 현재 스키마·migration 052·전체 실행기를 수정합니다.
3. 홈 조회와 동일 응답 CSV를 구현하고 단위 테스트와 브라우저에서 수치·초기화·지연 응답·권한·좁은 화면을 검사합니다.
4. 명시적인 package.json 테스트 목록에 추가하고 `corepack pnpm install --frozen-lockfile`로 기존 lockfile 일치를 확인합니다.
5. README·CLAUDE·역할 명세·수용표와 검증 기록을 같은 PR에서 갱신합니다.
6. `corepack pnpm check-types`, `corepack pnpm test`, 격리 DB의 `corepack pnpm test:db`·`corepack pnpm test:cloudflare`, 변경 경로 Trunk 검사를 통과시킵니다.
7. 독립 API·UI 검토와 루트의 적대적 점검 후 의미별 커밋·푸시·PR을 만들고 현재 커밋의 CI·코드·보안 리뷰를 확인합니다.
8. 화면 검토 자료를 보존하고 운영자 시각 승인과 merge commit 병합을 요청합니다.

## 제한

새 의존성이나 공통 리포트 프레임워크를 추가하지 않고 기존 구현 관례를 따릅니다.
운영 검증과 #50 전체 완료는 별도 범위로 남깁니다.
