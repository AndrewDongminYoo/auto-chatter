# Meta 게시용 개인정보 안내 페이지

## 범위와 승인

개인정보처리방침 URL 누락으로 Meta 앱 게시가 중단되어 기존 Worker에 공개 안내 페이지를 추가합니다.
운영자는 이름 `유동민(Dongmin Yu)`과 이메일 `ydm2790@gmail.com`의 공개를 승인했습니다.
연동 운영 중 필요한 기간 보관하고 연동 종료·서비스 종료 또는 본인 확인을 거친 삭제 요청 시 수동 삭제하며, 문의 기록은 처리 완료 후 삭제하는 운영 정책도 승인했습니다.
자동 삭제 기능, Meta 앱 게시 전환, 발송 활성화는 이 변경에 포함하지 않습니다.

## 구현과 검증

1. `/privacy`, `/data-deletion`의 GET·HEAD 접근을 비밀값·DB 없이 처리하고 다른 메서드는 405로 거부합니다. → `node --test src/cloudflare/public-pages.test.ts`
2. 기존 웹훅 서명 검사를 유지합니다. → 같은 테스트의 서명 없는 웹훅 거부 검사 및 `corepack pnpm test`
3. 의존성을 추가하지 않고 기존 Worker 번들에 문안을 포함합니다. → `corepack pnpm install --frozen-lockfile`, `corepack pnpm check-types`, `corepack pnpm build:cloudflare`
4. 브라우저에서 문안·연락처·삭제 안내 링크를 확인하고 배포 후 공개 HTTPS 응답을 확인합니다.

처음 추가한 공개 경로 테스트 4건은 구현 전 404 응답으로 실패했고, 구현 후 통과했습니다.
문안은 실제 `db/schema.sql`, `src/instagram/store.ts`, `src/cloudflare/index.ts`와 운영자의 승인을 근거로 작성합니다.
수신 DM 보관, AI 학습, 자동 만료·삭제처럼 구현하지 않은 동작을 약속하지 않습니다.
이 페이지의 게시만으로 Meta의 다른 게시·심사 요건 충족을 보장하지 않습니다.

## Oracle와 외부 근거

개인 계정 Oracle의 `sourceCommit`은 `c1681868ac634e4b2414874716bb75a7864113c4`이며 현재 Wiki HEAD와의 최신성 비교는 하지 않았습니다.
`wiki/concepts/source-verified-output.md`의 확인된 출처만 사용하라는 선례에 따라 보관 기간을 임의의 일수로 정하지 않고 운영자에게 실제 수동 삭제 정책을 확인했습니다.
`wiki/entities/dongmin-yu.md`의 운영자 정보는 이번 공개 승인과 일치합니다.
구체적인 프로젝트 보유·삭제 선례는 반환된 결과에서 확인되지 않았으며, 일부 결과가 생략되어 완전한 부재로 단정하지 않습니다.

- [개인정보보호위원회 안내서 목록](https://pipc.go.kr/np/cop/bbs/selectBoardList.do?bbsId=BS217&mCode=G010030000): 현재 작성지침의 존재를 확인했습니다. 특정 법적 적합성 인증의 근거로 사용하지 않습니다.
- [Cloudflare 개인정보처리방침](https://www.cloudflare.com/privacypolicy/): 최종 이용자의 요청 정보를 처리하는 제공자임을 설명합니다.
- [Supabase 개인정보처리방침](https://supabase.com/privacy): 제공자 자체의 운영 및 국외 처리 가능성을 설명합니다. 운영 DB 리전은 실제 생성 결과인 서울을 기재합니다.
- Meta Platform Terms 원문은 조회가 제한되어 읽지 못했습니다. 다른 Meta 제품의 정책을 Instagram 정책으로 대체하지 않습니다.

## 수동 삭제 운영 절차

1. 요청자에게 계정명과 관련 게시물·댓글 링크 및 요청 범위를 받고, 본인 또는 대리 권한을 확인합니다. 비밀번호·토큰은 받지 않습니다.
2. 대상 연결과 요청자 식별자를 조회해 범위를 확정합니다. 계정 연동 전체 종료라면 해당 연결을 비활성화하고 진행 중인 발송이 있는지 확인합니다.
3. 권한이 있는 관리자가 트랜잭션 안에서 해당 범위의 outbox를 먼저 삭제한 뒤 댓글 이벤트를 삭제합니다. 계정 전체 종료라면 규칙과 연결도 제거하고 다른 연결이 없는 workspace만 제거합니다. 다른 계정의 기록은 포함하지 않습니다.
4. 계정 전체 종료 시 더 이상 필요하지 않은 로컬·배포 인증정보와 Meta 연동 권한을 확인해 제거합니다. 공유하는 앱 시크릿을 개별 댓글 삭제 때문에 제거하지 않습니다.
5. 삭제 대상이 남아 있지 않은지 다시 조회하고, 외부 제공자 로그·백업 또는 법정 보관 예외가 있으면 확인된 범위와 제한을 요청자에게 안내합니다.
6. 결과를 이메일로 안내하고 요청 처리에 사용한 문의 기록을 삭제합니다. 이 문서는 절차이며 삭제나 이메일 발송을 자동 실행하지 않습니다.

서버 역할은 DELETE 권한이 없으므로 관리자 절차로 처리합니다.
Instagram 원본 댓글·이미 전달된 메시지의 삭제와 auto-chatter 저장 기록의 삭제를 구분합니다.

## 서비스 이용약관 추가

운영자가 Meta 앱 게시 완료를 알리고 `/service`에 서비스 이용약관 추가를 요청했습니다.
기존 공개 페이지 처리기에 GET·HEAD 약관 경로와 공통 탐색 링크를 추가하며, 발송이나 계정 연동 동작은 변경하지 않습니다.
문안은 계정 관리자의 이용 조건, 현재 댓글 자동화 기능, 금지 행위, 연동 종료와 수동 삭제, 이용 제한, 책임 및 변경 안내를 다룹니다.
유료 구독·결제 기능이나 자동 동의 기록을 구현한 것으로 설명하지 않습니다.
신규 외부 계정 연동 전에는 운영자가 약관을 안내하고 이용 의사를 확인해야 합니다.

앞서 조회한 Oracle의 `wiki/concepts/source-verified-output.md` 선례를 적용해 현재 구현과 승인된 수동 삭제 정책을 기준으로 작성했습니다.
[국가법령정보센터의 약관법 제7조·제12조·제14조](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1025032399)를 확인해 포괄적 면책, 단순 방문에 따른 동의 간주, 이용자에게 불리한 전속 관할을 문안에 넣지 않았습니다.
이는 문안 작성 근거이며 법적 적합성 인증을 의미하지 않습니다.

공개 페이지 테스트에서 `/service`의 GET·HEAD 404 응답과 기존 페이지의 약관 링크 누락을 먼저 확인한 뒤 구현했습니다.
검증은 `node --test src/cloudflare/public-pages.test.ts`, `corepack pnpm check-types`, `corepack pnpm test`, 변경 파일 Trunk 검사 및 배포 후 공개 HTTPS·브라우저 확인으로 수행합니다.
