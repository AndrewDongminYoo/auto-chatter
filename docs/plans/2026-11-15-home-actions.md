# 홈 다음 행동 구현 계획

## 승인된 방향

#351의 순서에 따라 #354를 진행합니다.
기존 디자인과 컨트롤러를 유지하고 상세 보고서를 독립 메뉴로 분리합니다.

## 구현과 검증

1. 기존 작업 공간·보고서 테스트에 화면별 초기화와 부가 옵션 지연 로딩의 실패 회귀를 추가합니다.
2. `public/app/index.html`의 홈·보고서 진입을 정리하고 `app.js`에서 세션과 작업 공간 조회에 묶인 화면 초기화를 공유합니다.
3. 두 비동기 보고서 컨트롤러는 맥락 설정과 옵션 조회를 구분하되 기본 API와 무효화 계약을 유지합니다.
4. 합성 API 브라우저에서 홈 요청 목록, 메뉴 재진입, 세션 교체, 초안·보고서 조건·CSV 및 권한을 검증합니다.
5. `corepack pnpm check-types`, 제품 lint, `corepack pnpm test`, `trunk check --all --monitor=false`와 렌더링을 확인합니다.
6. 커밋·PR 전에 로컬 mock API 미리보기를 제공하고 화면 검토를 받습니다.

## 위험

지연 초기화가 기존 맥락 무효화나 새로고침을 생략하지 않도록 하고, 오래된 응답이 다른 세션의 화면을 변경하지 못하도록 기존 generation 검사를 보존합니다.
요청 수 감소와 실제 서버 지연시간 개선을 구분합니다.
