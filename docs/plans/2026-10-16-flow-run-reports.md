# 플로 실행 현황 구현 계획

## 승인과 범위

PR #212 병합 후 다음 이슈를 선정해 pr-loop를 계속 진행하라는 요청에 따라 #50의 플로 리포트 단계를 구현합니다.
[명세](../specs/2026-10-16-flow-run-reports.md)를 이번 계약으로 사용합니다.
Advisor의 조정 의견을 반영해 생성 기간의 현재 실행 상태와 연결된 첫 답장 상태를 분리합니다.
병합, 운영 마이그레이션, 배포와 발송은 위임되지 않았습니다.

## 순서와 성공 기준

1. 새 API DB 테스트로 없는 라우트의 실패를 확인한 뒤 관리자 권한, 기간·시간대, 필터 소유권과 두 상태 집계를 구현합니다.
2. 기간 조회 인덱스가 없는 실행 계획의 실패를 확인한 뒤 migration 051·현재 스키마·전체 실행기를 수정합니다.
3. 홈 조회와 같은 응답의 CSV를 구현하고 실제 브라우저에서 결과·다운로드·늦은 응답·역할·좁은 화면을 검사합니다.
4. 명시적인 테스트 스크립트에 새 테스트를 등록하고 `corepack pnpm install --frozen-lockfile`로 lockfile 일치를 확인합니다.
5. README·CLAUDE·역할 명세·수용 기준표의 변경된 주장과 검증 기록을 같은 PR에서 갱신합니다.
6. `corepack pnpm check-types`, `corepack pnpm test`, 격리 DB의 `corepack pnpm test:db`·`corepack pnpm test:cloudflare`, 변경 경로 Trunk 검사를 통과시킵니다.
7. 규모에 맞는 독립 검토와 적대적 점검, 의미별 커밋·푸시·PR, 현재 커밋의 CI·코드·보안 리뷰를 이어갑니다.
8. 화면 자료를 보존하고 운영자의 시각 승인과 merge commit 병합을 요청합니다.

## 제한

보고서에 필요한 읽기와 인덱스만 추가하고 플로 실행기·발송 경로·청구 정책을 변경하지 않습니다.
집계는 보존된 현재 원장에 한정하며 #50의 나머지 범위와 운영 검증은 완료하지 않습니다.
