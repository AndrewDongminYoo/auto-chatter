# 세그먼트·발송 한도 수용 증거 정리 계획

## 작업 범위

[명세](../specs/2026-10-16-acceptance-evidence-reconciliation.md)를 따라 수용 매트릭스의 #26·#60과 도입부만 수정합니다.
이 명세·계획과 검증 기록을 포함해 문서 네 개를 변경합니다.
기존 제품 구현과 다른 행은 유지합니다.

## 실행과 검증

1. 매트릭스의 기존 주장을 줄 번호와 함께 추출하고 병합 코드의 함수·상수·SQL과 대조합니다.
2. 관련 테스트가 검사하는 경계와 기존 CI의 실행 커밋·결과를 확인합니다.
3. 구현된 부분과 남은 조건을 나눠 행을 고치고 검증 기록을 연결합니다.
4. 내부 링크 검사가 없는 파일·앵커에서 실패하는지 먼저 확인한 뒤 수정 문서 전체에 적용합니다.
5. 명시한 네 파일에 `trunk fmt`와 `trunk check --no-fix`를 실행하고 실제 diff를 검토합니다.
6. 하나의 문서 커밋으로 PR을 열고 해당 커밋의 CI·호스팅 리뷰가 끝날 때까지 확인합니다.

제품 동작 변경이 없으므로 새 단위 테스트나 DB 실행을 추가하지 않습니다.
문서 검사 통과는 기술한 제품 동작·운영 상태의 증명이 아니며, 각각의 코드와 실행 기록으로 근거를 구분합니다.
