# 필터 초안 미리보기 구현 계획

## 범위와 소유 파일

[초안 미리보기 계약](../specs/2026-10-16-segment-draft-preview.md)에 따라 `public/app/app.js`, `public/app/index.html`과 관련 명세·검증 기록만 변경합니다.
새 의존성·API·DB 마이그레이션은 없습니다.
기존 목록과 저장 폼의 조건 직렬화를 필요한 범위에서 재사용합니다.

## 실행과 검증

1. 실제 대시보드 파일과 합성 API 응답을 쓰는 로컬 브라우저에서 미리보기 버튼 부재를 실패로 확인합니다.
2. 저장 영역에 버튼·상태·읽기 전용 요약을 추가하고 현재 초안을 기존 연락처 API에 전달합니다.
3. 조건·정의·계정·세션 변경 시 무효화하고 이전 요청의 늦은 결과를 무시합니다.
4. 실제 브라우저에서 목록과 다른 초안, 카드 편집 보존, 0명·50명 초과, 필드 값·AND/OR, 실패·재시도·응답 역전·로그아웃·악성 텍스트를 검사합니다.
   미리보기가 GET 이외의 요청을 만들지 않는지 확인하고 데스크톱·390px 스크린샷을 남깁니다.
5. `node --check public/app/app.js`, `corepack pnpm check-types`, `corepack pnpm test`와 변경 파일의 Trunk 검사를 실행합니다.
   API·DB 계약은 바꾸지 않으며 전체 DB·workerd·격리 배포 검사는 hosted CI의 결과를 별도로 기록합니다.
6. 한 번의 구조화된 로컬 검토 후 명시적 파일만 커밋·푸시하고 PR에 `Refs #26`을 사용합니다.
   현재 커밋의 CI·호스팅 리뷰와 화면 검토 자료를 준비한 뒤 운영자 시각 승인·병합을 기다립니다.
