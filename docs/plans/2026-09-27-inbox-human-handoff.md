# 인박스 상담 전환 구현 계획

## 승인된 방향

ManyChat 대체 PR 루프의 7회차로 [상담 전환 명세](../specs/2026-09-27-inbox-human-handoff.md)를 구현합니다.
수동 발송을 추가하기 전에 자동화와의 충돌을 막는 서버 상태를 완성합니다.
기존 작업 공간을 사용하고 루트가 모든 변경·스테이징·커밋을 소유합니다.

## 변경 범위

마이그레이션 013·새 설치 스키마·관리자 runner·접근 정책, `src/app/inbox.ts`·새 상담 전환 모듈·API·연락처 중지, 기존 댓글·팔로우·Cloudflare guard와 DB fixture·회귀 테스트를 수정합니다.
README·CLAUDE·운영 마이그레이션·수동 삭제 안내와 기능 매트릭스도 현재 구현에 맞춥니다.
의존성·렌더링 UI·외부 계정·발송 스위치는 변경하지 않습니다.

## 성공 기준과 순서

1. 기존 API와 PostgreSQL에서 상담 전환 경로 부재·중지 미반영을 먼저 관찰합니다.
   검증: 소유권·근거·멱등성·버전·직접 중지·여러 대화·근거 변화·동시 변경 사례의 실제 실패입니다.
2. 013과 트랜잭션 API·감사 저장을 구현합니다.
   검증: 같은 DB 사례의 통과와 마이그레이션 재실행·서버 감사 UPDATE/DELETE 및 API 접근 금지입니다.
3. 기존 발송 경계마다 `paused OR handoff_paused`를 적용합니다.
   검증: 첫 DM·팔로우 claim·검증 중 변경·최종 POST 전 변경·크론에서 발송이 차단되고 다른 연락처는 진행합니다.
4. 전체 gate와 독립 로컬 적대적 검토를 수행합니다.
   검증: `corepack pnpm check-types`, `corepack pnpm test`, 격리된 DB의 `corepack pnpm test:db`·`corepack pnpm test:cloudflare`, `trunk check --all`입니다.
5. 스키마·API와 guard를 의미론적 커밋으로 보존하고 PR·호스팅 코드/보안 리뷰·CI를 확인합니다.
   검증: 최신 head의 모든 결과와 운영자 병합입니다.

## 남은 일

이 PR은 #18 전체 완료가 아닙니다.
수동 답장 예약·발송 정책·unknown 처리·발신 이력과 #19 화면, 운영 배포·명시적으로 승인된 실계정 발송은 다음 구현과 별도 수용 증거가 필요합니다.
