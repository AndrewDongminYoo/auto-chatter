# 단일 서버 배포 계획

## 범위와 결정

승인된 첫 배포는 서버 한 대에서 Docker Compose로 PostgreSQL과 웹훅 수신기를 실행하고, 명시적으로 활성화한 경우에만 Instagram 발송 워커와 Caddy HTTPS 프록시를 실행합니다.
관리자 화면, OAuth 연결, 여러 연결의 워커 스케줄링, Supabase 전환과 실제 서버 공개는 이번 구현에 포함하지 않습니다.
실행 이미지에는 Node.js 24와 잠금 파일에 고정된 운영 의존성만 넣고, 비밀값은 실행 환경에서 전달합니다.
수신기와 워커는 비관리자 사용자로 실행하며, DB에서도 테이블 변경 권한이 없는 별도 역할을 사용합니다.

## 작업과 수용 기준

1. Dockerfile과 빌드 컨텍스트 제외 규칙을 추가합니다.
   검증: 운영 이미지 빌드 성공, 비관리자 실행, 이미지 안에 비밀값 파일과 개발 의존성이 없음을 확인합니다.
2. PostgreSQL 영속 볼륨과 수신기를 Compose로 연결합니다.
   검증: 빈 볼륨에서 초기화하고 서명된 모의 댓글을 보내 DB 저장까지 확인합니다.
3. 발송 워커와 HTTPS 프록시를 선택적으로 실행하도록 구성합니다.
   검증: 기본 실행에 두 서비스가 포함되지 않고, 로컬 프록시를 통한 구독 확인이 통과합니다.
   실제 토큰을 사용하는 발송과 공인 인증서 발급은 별도 승인 후 검증합니다.
4. 백업·복구·마이그레이션·업데이트 절차를 기록합니다.
   검증: 임시 DB의 백업을 다른 빈 DB에 복원하고 저장 행을 확인하며, 기존 마이그레이션을 재적용합니다.
5. 기존 단위·DB 테스트, 타입 검사와 Trunk를 실행하고 배포 구성과 운영 절차를 검토합니다.

## 남은 운영 결정

서버와 도메인, 외부 백업 저장 위치·보존 기간, 장애 알림 수신처는 아직 정하지 않았습니다.
이미지의 Node·PostgreSQL·Caddy 태그는 주 버전 계열을 따르므로 재빌드 시 기반 이미지가 달라질 수 있습니다.
운영 배포마다 애플리케이션 이미지 태그와 실제 이미지 ID를 기록하고 이전 이미지를 보관합니다.
개인 위키 인덱스에서 `automations`와 `auto-chatter` 프로젝트 항목을 확인하지 못해 Oracle 프로젝트 선례 조회는 미확인 상태입니다.
이번 결정은 승인된 배포 방향과 현재 저장소 명세를 기준으로 합니다.
